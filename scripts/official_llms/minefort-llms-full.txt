# Citadel 0.1.0 pack API

A pack is a folder with `citadel.yml`, a `main.luau` entry and optional `assets/sounds/*.ogg`. On a hosted server the folder is `/packs/<name>/`, and a pack takes effect when the server restarts.

# Examples

Whole packs that run: read one to see how the calls below fit together.

## Your first pack

Build a small lobby with solid ground, a welcome, and a `/spawn` command.
A pack is a folder with two files: `citadel.yml` configures it, and
`main.luau` defines what happens in the game.

### 1. Create the pack

Make a folder named `first` and put this `citadel.yml` inside it:

```yaml
# citadel.yml
name: first
entry: main.luau
motd: My first Citadel pack
spawn_point: [0.5, 65.0, 0.5]
gamemode: 2
mode: lite
world: script
```

`entry` names the script to run. `world: script` means that script supplies
the terrain, and `mode: lite` makes your pack the game. Adventure mode
(`gamemode: 2`) lets players explore without breaking the floor.
`spawn_point` places their feet one block above the floor, in the centre
of the gold marker you will create next.

### 2. Add the script

Create `main.luau` beside `citadel.yml`:

```lua
--!strict
-- A small lobby: solid ground, a welcome, and a way back to spawn.

world.on_generate(function(chunk)
    chunk:fill(
        vec3(chunk.min.x, 64, chunk.min.z),
        vec3(chunk.max.x, 64, chunk.max.z),
        "stone"
    )
    chunk:set(vec3(0, 64, 0), "gold_block")
end)

players.on_join(function(player)
    player.ui.title{
        title = "Welcome",
        subtitle = player.name,
        color = "aqua",
    }
    player:message("Walk around, then type /spawn to return to the gold block.", "aqua")
end)

commands.add("spawn", function(player)
    player:teleport(world.spawn_point)
    player:message("You are back at spawn.", "green")
end, { help = "Return to the lobby spawn" })
```

Read the three callbacks in order:

- `world.on_generate` fills each chunk with a stone floor at y = 64, then
  marks `(0, 64, 0)` with gold. `chunk:set` ignores positions outside its
  chunk. `vec3(x, y, z)` describes a position; y is height.
- `players.on_join` receives the player who joined. The title and message
  go to that player. Register the callback once; Citadel calls it when
  needed.
- `commands.add` registers `spawn` without a slash. When a player types
  `/spawn`, `player:teleport(world.spawn_point)` returns them to the point
  from the manifest. Reading it avoids repeating the coordinates.

### 3. Run it and check your work

With `citadel` on your `PATH`, run this from the directory containing `first`:

```sh
citadel --lite --pack ./first
```

Keep the server running and join `localhost:25565` from Minecraft Java
Edition, or use the address and port configured for your server. You should
see a welcome and stand on the gold block. Walk away, type `/spawn`, and
check that you return to it with a confirmation in chat.

### 4. Make an edit

Change `title = "Welcome"` to `title = "My lobby"` and save. Citadel reloads
`.luau` files while players stay connected, and runs the join callback for
those players again. The new title should appear. If it does not, check
the server log for a script error.

Reloading keeps existing chunks: edits to `world.on_generate` affect newly
generated terrain. Restart after editing `citadel.yml`. As a next exercise,
add a `/hello` command that sends a message to the player who uses it.

## Scoreboard with a button

The hotbar is the menu, the screen shows the scores, and `storage` keeps the
count over restarts. Clients from 1.8 see it all.

```lua
-- main.luau
world.on_generate(function(chunk)
    chunk:fill(vec3(chunk.min.x, 64, chunk.min.z), vec3(chunk.max.x, 64, chunk.max.z), "stone")
end)

local board = world.screen{ at = vec3(-2, 68, -10), facing = "south", width = 4, height = 2 }

local function redraw()
    board:clear(colors.black)
    board:text(16, 12, "TAPS", colors.yellow, 40)
    local y = 64
    for _, p in players.list() do
        local score = storage.get("taps." .. p.name) or 0
        board:text(16, y, p.name, colors.white, 28)
        board:text(board.width - 16 - board:measure(tostring(score), 28), y, tostring(score), colors.cyan, 28)
        y += 34
    end
end

players.on_join(function(player)
    player:hotbar{ [1] = { item = "lapis_block", name = "Tap me" } }
    player:message("Right click the block in your hand.", colors.cyan)
    redraw()
end)

players.on_leave(function()
    redraw()
end)

players.on_click(function(player, hit)
    if hit.slot ~= 1 or hit.button ~= "right" then
        return
    end
    local key = "taps." .. player.name
    storage.set(key, (storage.get(key) or 0) + 1)
    sound.play("block.note_block.hat", { at = player.at, pitch = 1.5 })
    redraw()
end)
```

## A world per player

`rooms.create` gives a player their own world, with own chunks, players and
effects. Add the room's listeners before you move the player: its `on_join`
fires as the player arrives.

```lua
-- main.luau
local COURSE = { vec3(0, 65, 4), vec3(4, 66, 8), vec3(-3, 68, 12) }

world.on_generate(function(chunk)
    chunk:fill(vec3(chunk.min.x, 64, chunk.min.z), vec3(chunk.max.x, 64, chunk.max.z), "stone")
end)

players.on_join(function(player)
    player.ui.title{ title = "Lobby", subtitle = "type /play", color = colors.cyan }
end)

commands.add("play", function(player)
    local mine = rooms.create{
        spawn_point = vec3(0.5, 65, 0.5),
        generate = function(chunk)
            chunk:fill(vec3(chunk.min.x, 64, chunk.min.z), vec3(chunk.max.x, 64, chunk.max.z), "stone")
            for _, at in COURSE do
                chunk:set(at, "gold_block")
            end
        end,
    }
    mine.players.on_join(function(p)
        p:message("Reach every gold block.", colors.yellow)
        mine.ui.title{ title = "Go", color = colors.lime }
    end)
    mine.players.on_leave(function()
        if mine.players.count() == 0 then mine:destroy() end   -- the last one out closes it
    end)
    player:move_to(mine)
end)
```

# Basics

What a pack is, how a server runs it, and the rules every call follows.

## Packs

A pack is a folder. `citadel.yml` names the pack and points at `main.luau`.
Each `assets/sounds/*.ogg` file becomes a sound event named `<pack>.<file>`.

The script runs on every Java client from 1.8 to 26.2 and never sees a
client version. To check a feature, ask `player:supports` (see "Client
versions").

`packs/citadel.d.luau` types this whole API. Start a script with `--!strict`
and point a language server at that file to catch misspelt fields.

Use the standard platform and Luau's new type solver (luau-lsp 1.70.1 or
later). For a command-line check:

```sh
luau-lsp analyze --platform=standard --flag:LuauSolverV2=true --definitions=packs/citadel.d.luau main.luau
```

In VS Code, set `luau-lsp.platform.type` to `standard`, add the definitions
file to `luau-lsp.types.definitionFiles`, and set
`luau-lsp.fflags.override` to `{ "LuauSolverV2": "true" }`.

```yaml
# citadel.yml
name: rave             # also the sound namespace: assets/sounds/kick.ogg -> "rave.kick"
entry: main.luau
motd: Rave by Minefort
spawn_point: [0.5, 65.0, -4.5]
gamemode: 1            # 0 survival, 1 creative, 2 adventure, 3 spectator
game: "1.8.9"          # the content and rules the server simulates; clients older than it are refused
min_client: "1.14"     # refuse clients older than this too (optional; the strictest pack wins)
resource_pack: offered # or "required": a client that turns the pack down cannot join (1.17+ clients)
mode: lite             # what server this pack is for: "lite" = your scripts are the game,
                       # "full" = it adds to survival; left out, the pack runs on either
world: script          # "script" = world.on_generate below, "overworld" = the built-in terrain,
                       # "hub" = the world folder <pack>/hub that `citadel import` wrote
seed: 1234             # the overworld map; left out, a new world rolls its own
terrain: { snow: true } # what an a0.1.0 overworld is made of; see "terrain" below
budget_ms: 2           # this pack's share of a tick, for its tick and event callbacks
view_distance: 12      # chunks sent round each player, 2..32; the farthest pack wins, 6 if none asks
mute: [block.stone.hit] # vanilla sounds nobody on this server hears (the resource pack plays silence for them)
hide_hud: [hearts, food] # parts of the game's own HUD nobody on this server sees; see "Layouts"
dialogs: true           # the pack opens dialogs: what they draw with rides in the resource pack; see "Dialogs"
```

Run it: `citadel --lite --pack ./rave`.

### loading

- The entry script has **5 s** of work between two waits (`task.wait`), and
  30 s in all. Past that, the load fails and the log says why.
- Build big scenery once at load and copy it, for example one tree variant
  pasted per chunk. Do not loop over every block of every level at load.

### textures of your own

On Java 1.21.4 and later, a pack's own items and blocks can have textures.
Set `texture` in `game.items.define` and `game.blocks.define` (below). The
engine adds them to its resource pack. Older clients see the vanilla item or
block. A client that turns the resource pack down sees them too from then on
(`player:supports("resource_pack")` is false). A pack that needs the textures
says so:

```yaml
min_client: "1.21.4"      # the oldest client that draws a pack's own textures
resource_pack: required   # a client that turns the pack down cannot join
```

Every other folder in `<pack>/assets/` (not `sounds`) goes into the resource
pack unchanged (`assets/<pack>/textures/...`).

### mode

`mode` says **who owns the game**. In a pack manifest, it names the kind of
server the pack is *for*.

- `mode: lite`: your scripts are the game.
- `mode: full`: **Citadel plays survival** (terrain, health, hunger, mining,
  inventory, mobs, world rules). A pack cannot ship survival; it *adds* to
  it (a shop, a scoreboard, a custom drop).
- **no `mode` key**: the pack runs on either kind of server, like a plugin.

`citadel` with no flags (or `--full`) runs survival with `gamemode: 0` and
the overworld. `--lite` makes the packs own the game. Add packs to either
with `--pack ./shop` or `--packs-dir ./packs`.

- A `--lite` server with no packs does not start survival. It runs with an
  empty world and no game, and the log says so. Add a pack and restart.
- With no flag and no server file, the packs' manifests decide. Packs that
  name different modes, or that all name none, stop the server. The message
  says how to set one.
- A flag or the server file overrules a pack that names the other mode. The
  log names that pack.

## Server settings

The `citadel.yml` beside the world describes the **server**. On a hosted
server, the owner changes settings here, not on the command line. An edit
takes effect on restart and survives it.

```yaml
# citadel.yml
mode: lite              # "full" = Citadel plays the game, "lite" = the packs are the game
packs: packs            # where the packs are, relative to this folder
bind:                   # what to listen on; each line left out is this default
  java: 0.0.0.0:25565
  packs: 0.0.0.0:25566  # resource packs over HTTP; give a second server on one machine its own
  bedrock: 0.0.0.0:19132    # Bedrock over RakNet (UDP); "" turns it off
  nethernet: 0.0.0.0:19132  # Bedrock over NetherNet (TCP signaling, the same number as RakNet on UDP); "" turns it off
game: a0.1.0            # the game version, "1.8.9" (the default) or "a0.1.0"
world_dir: worlds/a0    # the world folder; a world keeps the game it was written by
operators:              # players with every permission, by uuid (Minefort writes the owner here)
  - 069a79f4-44e9-4726-a5be-fca90e38aaf5
online_mode: true       # check each player with Mojang, as vanilla does; this is the default
nethernet_tls:          # the certificate for Bedrock clients that dial HTTPS; not used behind a proxy with a forwarding secret
  cert: fullchain.pem
  key: privkey.pem
store_dir: data/store   # where `stores` keeps its files when no platform store was named; this is the default
```

A player's identity comes from one of three places:

- Behind a proxy with `MODERN_FORWARDING_SECRET`: the proxy signs it.
- No proxy, `online_mode: true`: Citadel checks with Mojang.
- `online_mode: false`: nobody is checked, and the log warns at start.
  Anyone can join with any name, an operator's too.

Every key is optional, and so is the file. With no `packs` key, a `packs`
folder beside the world is used when one exists. An unknown key or mode
stops the server.

The mode is decided in this order:

1. a `--full` or `--lite` flag
2. this file
3. what the packs agree on in their own manifests
4. survival, when there are no packs.

### world

`world` says where a chunk comes from.

- `world = "script"`: `world.on_generate` makes the chunks. A chunk it does
  not fill is air.
- `world = "overworld"`: Citadel's terrain, with biomes, hills, caves, ores,
  trees and sea level 63. Scripts only add to it (`world.on_populate`).
  `seed` pins the map.
- `world = "hub"`: any other name is a world folder in the pack,
  `<pack>/hub`, made once from a build or a vanilla world. The server reads
  it chunk by chunk and saves player changes into it. A chunk the folder
  lacks comes from `world.on_generate`, or is air.

  ```sh
  citadel import builds/lobby.schem <pack>/hub --at -186,48,-236 --spawn 0.5,65,0.5
  ```

  Generate a map too big to make live into that folder ahead of time, with
  the pack's `world.on_generate`:

  ```sh
  citadel generate <pack> --from -4096,-6144 --to 4095,6143   # block corners; --threads n
  ```

  It runs one script per core, and any map size fits in memory. Chunks
  already in the folder are kept, so a stopped run continues.

  `parts.define` declares a named part whose generator runs on request.
  Build mode edits the folder by hand (see "Named parts").

  ```sh
  citadel generate <pack> --part tower-3   # one part's generator, into the folder
  citadel parts <pack>                     # every part: clean, modified, kept or orphaned, and who edited it
  ```
- **no `world` key**: the scripts are asked first. A chunk no script filled
  is overworld terrain on a full server and air on a lite server.

**Chunks nobody is near are unloaded.** Every ten seconds the server drops
chunks beyond the view distance of all players and entities. When someone
returns, a stored world loads the chunk from disk (a changed chunk waits for
its save). A `script` world calls `on_generate` again.

So **`on_generate` must make the same blocks every time**. Draw from a hash
of the position, never `math.random`. A script-world chunk changed live
(`world.set_block`, `world.fill`) stays in memory.

**Where the world is.** A full server keeps its world in `world/`, beside
the server's `citadel.yml`, with or without packs: the world is the
server's, and a pack that is removed does not take the map with it. A lite
server keeps it in the first pack, `<pack>/data/world`. A dimension is a
folder beside the main world (`world_dungeon`). `world_dir` in the server's
`citadel.yml` names another place.

The world's `level.json` keeps the seed, spawn, time and weather of the first
run. Changing `seed` does nothing to an existing world. Delete the world
folder for a new map.

With no `spawn_point`, a `world: overworld` pack takes the first grass block above
sea level, ring by ring out from (0, 0). It searches once and stores the
result in `level.json`. With no `world` key, the spawn is the origin.

The chunks around the spawn are generated before the port opens.

### terrain

`terrain` sets the overworld's step list. Only `game: a0.1.0` has one.
Without `terrain`, the world uses the original game's steps.

```yaml
game: a0.1.0
world: overworld
terrain:
  snow: true              # Alpha's snowy world: a frozen sea, snow on every open column
  steps:                  # the whole populate list, in order, in place of the jar's
    - { step: dungeons, count: 8 }
    - { step: clay, block: clay, size: 32, count: 10 }
    - { step: ore, block: coal_ore, size: 16, count: 20, below: 128 }
    - { step: ore, block: diamond_ore, size: 7, count: 4, below: 16 }   # four times the jar's
    - { step: trees, bonus: 10, big: 10 }
    - { step: patch, block: dandelion, count: 2 }
    - { step: patch, block: poppy, count: 1, chance: 2 }
    - { step: reeds, count: 10 }
    - { step: cactus, count: 1 }
    - { step: springs, fluid: water, count: 50, bound: 120, nesting: 1 }
    - { step: springs, fluid: lava, count: 20, bound: 112, nesting: 2 }
    - { step: snow }
```

| step | what it places |
|---|---|
| `dungeons` | `count` tries at a cobblestone room with a spawner and up to two chests |
| `clay` | `count` blobs of `block`, `size` long, into sand that starts under water |
| `ore` | `count` veins of `block`, `size` long, into stone below y `below` |
| `trees` | trees on the surface; one chunk in `bonus` gets one more, one in `big` grows big trees |
| `patch` | a patch of 64 tries at `block` — `count` times, or with `chance: n` one time in n |
| `reeds` | `count` clumps of sugar cane beside water |
| `cactus` | `count` clumps of cactus on sand |
| `springs` | `count` fluid sources in stone walls; `nesting` pushes them deeper |
| `snow` | a snow layer on every open column — in a `snow: true` world only |

`game.terrain` prints the original list. Start an edit from it.

- Order matters: moving or removing a step changes everything after it.
- A block must be one the game can name.
- A size or a bound must be at least 1.
- An unknown key stops the server.
- The list is stored in `level.json`. Like `seed`, a later edit changes
  nothing for an existing world.
- `terrain` on a 1.8.9 world stops the server.

## API basics

The rules that hold for every call: namespaces, handles, callbacks and errors.

- Namespaces: `world`, `players`, `sound`, `fx`, `ui`, `commands`, `time`,
  `rooms`, `storage`, `http`. Plus `task` for waiting and `require` for splitting a
  pack into files.
- A pack is its files. `loadstring` is not there, so a pack cannot run text
  as code, and `require` reads only files inside the pack. `getfenv` and
  `setfenv` are not there.
- The first six belong to the main room. `rooms.create{}` gives another room
  the same six tables.
- Event subscriptions are `on_*` and return a connection;
  `connection:cancel()` stops the subscription. `world.on_generate` and
  `world.on_populate` are single-handler setters: a later call replaces the
  previous handler, and they return nothing.
- Positions are `vec3(x, y, z)` with fields `x y z`. Block positions are
  floored.
- Colours are `color(r, g, b)` in `0..1`, `colors.red`, ..., or
  `color.hsv(h, s, v)`, everywhere, text included.
  - A name string also works: Minecraft's
    sixteen (`"red"`, `"dark_aqua"`, `"light_purple"`, ...), six more
    (`"orange"`, `"lime"`, `"cyan"`, `"purple"`, `"magenta"`, `"pink"`),
    `"transparent"`, or hex (`"#ff8800"`).
  - `colors` holds the same names. `colors.grey` is an error that lists
    them.
- Text is a string or a table of coloured runs. See "Text formatting".
- Calls with more than three inputs take an options table. Every field has
  a default.
  - **An unknown field is an error** that names the nearest valid one:
    `world.display{ kind = "text", colour = "red" }` stops the script with
    *no option "colour"; did you mean "color"?*
  - A field of the wrong type is also an error.
- For optional settings that accept both, `nil` removes an override and
  `false` switches it off. Each field documents whether it accepts `nil`.
  Numeric settings such as `player.speed`, `player.scale` and `player.reach`
  require a number; `nil` does not reset them.
  - `player.visible = nil` shows the player again, because a player is
    visible by default.
  - Where off is the default, the two do the same: `display.glow = false`
    and `display.glow = nil` both remove the glow.
  - A flag is `true`, `false` or `nil`. A number or a string is an error:
    `world.rules{ fall = 0 }` does not turn the rule off.
- One spelling per idea: a position is `at`, removing a thing is
  `:destroy()`, stopping a timer or an event is `:cancel()`, and a box's
  corners are `from` and `to`.
- Block names are Minecraft's, without `minecraft:`.
  - Every block of every version is real here and stored exactly. An older
    client sees the nearest block its version has.
  - A name even the newest version lacks becomes the nearest block. Write
    `"future_block|obsidian"` to pick the substitute yourself.
  - Properties go in brackets, in any order and any subset:
    `"oak_trapdoor[facing=east]"`, `"stone_button[facing=west, face=wall]"`.
    Missing properties come from the default state. The nearest state wins.
  - A name that is no block of any version (`"grassblock"`,
    `"stone_brick"`) is an error that lists the nearest real names.
  - Queries (`game.block(name)`, the block an entity stands on) return `nil` for
    a name the game lacks.
- Sound names are `"<pack>.<file>"` for your assets, or vanilla names like
  `"block.note_block.hat"`.
- Time is in seconds. Only the day is in ticks (24000 to a day).
- Nothing is global state except the callbacks you register.

## Vectors and colours

Positions are `vec3` values and colours are `color` values; both have math of their own.

```lua
local a = vec3(1, 2, 3)
a + b, a - b, -a, a * 2, a * b, a / 2, a == b
a:magnitude(), a:unit(), a:dot(b), a:cross(b), a:distance(b), a:lerp(b, t), a:floor(), a:with{ y = 70 }
vec3.zero, vec3.up

local c = color(1, 0, 0.5)   -- or colors.red, color.hsv(0.6, 1, 1)
c * 0.5, c * d, c:lerp(d, t), c == d
color.gradient({ "gold", colors.white, "#3366ff" }, u)   -- the colour u (0..1) of the way along the list
color.gradient(list, u, true)                           -- a loop: u wraps, and the last colour runs back into the first
color.nearest(c)             -- the colour a screen or canvas really shows, since a picture snaps to the map palette
```

## Version info

The `citadel` global tells a script which engine runs it, and when a batch ran out of budget.

```lua
citadel.log("anything", 42)          -- to the server log, under this pack's name
citadel.version                      -- the engine version
citadel.game                         -- the game version from citadel.yml, "1.8.9"
citadel.env                          -- "development", "unlisted" or "published"
citadel.budget()                     -- this pack's slice of a tick, and what it did with it
citadel.on_slow(function(slow) end)  -- a batch that ran out of budget; see "Limits and reload"
```

`citadel.version` is the engine build (`0.1.0`).

`citadel.env` is:

- `"development"` on the Minefort workload where an experience is built.
- `"unlisted"` or `"published"` on an experience's instances, by visibility.
- `"published"` on a Minefort server that is not an experience.
- `"development"` anywhere else.

Gate debug tools on it:

```lua
if citadel.env == "development" then
    -- builder-only commands, verbose logs, …
end
```

Build mode (`/build`, `/part`; see "Named parts") exists on `"development"` only.

# World

The ground players stand on: terrain, blocks, builds, time, and the game version's own data.

## Blocks and terrain

Make the ground as chunks load, change blocks live, and build in code or from a file.

```lua
world.on_generate(function(chunk) end)   -- called for a chunk each time it comes into memory; same blocks every time
--                             it may wait (task.wait, http.get, stores); the chunk is done when it returns
--   chunk.x, chunk.z          chunk coordinates (16 blocks each)
--   chunk.min, chunk.max      vec3 bounds of this chunk, inclusive; y runs
--                             0 .. 255, the game version's height, for every client
--   chunk:get(pos)            what is there now, by name; air outside the chunk
--   chunk:set(pos, block)     one block; positions outside the chunk are ignored
--   chunk:fill(from, to, block)   a box, clipped to the chunk
--   chunk:paste(schem, origin)    a schematic, clipped to the chunk
--   chunk:set_biome(pos, biome)   the biome of one column; see "biomes"
--   chunk:fill_biome(from, to, biome)   the biome of each column in a box
--   chunk:get_biome(pos)      the biome name there; nil outside the chunk
world.set_block(pos, block)               -- live change, stored and sent to everyone
world.set_block(pos, "player_head[rotation=8]", { skin = "Notch" })   -- a head with a face; see "player heads"
world.set_blocks({ { at = vec3(...), block = "red_wool" }, ... })   -- many at once, cheapest; a row takes skin = too
world.fill(from, to, block)               -- live box
world.get_block(pos)                      -- the block name there, or nil (see below)
world.block(pos)                          -- the block there as a handle: its state, its data, whether it is powered; see "power"
world.get_blocks(from, to)                -- a box of names in one pass
world.get_biome(pos)                      -- the biome name of a column, or nil (chunk not loaded)
world.time("day")                         -- the sky stays there; see "the time of day"
world.time(function(s) return s * 20 end) -- asked each tick; s is seconds since this call
world.time()                              -- the time of day now, 0 .. 23999; 6000 (noon) on a lite world until something sets it
world.schematic(file)                     -- a .schem file in the pack, read once
--   schem.size                vec3, the build's width, height and length in blocks
--   schem.min                 vec3, the build's own lowest corner (0, 0, 0 for a file)
world.build(function(b) end, { detail = 1 })   -- the same value, written in code; detail 2 is half blocks
--   b:block(pos, block)       one block
--   b:box(from, to, block)    a box, inclusive corners, like chunk:fill
--   b:line(from, to, block)   every block the straight line passes through
--   b:part(name, function() end)   what the function writes is a named part; see "naming the parts"
world.paste(schem, origin)                -- live, like world.fill; { part = "house" } names the paste
world.container(pos)                      -- a chest's stacks, or nil; see "containers"
world.drop(pos, item)                     -- a stack on the ground at a block, as a broken block leaves one
world.on_populate(function(chunk) end)    -- add to the overworld's own chunks; see "populating the overworld"
```

A build that a script writes is a schematic with no file:

```lua
local road = world.build(function(b)
    b:box(vec3(-4, 0, -48), vec3(4, 0, 48), "gray_concrete")
    b:line(vec3(0, 0, -48), vec3(0, 0, 48), "white_concrete")
    b:block(vec3(0, 1, 0), "sea_lantern")     -- later writes win
end)
road.size, road.min          -- vec3(9, 2, 97) and vec3(-4, 0, -48)
world.paste(road, vec3(0, 64, 0))             -- road.min lands here
```

The rules:

- Coordinates are whole blocks in the build's own space, and may be
  negative. A build written around `vec3(0, 0, 0)` lands with its middle
  `-build.min` from `origin`.
- A block name this game version lacks becomes the nearest block it has.
- `chunk:paste` and `world.paste` take a build like any schematic. Make it
  at the top of the script, not inside `on_generate`.
- A build costs only what it writes. One build may write 4 096 16-block
  cubes (32 MB, sixteen million solid blocks), in a box of up to 256 million
  blocks. For more, use several builds or a `.schem`.
- Fences, walls, glass panes and iron bars join their neighbours, and stairs
  take their corners. Write `"oak_fence"`, not its `north=true` states.

### player heads

A `"player_head"` or `"player_wall_head"` shows a face when you give it a
`skin`:

```lua
world.set_block(vec3(0, 65, 0), "player_head[rotation=8]", { skin = "Notch" })
world.set_block(vec3(1, 65, 0), "player_wall_head[facing=south]", { skin = player.name })
world.set_block(vec3(2, 65, 0), "player_head", { skin = { value = "ewogICJ0aW1l...", signature = "..." } })
world.set_blocks({ { at = vec3(3, 65, 0), block = "player_head", skin = "jeb_" } })
```

- A name is looked up from a player in this room, else from Mojang. The
  head appears at once and gets its face later. A name with no account
  leaves a plain head and logs a line.
- `{ value = , signature = }` is the account's `textures` property, as for
  `world.npc{ skin = }`. The signature is optional.
- The face is saved with the chunk. Replacing, breaking or turning the head
  forgets it: write the new state with its `skin` again.
- A head in a `.schem` (Sponge or MCEdit) or an imported world keeps its
  face through pastes, turns and `citadel import`. A head saved with only a
  name is looked up when its chunk loads.
- `skin` on any other block is an error.
- Clients from 1.7 see the face. Bedrock clients see no face.
- For a head as an item, see "head items".

### half blocks: `detail = 2`

At `detail = 2`, every coordinate is a half block. The engine turns each
block's eight cells into the block, a slab or a stair of the material, with
the correct `facing`, `half` and `shape`:

```lua
local roof = world.build(function(b)
    for k = 0, 9 do                          -- a 45-degree roof, half a block a step
        b:box(vec3(k, k, 0), vec3(19 - k, k, 15), "deepslate_tiles")
    end
end, { detail = 2 })                         -- 10 blocks wide: coordinates 0..19
```

| cells of a block | what is placed |
|---|---|
| all eight | the block |
| the bottom four, or the top four | a bottom or top slab |
| a half and one quarter above it (or below) | an outer-corner stair |
| a half and two quarters on one side | a straight stair, climbing that side |
| a half and three quarters | an inner-corner stair |
| anything else | the block when four or more cells hold it, else nothing |

- The slab and the stair are the material's own: `stone_bricks` makes
  `stone_brick_slab` and `stone_brick_stairs`, `oak_planks` makes
  `oak_slab`, `quartz_block` makes `quartz_stairs`.
- A material with no slab or stairs, or whose slab or stairs came in a
  later release (concrete's), is the whole block or nothing.
- Only full blocks are fitted. A lantern, flower, fence or stair named
  directly is placed as named in a block with no full-block cells. So a
  detail is one `b:block`, not eight.
- A block that holds two materials takes the one most of its cells hold.
- `detail` is `1` (the default) or `2`. `build.size` and `build.min` are in
  blocks. The cube limit counts cells, so detail 2 holds an eighth as many
  blocks.

### turning a build

A build turns and flips as a value; the original does not change:

```lua
local window = world.build(function(b) ... end)
local east   = window:rotate(90)      -- a quarter turn clockwise seen from above: north becomes east
local back   = window:rotate(180)
local left   = window:mirror("x")     -- east and west swap; "z" swaps north and south
```

- A build turns about `vec3(0, 0, 0)`, so a part drawn around its middle
  turns in place. `min` reads back the new start.
- Block states turn with it: facings, log axes, fence and pane sides, stair
  corners, door hinges, rail curves, sign and banner rotation.
- `rotate` takes 90, 180 or 270. Any other value is an error.

### cutting a build, and changing its blocks

A build somebody made by hand is a kit of pieces. `crop` takes one piece out
of it, and `replace` makes it of other blocks. Both give a new build; the
original does not change.

```lua
local town  = world.schematic("builds/town.schem")
local tower = town:crop(vec3(140, 17, 80), vec3(172, 99, 112))   -- two corners, both inside the piece
tower.min, tower.size        -- vec3(140, 17, 80) and vec3(33, 83, 33): the piece keeps its place
local blue  = tower:replace { red_nether_bricks = "blue_concrete", red_wool = "blue_wool" }
world.paste(blue, vec3(0, 64, 0))        -- its lowest corner goes here, as for any build
```

- The corners are in the build's own blocks, in either order. A file's
  lowest corner is `vec3(0, 0, 0)`.
- A box that reaches outside the build is cut to it. A box with none of the
  build in it is an error that says where the build runs.
- A cropped piece has no named parts. `replace` keeps them.
- `replace` takes block names with no state. A block keeps its state where
  the new block has one like it: stairs stay stairs that face the same way.
  Where it has none, the block is the plain block. `"air"` takes a block
  away.
- A name that is not a block is an error that names it.
- To save memory, crop the pieces while the pack loads and keep only them:
  a file nobody holds is let go.

### naming the parts

A build names its pieces as it writes them, and the names stay after the
paste. `citadel render` frames a part by name. `citadel check` says which
part an edit touched.

```lua
local house = world.build(function(b)
    b:part("walls", function()
        b:box(vec3(-5, 0, -4), vec3(5, 4, 4), "stone_bricks")
        b:part("door", function() ... end)      -- "walls/door"
    end)
    b:part("roof", function() ... end)
end, { detail = 2 })
world.paste(house, vec3(0, 64, 0), { part = "house" })   -- "house", "house/walls", "house/roof"
chunk:paste(house, vec3(0, 64, 0), { part = "house" })   -- the same from on_generate
```

- A part is the box its writes reached, in whole blocks at either detail.
  It turns and flips with the build.
- A name is 1 to 64 characters without a `/`. A part inside another part is
  named by its path, `"walls/door"`.
- A name may repeat. Selecting it takes every part with that name.
- Name the parts you will talk about: the body, each tower or wing, the
  roof, the entrance. Then "make the tower taller" stays an edit to the
  tower.

### seeing what you built

`citadel render <pack dir> --out view.png` runs the pack with nobody joining
and draws its world.

- Each block has its real shape, in the average colour of its textures.
- With named parts, four cameras frame them from the sides (`view-1.png`
  looks north). Otherwise they circle the spawn.

Ask for the view that answers your question:

```sh
citadel render ./castle --out v.png --view approach,entrance     # does the way in read?
citadel render ./castle --out v.png --view roof --part castle/keep
citadel render ./castle --out v.png --view plan,cutaway          # the enclosed spaces, storey by storey
citadel render ./castle --out gate.png --at 0,66,30 --look 0,70,-10   # one camera, placed
```

| view | camera | the question it answers |
|---|---|---|
| `sides` | four, round the build, a little above it | silhouette and proportion from every side |
| `approach` | a player's eye height, out from the main door | what a player sees walking up to it |
| `entrance` | close on the main door, eye height | does the way in read as the way in |
| `roof` | high up, at an angle | the roof line, and where the parts meet |
| `plan` | straight down, to scale, one per storey | the enclosed spaces, walls and doors of each floor |
| `cutaway` | at an angle, one per storey | the enclosed spaces as a player stands in them |
| `eye` | in each named part, where a player stands, at eye height | the part as one who walks in sees it: a hall from inside, a square from its edge |
| `night` | as `sides`, at night | the light: only blocks that give light (lanterns, lamps, glowstone, froglights) light the build |

- `--part name` frames that part and the parts inside it.
  `--from x,y,z --to x,y,z` frames a box. Without either, `--view` frames
  every named part.
- The main door is the lowest door that opens outdoors. A build with no
  `*_door` block has no `approach` or `entrance` view.
- `plan` and `cutaway` remove everything above each storey. `--cut y`
  removes everything above `y` for any view. `--night` draws any view at
  night, the placed cameras of `--at` too.
- Under a roof, a face is lit by the sky light that comes in through the
  openings and by the light blocks near it, as in the game: a room with
  windows is light, one without is dark.
- `--around x,y,z`, `--distance d`, `--height h` and `--views n` circle a
  point instead. `--size 1280x720`, `--fov 60` and `--radius r` (how far
  around the target the world is read) change the rest.
- Each file prints one JSON line on stdout: `{"file":..., "view":...,
  "eye":[x,y,z], "look":[x,y,z]}`, with `"cut"` when something was removed.

**What a picture proves.** Shape, depth, proportion and silhouette, not
textures: every block is one flat colour. Say so when you report on how a
build looks. At night a block is lit by the light blocks within 15 blocks of
it, as in the game; a lamp outside the views' box lights nothing.

### checking what you built

`citadel check <pack dir>` measures the named build and reports what is
wrong with it:

```sh
citadel check ./castle                          # every named part
citadel check ./castle --part castle/keep --storeys 3 --enclosed
citadel check ./castle --save before.snap       # write the blocks down ...
citadel check ./castle --since before.snap      # ... and say what changed, part by part
```

It lists:

- the enclosed spaces (the air closed in with doors and windows shut)
- how many blocks the build holds
- the storeys
- for each innermost part: its places to stand and the detail near them
  (blocks within reach that are not a full cube and not glass)
- the doors, and where each opens
- each face: how much is one plane, its windows and how many are framed,
  its materials
- the roof: how much is one height, how much is stairs and slabs
- the setting: how much of the ground around it has something placed.

Then it lists the findings:

| finding | kind | what it means |
|---|---|---|
| `FLOATING` | fix | blocks that touch nothing standing |
| `DOOR_BLOCKED` | fix | a block in a door's way at foot or head height, named |
| `DOOR_DROP` | fix | a door that opens onto nothing to stand on |
| `DOOR_UNREACHED` | fix | a door nobody can walk to from outside |
| `UNREACHED` | fix | floor inside walls and under a roof that nobody can walk to from outside |
| `STOREYS` | fix | `--storeys n` asked for, and not what enclosed spaces stand on |
| `NOT_CLOSED_IN` | fix with `--enclosed` | outside air reaches the inside with doors and windows shut, and where it comes in |
| `FLAT_FACE` | advice | a face nearly all in one plane |
| `FLUSH_WINDOWS` | advice | windows with nothing in front of them: no sill, lintel or post that stands out |
| `ONE_MATERIAL` | advice | a face nearly all one block |
| `FLAT_ROOF` | advice | the top one flat height, not stepped |
| `BLOCKY_ROOF` | advice | a sloping roof of whole blocks where stairs could be |
| `LOW_CEILING` | advice | a room two blocks high |
| `NO_SETTING` | advice | bare ground all round |
| `BARE_FACE` | advice | a face with few shape blocks (stairs, slabs, walls, trapdoors, lanterns): masses without detail |
| `DARK_AT_NIGHT` | advice | over half of the places a player walks to is dark at night |
| `SPARSE` | advice | a part where players walk with little detail near them: an empty hall, square or deck |
| `PART_OVERLAP` | advice | two parts (`parts.define`) overlap without one inside the other: regenerating either rewrites the other |

- A fix is wrong for any build. Weigh advice against the build's purpose:
  a market stall is open, and a tower's roof may be flat.
- A player walks on two clear cells over something solid, steps onto stairs
  and slabs, jumps one block, drops three, and climbs ladders and vines.
  Blocks are sorted by their names.
- `--json` prints one JSON object. The command exits 1 when there is
  something to fix.
- `--since` counts changed blocks by the innermost part that holds them,
  and counts the rest as `(in no part)`.

Ship a build too big for `chunk:set` lines as a `.schem` in the pack folder,
and paste it:

```lua
local lobby = world.schematic("builds/lobby.schem")   -- at the top, not per chunk
world.on_generate(function(chunk)
    chunk:paste(lobby, vec3(0, 64, 0))         -- origin is the build's lowest corner
end)
world.paste(lobby, vec3(100, 64, 0))           -- the same build, live
chunk:paste(lobby, vec3(0, 64, 0), { air = true })   -- both take this third argument
```

The rules:

- `file` is a path inside the pack folder, written with `/`. These are
  errors that name the file: a path from the root, a path that leaves the
  pack with `..`, a missing file, and a file that is not a schematic.
- Call `world.schematic` while the pack loads and keep the value. Inside
  `on_generate`, it reads the file again for every chunk.
- `origin` is where the build's **lowest** corner goes. The build fills
  `origin` to `origin + schem.size - vec3(1, 1, 1)`.
- Air in the build is skipped, so a paste sits on the terrain. Pass
  `{ air = true }` to place the air too.
- `chunk:paste` writes only the part inside its chunk, so the call in
  `on_generate` builds the whole thing. `world.paste` writes all of it at
  once, like `world.set_blocks`.
- Sponge v2, Sponge v3 and the old MCEdit `.schematic` all load. Block
  entities (chest contents, signs) and entities do not: a chest pastes
  empty.
- A paste does not turn. Turn the value first with `:rotate` or `:mirror`
  (see "turning a build"). A file's schematic has them too.
- A paste keeps the exact blocks of any release Citadel knows. A newer
  name becomes the nearest block. What nothing covers becomes air, and the
  log names and counts it once per file.

### the time of day

The time is in ticks, 0 at dawn and 24000 to a day. Each room has its own
time, and late joiners get the same sky.

```lua
world.time("night")          -- sets the hour: sunrise 23000, day 1000, noon 6000, sunset 12000, night 13000, midnight 18000
world.time(18000)            -- sets the hour, in ticks
world.time(function(s)       -- a cycle: asked each tick, s seconds after this call
    return 1000 + s * 40     -- a day of ten minutes, from morning
end)
world.time(function(s)       -- anything the pack likes: a day that stops at dusk
    return math.min(1000 + s * 20, 12000)
end)
local now = world.time()     -- 0 .. 23999
```

- A call replaces the previous one, a function too.
- The function returns ticks or a name. If it errors, the sky stays where
  it was.
- Whether the sun moves is a rule: `world.rules{ day_cycle = true }` runs
  the version's own day (20 minutes), and nothing else of survival.
- On a `mode: lite` world and in a room made by `rooms.create`, the rule is
  off and the sun stays straight overhead (noon).
- On a `mode: full` world, and after `world.rules{ survival = true }`, the
  rule is on.
- A number or a name sets the hour. With `day_cycle` on, the day runs on
  from there, as `/time set` does. With it off, the sky stays there.
- A function drives the sky itself. The engine's day stands aside until the
  next `world.time` call.
- A stopped sky, the normal day or an `s * 20` day costs one packet a second. A faster or
  slower day costs one packet every tick it moves.

Reading blocks:

```lua
local here = world.get_block(player.at - vec3(0, 1, 0))   -- "grass_block"
local box = world.get_blocks(vec3(0, 64, 0), vec3(15, 64, 15))  -- 256 names
--   the order is x, then z, then y: index ((dx * zn) + dz) * yn + dy + 1
```

**A read never generates.** A position in an unloaded chunk reads as `nil`
(not loaded), not `"air"`. Inside `on_generate`, `chunk:get` always works.

A block change is stored, so late joiners see it. A block name may list `|`
alternatives (`"deepslate|stone"`): the first one the game version knows
wins. Without `|`, an unknown name becomes the nearest block, never air.

### containers

A chest's stacks, for a pipe, a quarry or a sorting machine to take from
and put into:

```lua
local box = world.container(pos)   -- nil unless the block there is a chest
box.size                           -- 27
box:items()                        -- { { slot = 1, item = "cobblestone", count = 12 }, ... }, the filled slots
box:take("cobblestone", 16)        -- up to 16, slot by slot; answers how many it took
box:put{ item = "brick", id = "copper_ingot", count = 5 }   -- answers how many did not fit, 0 for all of it
```

- A chest a player has open belongs to that player until they close it.
  Until then, `take` and `put` do nothing.
- Each half of a double chest is its own 27 slots.
- A kept handle never goes stale. `items()` on a chest that is gone returns
  an empty list.

### populating the overworld

```lua
world.on_populate(function(chunk) end)   -- once per chunk the overworld terrain made, after it made it
```

`on_populate` works on the engine's overworld (`world: overworld`, or
`mode: full` with no `world` key). It gets each new chunk with terrain,
caves and ores in place, with the same `chunk:get`, `chunk:set` and
`chunk:fill` as `on_generate`. Use it for your own ores and trees. A changed
hook reaches new land only.

### biomes

A biome is what the client colours a column by: the grass, the leaves, the
water, the sky and the fog. It is also the weather there. Each block column
has one biome.

```lua
chunk:set_biome(pos, "desert")                      -- one column; pos.y is not read
chunk:fill_biome(chunk.min, chunk.max, "jungle")    -- each column of a box, clipped to the chunk
chunk:get_biome(pos)                                -- "jungle"; nil outside the chunk
world.get_biome(pos)                                -- the same for a loaded chunk; nil when it is not loaded
```

- A column that nothing sets is `"plains"`.
- The engine's overworld sets the biomes of its own chunks. `on_populate`
  can read them and change them.
- A name is a vanilla biome name of any release: `"windswept_hills"` and
  `"mountains"` are the same hill. A wrong name is an error.
- A client that lacks a biome shows the nearest one it has. A 1.8 client
  shows `"cherry_grove"` as plains.

A pack makes biomes of its own. A new biome is a copy of a vanilla biome
with other colours and weather:

```lua
local crystal = game.biomes.define {
    name = "crystal",        -- becomes "mypack:crystal", which define returns
    like = "forest",         -- the vanilla biome to copy; "plains" when left out
    grass = "#7fd8c8",       -- each colour is a colour name or a color value
    leaves = "#58b7a6",
    water = "#3fd0ff",
    water_fog = "#0a4060",   -- the view under water
    sky = "#b0e8ff",
    fog = "#e0f6ff",         -- the far distance
    weather = "snow",        -- "rain" or "snow"; "none" or false for no weather
}

world.on_generate(function(chunk)
    chunk:fill_biome(chunk.min, chunk.max, crystal)
end)
```

- Define biomes at the top of the script. A client learns the biomes when
  it joins.
- Clients from 1.16.2 show a new biome. An older client and a Bedrock
  client show the `like` biome.
- A changed colour reaches a player on the next join. A biome that is
  new after the first player joined shows as its `like` until the server
  restarts. The console says so.
- A colour that is left out stays as `like` has it. `weather = "snow"`
  also makes the grass and leaves colder in colour, unless you set them.
- A biome does not make trees or blocks. The generator puts them there.

### noise

`noise` gives smooth random numbers for hills, caves and biome borders. The
engine calculates them, so a generator stays inside its 100 ms.

```lua
local hills = noise.new { seed = 7, scale = 96, octaves = 4 }
hills:get(x, z)                 -- about -1 .. 1, for a height
hills:get(x, y, z)              -- the same in 3D, for caves and overhangs
hills:grid(x, z, 16, 16)        -- 256 heights in one call: [dz * 16 + dx + 1]
```

| Option | Default | Meaning |
|---|---|---|
| `seed` | 0 | the same seed gives the same numbers each time |
| `scale` | 64 | the size of one hill, in blocks |
| `octaves` | 1 | layers of detail, 1 to 16 |
| `lacunarity` | 2 | how many times finer each next layer is |
| `gain` | 0.5 | how many times as strong each next layer is |

A world with hills and two biomes:

```lua
local hills = noise.new { seed = 7, scale = 96, octaves = 4 }
local climate = noise.new { seed = 8, scale = 300 }

world.on_generate(function(chunk)
    local h = hills:grid(chunk.min.x, chunk.min.z, 16, 16)
    local c = climate:grid(chunk.min.x, chunk.min.z, 16, 16)
    for z = 0, 15 do
        for x = 0, 15 do
            local i = z * 16 + x + 1
            local at = chunk.min + vec3(x, 0, z)
            local top = 64 + math.floor(h[i] * 24)
            local dry = c[i] > 0
            chunk:fill(at, at + vec3(0, top - 1, 0), "stone")
            chunk:set(at + vec3(0, top, 0), dry and "sand" or "grass_block")
            chunk:set_biome(at, dry and "desert" or "forest")
        end
    end
end)
```

- Make each noise at the top of the script, not inside `on_generate`.
- Ask for a chunk with one `grid` call. 256 `get` calls are slower.
- `grid` gives up to 65 536 numbers (256 x 256).

### a declared world

`world.generate` declares a world as rules. The engine makes each chunk from
them, on all cores, and no script runs for a chunk. Use it for a large world.
`world.on_generate` stays for what the rules cannot say.

```lua
local hills = fields.noise { seed = 7, scale = 96, octaves = 4 }
local dry = fields.noise { seed = 8, scale = 300 }:gt(0)

local made = world.generate {
    height = 64 + hills * 24,                -- the y of the surface
    sea = 62,                                -- water fills the open air up to here
    biomes = { { "desert", when = dry }, { "forest" } },   -- the first that holds
    surface = {                              -- the first rule that holds, for each block
        { block = "stone", when = fields.slope:gt(2), depth = 4 },
        { block = "sand", biome = "desert", depth = 4 },
        { block = "grass_block" },           -- depth 1: the top block
        { block = "dirt", depth = 4 },       -- the 3 blocks below it
    },
    rock = { { block = "stone" } },          -- the body of the land
    plants = { { block = "short_grass", chance = 0.3, biome = "forest" } },
    things = { { cell = 8, { shapes = { oak }, chance = 0.4, biome = "forest" } } },
}
made:sample(hills, pos)     -- a field's value there, as the engine calculates it
made:biome_at(pos)          -- "forest"
```

**A field** is a number at each block, written as a recipe. `fields.noise`
gives one, and maths on fields gives more: `+ - * / ^`, a minus sign, and
the methods. A number is a field too.

```lua
fields.noise { seed = 7, scale = 96, octaves = 4, solid = false }   -- about -1 .. 1; solid = true changes with y
fields.x, fields.y, fields.z                -- the block's own coordinates
fields.height, fields.slope                 -- the surface y of the column; the step to its steepest neighbour
fields.water, fields.shore                  -- the water depth over the surface (0 or less on land); 1 at the water's edge
fields.depth                                -- blocks under the surface: fields.height - fields.y
fields.room                                 -- the height of the open space the block is in (0 in rock, 64 at most)
fields.hash(cell, seed)                     -- one number 0 .. 1 for each square of `cell` blocks
fields.cells(size, seed)                    -- { distance = field, random = field }: the nearest point of a scattered grid
fields.mix(a, b, t)                         -- a where t is 0, b where t is 1
f:abs()  f:floor()  f:sqrt()  f:min(g)  f:max(g)  f:clamp(low, high)
f:gt(g)  f:lt(g)                            -- 1 or 0
f:smooth(from, to)                          -- 0 at from, 1 at to, smooth between
f:curve({ { -1, -40 }, { 0, 2 }, { 1, 20 } })   -- straight lines through the points
f:at(dx, dy, dz)                            -- f at the block that far away
```

```lua
-- 1 on a column with water beside it: sugar cane beside water.
local w = fields.water
local beside_water = w:at(1, 0, 0):max(w:at(-1, 0, 0)):max(w:at(0, 0, 1)):max(w:at(0, 0, -1)):gt(0.5)
plants = { { block = "sugar_cane", height = 2, chance = 0.5, when = beside_water * w:lt(0.5) } }
```

- A rule asks a question with `when`: it holds where the field is above
  0.5. `a * b` is "and", `a:max(b)` is "or", `1 - a` is "not".
- `height` cannot use `fields.height`, `slope`, `water` or `shore`: they
  are read from it.
- `biome` in a rule is a biome name. It is the same as a `when`, and faster.

**The rules:**

| Key | A rule | Meaning |
|---|---|---|
| `biomes` | `{ "desert", when = f }` | the first that holds names the biome of the column |
| `surface` | `{ block, biome, when, depth }` | `block` for the top `depth` blocks (1) of each surface |
| `rock` | the same | the body of the land under the surface rules |
| `plants` | `{ block, chance, biome, when, ... }` | at most one plant on a column |
| `things` | `{ cell, seed, { shapes, chance, biome, when, afloat, place, y }, ... }` | at most one thing in a grid cell |
| `fluids` | `{ block, below, biome, when }` | the carved air under `below` becomes `block`; the first that holds |

- A **block** is a name, or a list with a field that chooses:
  `{ "stone", "andesite", by = fields.hash(3) * 2 }`. `floor(by)` counts
  through the list.
- A **plant** is `block`, or `blocks = { lower, upper }` for a plant of two
  blocks. With `height = f` it grows: `block` repeats, and `tip` is the top
  block. `afloat = true` puts it on the water, and `sink = 1` puts it one
  block lower (ice in the top of the sea). `clear = n` keeps `n` blocks of
  water free over a plant that grows in water.
- A column tries the plant rules in order. Each rule that holds takes its
  `chance` of the column's roll, so two rules of 0.3 and 0.2 give a plant
  on half of the columns.
- A plant stays only where the game version's own rule lets it stay, for
  example cane needs water beside the block under it, at the same level.
  Where the rule fails, the column has no plant. Light is not known yet,
  so a rule about light is not checked.
- A **thing** is one of `shapes`: builds from `world.build` or
  `world.schematic`. Its `(0, 0, 0)` goes on the block above the ground. A
  thing that crosses a chunk border is complete. Nothing stands on ground
  that is under water, but `afloat = true` puts the thing on the water.
- `density = f` makes a block solid where `f` is above 0. Use it with a
  `solid` noise for caves, overhangs and land in the air. With `height`
  too, a block must pass both.
- Without `height` and `density`, the rules add to the land that the
  engine's own terrain made (`world: overworld`): surface rules do not
  run, plants grow on each column, and a thing must stand inside one chunk.
- Make the shapes and the fields at the top of the script, within the load
  limits (see "loading").

**Caves.** `density` carves air under the top surface. A plant or a thing
goes into that air with `place`, and `fluids` fill it:

```lua
local caves = fields.noise { seed = 3, scale = 24, octaves = 2, solid = true }
world.generate {
    height = 72 + hills * 20,
    density = 1 - caves:abs():lt(0.12) * fields.y:gt(5),   -- caves under y 5 and up
    rock = { { block = "stone" } },
    plants = {
        { block = "moss_carpet", place = "floor", chance = 0.6 },          -- moss on cave floors
        { block = "cave_vines_plant", tip = "cave_vines", height = fields.room / 3,
          place = "ceiling", chance = 0.3 },                               -- glow berries from the ceilings
        { block = "glow_lichen[{wall}=true]", place = "wall", chance = 0.1, y = { 0, 50 } },
    },
    fluids = { { block = "water", below = 30 }, { block = "lava", below = 10 } },  -- a lake, and lava under it
    things = { { cell = 6, { shapes = { stalagmite }, place = "floor", when = fields.room:gt(5) } } },
}
```

| `place` | Where | At most |
|---|---|---|
| `"top"` (the default) | on the top surface, as before | one plant on a column |
| `"floor"` | the air block over each floor of a cave | one plant on each floor |
| `"ceiling"` | the air block under each ceiling, hanging down | one plant under each ceiling |
| `"wall"` | each air block of a cave with rock on a side (plants only) | one plant in each block |

- A column can cross many caves. Each floor and each ceiling of each cave
  is its own place, with its own roll.
- `y = { low, high }` keeps a rule to the blocks it starts at from `low` to
  `high`. `when`, `chance` and `y` are read at the air block the plant
  starts in, not at the rock under it.
- A plant that grows (`height`) under a ceiling hangs down: `block` is at
  the ceiling and `tip` is the lowest block. With `blocks`, the first is at
  the ceiling. A plant never grows into rock, a fluid or another plant.
- A wall plant is one block. In its name, `{wall}` is the side the rock is
  on and `{facing}` is the side away from it: `"vine[{wall}=true]"`,
  `"wall_torch[facing={facing}]"`, `"cocoa[facing={wall}]"`.
- A thing on a floor has its `(0, 0, 0)` on the air block over the floor. A
  thing under a ceiling has its `(0, 0, 0)` on the air block under the
  ceiling, so build it down from there (negative y). A grid cell holds one
  thing; when its column has several caves, the cell's roll picks one. A
  thing does not look at fluids or at the size of the cave: use
  `when = fields.room:gt(n)` and `y` to keep it in a cave it fits.
- A fluid fills only carved air, from the floor of a cave up to `below - 1`.
  The open sky over the top surface is the `sea`'s, not the fluids'. A cave
  that opens to the sea from the side is not flooded: give it a fluid rule
  under the sea level. Plants go only where the air stays air.
- `fields.room` counts the air block, the air over it and the air under
  it, up to 64. The open sky over the top surface reads 64. Read it with
  `at` anywhere; another column's room costs one `density` read for each
  block of it. `density` cannot use `fields.room`.
- `fields.depth` is measured from `height`, so it needs a `height`.
- The game version's own plant rule holds in caves too. On 1.8.9, grass and
  flowers need dirt under them, so a stone floor keeps none. Cave blocks
  that 1.8.9 does not have (moss, glow lichen, hanging roots, cave vines)
  stay. `vine` keeps its 1.8.9 rule: rock on its side.
- Caves need `density` or `carvers`: a rule with `place` under the top, or
  a fluid, without one of them is an error.

**The game's own caves and structures.** `carvers` and `structures` run the
game version's own generators over the declared land, with the world seed:

```lua
world.generate {
    height = 64 + hills * 20,
    rock = { { block = "stone" } },
    carvers = { "caves", "ravines" },        -- the game's tunnels and ravines
    structures = { "mineshaft", "dungeon" }, -- with rails, spawners and loot
    plants = { { block = "moss_carpet", place = "floor" } },  -- in those caves
}
```

| Key | Names | Versions |
|---|---|---|
| `carvers` | `"caves"` | every version |
| | `"ravines"` | b1.8 and later |
| `structures` | `"mineshaft"`, `"dungeon"` | 1.7 to 1.12 |

- They dig and build after the land (`height`, `density`) and before the
  plants, fluids and things, so the cave rules (`place`, `fluids`) use the
  caves they dig. They need `height` or `density`: the game's own terrain
  (`world: overworld`) has its own.
- A dungeon's spawner has its mob and its chest has its loot, as in the
  game. Without the lists, the world has none of them.
- A name this version does not have is an error that names the ones it has.

## Named parts

The world folder (`world: city`) is the source of truth. It is stored, saved
as people edit it, and shipped with the pack. A **part** is a named box of it
that a generator writes on request.

```lua
parts.define {
    name = "tower-3",                  -- unique; a path, "downtown/tower-3", nests
    at = vec3(56, 64, 15),             -- where the build's block (0, 0, 0) lands
    detail = 1,                        -- as world.build: 1, or 2 for half blocks
    build = function(b) ... end,       -- exactly a world.build function
}
```

The rules:

- **Nothing runs on load.** `parts.define` only declares the part. A
  generator runs on request (`citadel generate`, or `/part generate` in build
  mode) or when its code changes. A server boots the stored world and runs no
  generator.
- Each word of a name is 1 to 64 letters, digits, `-`, `_` and `.`.
- A duplicate name is an error that names the file of the first definition.
- A part is its whole box, air included. Writing it again clears what the old
  box held outside the new box.
- `citadel render` and `citadel check` frame the `b:part`s inside a part by
  path, for example `"tower-3/roof"`.
- On a `world: script` pack, `parts.define` logs that parts need a world
  folder, and generates nothing.

Each part is in one of four states, kept in `<world>/parts.json`:

| state | means | when its code changes |
|---|---|---|
| **clean** | the box holds exactly what its generator last wrote | written again, by itself |
| **modified** | somebody edited blocks in it since | left alone, and reported: "its code changed" |
| **kept** | somebody chose its blocks: they are in `parts/<name>.schem` in the pack | ignored: the generator no longer owns it |
| **orphaned** | its definition is gone from the pack | reported: keep it, or regenerate it to remove its blocks |

```json
{ "tower-3": {
    "state": "modified",
    "region": [[48, 64, 4], [64, 119, 26]],
    "module": "city.luau",
    "generated": "sha256:…",
    "at": "2026-09-27T14:02:11Z",
    "edits": { "count": 214, "by": { "melvin": 200, "agent:claude": 14 } }
} }
```

**Only people and the agent make edits, never scripts.**

- An edit in build mode counts under the player's name. An agent edit counts
  under `agent:<client>`.
- Either kind makes a clean part modified.
- Blocks your script writes are not edits: `world.set_block` from a callback,
  a door it opens, a display, a ride.
- `citadel parts` and `/part` confirm the state against the `generated` hash.
  A modified part with every edit undone is clean again.

**You regenerate or keep a whole part.** Hand edits never merge into new
code.

- `regenerate` clears the part and runs its generator. On an orphan, it
  removes the blocks.
- `keep` saves the blocks to `parts/<name>.schem` as Sponge v3, the format
  `world.schematic` reads. Generating a kept part pastes that file.
- `release` deletes the file and regenerates the part.

**When the code changes.** Saving a `.luau` file reloads the pack. Parts
defined **in that file** then act as the table says.

- A clean part is written again through the tick. Unchanged blocks are
  skipped.
- On start, files changed while the server was down count too.
- A change to a module that a part `require`s re-runs nothing.

**Nested and overlapping parts.** A block belongs to the innermost part whose
box holds it.

- Writing a parent leaves its nested parts alone.
- An edit inside a nested part counts against it, not its parent.
- Where parts overlap without nesting, an edit counts against each.
  `citadel check` warns (`PART_OVERLAP`): regenerating one rewrites the other.

From the command line, on the world folder:

```sh
citadel generate <pack> --part tower-3      # run one generator into the world; --parts runs every one
citadel parts <pack>                        # every part: state, region, module, edits and who; --json
citadel regenerate <pack> --part tower-3 [--yes] [--render before.png]
citadel keep <pack> --part tower-3          # its blocks become parts/tower-3.schem
citadel release <pack> --part tower-3       # a kept part goes back to its generator
```

- `generate` makes the world folder if it is missing. It writes new and clean
  parts, pastes kept parts from their files, and refuses modified parts.
- `regenerate` of a part with hand edits needs `--yes`. Without it, it writes
  nothing and says how many blocks of whose edits it would overwrite.
- `--render file.png` writes `file-before.png` and `file-after.png`.
- Stop any server running the pack first, or use `/part` in the game.
- `citadel check` and `citadel render` read the world folder with its hand
  edits. The check report has a "part states" section: states, edits,
  authors, and code changes.

### build mode

Build mode works only on a development copy (`citadel.env` is
`"development"`), never on a live instance. A player with the `citadel.build`
permission builds by hand. Every operator has it.

```
/build                          creative and flight, and your clicks change the world; again to stop
/build wand                     the wooden axe: left click the first corner, right click the second
/build pos1, /build pos2        a corner where you stand
/build fill <block>             the selection, filled
/build replace <from> <to>      one block for another in the selection
/build copy                     the selection, held from where you stand
/build paste                    the clipboard, the same way round you as it was copied
/build rotate <90|180|270>      the clipboard, turned about where you stood
/build mirror <x|z>             the clipboard, flipped
/build undo                     your last edit, taken back
/part                           the part you look at: its state, its region, who edited it
/part <name>, /part list        one part by name; every part
/part generate <name>           run a part's generator
/part regenerate [name] [confirm]   throw its hand edits away; asks for "confirm" when there are some
/part keep [name]               its blocks become parts/<name>.schem
/part release [name]            a kept part back to its generator
/part outline                   every part's box nearby, 15 seconds: green clean, amber modified, blue kept, red orphaned
```

- Every block a builder changes, undo included, is an edit under their name.
- Outside build mode, a click on a pack server changes no blocks.
- A place puts the held item's block, facing as in the game. A pack's
  own block item places the pack's block.
- Undo is per player, 64 edits deep. One command is one edit of at most one
  million blocks.
- Rotate and mirror turn facings, axes and shapes, as `build:rotate` and
  `build:mirror` do.
- The outline is particles for the asking player only, on clients from 1.7.

## Custom blocks

`game.blocks.define` gives a pack its own block:

```lua
local crate = game.blocks.define {
    name = "crate",
    looks = "tnt",
    on_use = function(block, player)
        block:become("primed_tnt", { fuse = 20 })
        return "used"
    end,
}

world.set_block(vec3(10, 65, 10), crate)   -- the handle, or "rave:crate"
```

It is a real block: saved under its own name, broken, used and ticked like
any other. Every client that has never heard of your pack draws it as TNT.

Three rules apply:

* **The engine adds the namespace.** `"crate"` becomes `"rave:crate"`, after
  your pack. A colon in the name is an error. The handle `define` returns
  works wherever a block name works.
* **`looks` is all a client sees.** Pick an inert block state that reads
  right. A name this version lacks is an error, not air. `|` takes the first name that
  exists: `looks = "crimson_planks|nether_brick"`.
* **Hooks record changes; the engine applies them.** `block:become` takes
  effect when your hook returns.

### the definition

```lua
game.blocks.define {
    name = "crate",              -- no namespace: yours is added
    looks = "tnt",               -- or { "wheat[age=0]", "wheat[age=7]" }, one per state
    hardness = 0.5,              -- seconds-scale; below zero is unbreakable
    resistance = 6,              -- what an explosion has to chew through
    material = { solid = true, covers = false, firm = true, liquid = false, burns = false },
    opacity = 15,                -- what a step through it takes off the light
    light = 0,                   -- what it gives off, 0..15
    tick_every = 0.5,            -- seconds between block:schedule() and on_tick
    drops = { { item = "stick", count = 2 } },   -- or "table"; "none" or false for nothing; a row may be a pack item
    item = { item = "furnace", name = "Crate" },  -- the block in a hand; see "the block as an item"; false for no item
    texture = "textures/crate.png",  -- its own picture on 1.21.4+; see "blocks with their own pictures"
    model = models.crate,        -- or its own shape, in place of texture; see "blocks drawn from a model"
    facing = true,               -- turns its front to whoever places it
    power = 0,                   -- what it gives a redstone circuit, 0 or 15; see "power"
    label = "Crate",             -- the name of the item a textured block comes with
    extends = "tnt",             -- a name, a handle, a plain table, or a list
    on_use = function(block, player, held, base) end,
}
```

- Every field except `name` and `looks` has a default.
- Call `define` only **while your pack loads**.
- Define blocks at the top of `main.luau`. A reload runs `define` again and
  keeps the world.

### blocks with their own pictures

`texture` gives a block its own picture on 1.21.4 and later. `facing = true`
turns its front to whoever places it, like a furnace:

```lua
local side = game.texture(16, 16)
side:noise(0, 0, 16, 16, { "#8a8a8a", "#7d7d7d", "#969696" }, 3)
side:frame(0, 0, 16, 16, "#5a5a5a")
local front = side:copy()
front:rect(4, 4, 8, 8, "#303030")

local macerator = game.blocks.define {
    name = "macerator",
    looks = "dispenser",                  -- what an older client sees; left out, stone
    texture = { side = side, top = side, bottom = side, front = front },
    facing = true,
    label = "Macerator",                  -- the item's name
}
player:give(macerator.item)
```

- `texture` is one picture for all six faces, or a table of `all`, `side`,
  `top`, `bottom`, `front`, `back`, or a face by name (`north`, `up`, ...).
  `front` is the side a facing block faces; `back` is opposite. A missing
  face uses `side`, and `side` uses `all`.
- Several states take a list, one per state:
  `texture = { idle, working }` with `looks = { "furnace", "furnace[lit=true]" }`.
- `facing = true` gives every state four facings. `block.state` counts only
  your states. `block.facing` reads and turns the facing (`"north"`,
  `"south"`, `"west"`, `"east"`). The `looks` block turns too if it can.
- A textured block comes with its item. `label` names it. `item` sets
  another item underneath. `item = false` gives the block no item.
- The picture is a full, opaque cube: see-through pixels draw solid. A
  server has room for about a thousand textured blocks.
- A client from 1.21.4 draws a textured cube on a note block state, so it
  hears a note block (wood) when the block is hit or broken. An older client
  hears the `looks` block.
- A block a pack places is never drawn as a textured block. A pale moss
  carpet with moss up its sides can show as a bare one.
- The block collides as its `looks` block does. One that looks like a rail
  or a carpet is drawn on a state a client walks through or over; a server
  has room for about a hundred of each. See "blocks drawn from a model".

### blocks drawn from a model

`model` draws a block from a model on 1.21.4 and later, in place of
`texture`. This is a conveyor belt whose top runs by itself:

```lua
local belt = models.new("belt", function(m)
    local frame = m:material("frame", colors.gray, { grain = 0.2 })
    local strip = m:texture(16, 16, { scroll = "up", speed = 2 })   -- two texels a tick, on the client
    strip:fill(colors.black)
    strip:rect(0, 0, 16, 2, colors.gray)
    m:part("body"):box(vec3(-8, 0, -8), vec3(8, 16, 8), frame, { faces = { up = strip } })
end)

local DIR = { north = vec3(0, 0, -1), south = vec3(0, 0, 1), west = vec3(-1, 0, 0), east = vec3(1, 0, 0) }

game.blocks.define {
    name = "belt",
    looks = "stone",                      -- what an older client sees; left out, stone
    model = belt,
    facing = true,
    label = "Conveyor Belt",
    on_step = function(block, body)       -- carry what lies on it toward the block's front
        if body.kind ~= "item" then return end
        local at, dir = block.at, DIR[block.facing]
        for _, it in world.entities { near = vec3(at.x + 0.5, at.y + 1, at.z + 0.5), radius = 1.5 } do
            if it.id == body.id then it:push(vec3(dir.x * 0.05, 0, dir.z * 0.05)) end
        end
    end,
}
```

- The model stays inside its block: `-8 .. 8` across and `0 .. 16` up. A box
  outside that is an error. A bigger shape is a display.
- **A block collides as its `looks` block does**, for the server and for
  every client. `looks` picks what the model is drawn on:
  - A full cube (`"stone"`, the default): players stand on it, and the
    client does not draw the sides of its neighbours that touch it. Where
    the model leaves the side of the cube open, you see through the
    neighbour. Fill the block's sides.
  - A block you walk through (`"rail"`, `"stone_pressure_plate"`): the model
    can be any low shape, and nothing around it is hidden. A stack dropped on
    it lies on the block below, and `on_step` still hears it. A client from
    1.21.4 breaks it at a touch, whatever its `hardness`; a `hardness` below
    zero still cannot be broken.
  - A carpet (`"white_carpet"`): a sixteenth of a block high.
  - Any other shape (a slab, a fence) is drawn on a full cube.
- A low belt is the same definition with `looks = "rail"` and a model two
  units high. It needs a floor under it. Give it `opacity = 0`, or the block
  is dark inside.
- A block draws the model in its rest pose. It plays no animation and takes
  no `paint`. A see-through material draws solid.
- A texture with `scroll` moves by itself on the client, with nothing sent:
  `"up"`, `"down"`, `"left"` or `"right"`, at `speed` texels a tick. A speed
  is a whole number, or `0.5`, `0.25`, `0.2` for one texel every few ticks.
  On a top face, `"up"` runs toward the model's front (`-z`), which is where
  `block.facing` points. A display draws a scrolling texture still.
- `model` is one model for every state, or a list with one per state, like
  `texture`. `texture` and `model` together are an error.
- Like a textured block, it comes with its item, and it uses one spare state
  per state and facing.

### the block as an item

`item` is the block in a hand, with the block's name as its `id`. Placing
it puts **this** block down. Breaking the block leaves it, unless `drops`
says otherwise:

```lua
local macerator = game.blocks.define {
    name = "macerator", looks = "furnace",
    item = { item = "furnace", name = "Macerator", lore = { "grinds ore into dust" } },
}
player:give(macerator.item)       -- a Macerator; place it and it is one
game.recipes.shaped{ pattern = { "FFF", "F F", "FFF" }, keys = { F = "flint" }, result = macerator.item }
```

Placing it fires `players.on_place`, then the block's `on_place` with the
placer and an empty `block.data`.

### the block handle

Every hook gets the block it is about. Fields read; methods act:

```lua
block.at         -- vec3
block.name       -- "rave:crate"
block.room       -- which room it is in
block.state      -- which of this definition's states, counting from 1; writable
block.facing     -- a facing block's front, "north" ... "east"; writable. nil for one that does not turn

block:get("up")            -- the block one face away, by name — a live read
block:set("stone")         -- put another block here
block:destroy()            -- take it out, leaving nothing
block:become("primed_tnt", { fuse = 20 })   -- stop being a block; be that
block:drop("stick", 2)     -- leave a stack on the ground here; an item table keeps its id: block:drop(COPPER, 3)
block:schedule()           -- ask for on_tick, tick_every seconds from now
block:notify()             -- tell the six neighbours it changed
block.powered              -- true while a redstone signal reaches it; see "power"
```

For crop stages, give one `looks` per stage and write `block.state = 3`. The
value must be in that list. A state change keeps the block: `block.data`
stays, and `on_removed` and `on_added` are not called.

### block.data

`block.data` holds what a block remembers besides its state, such as a
chest's contents. It is a [data view](#data-views): nested edits and whole-record
assignments are tracked, just like a pack-defined entity's `data`. Read and write its fields:

```lua
on_use = function(block, player)
    block.data.clicks = (block.data.clicks or 0) + 1
    player:message(`clicked {block.data.clicks} times`)
    return "used"
end,
```

- `block.data` belongs to the **position**. It saves with the chunk, through
  reloads and restarts.
- Each write is checked at the assignment by the `storage.set` rules. A
  bad value is an error that names the key.
- When the block goes, its data goes.
- Pack-wide facts, such as a leaderboard, go in `storage`.

### Data views

`block.data` and a pack-defined entity's `data` are attached records. Nested
records and lists are attached too: `e.data.stats.wins += 1` writes back without
assigning the whole record again. This works on handles from `world.spawn` and
`world.entities`, as well as handles passed to hooks.

```lua
e.data = { stats = { wins = 0 }, history = {} }
local stats = e.data.stats
stats.wins += 1
data.insert(e.data.history, { score = 12 })
e.data.history[1].score += 3
local last = data.remove(e.data.history) -- removes and returns a detached value
local snapshot = data.copy(e.data)      -- an ordinary, detached Lua table
snapshot.stats.wins = 99               -- does not change the entity
```

- Roots are records with string keys. Values can be finite numbers, strings,
  booleans, records, or contiguous lists starting at index 1. Functions, handles,
  cycles, sparse lists, and tables mixing list indices and record keys raise an
  error before any part of that assignment changes the record.
- Set a record field to `nil` to delete it. Write `list[#list + 1] = value` to
  append, or use `data.insert(list, value)` / `data.insert(list, index, value)`.
  `data.remove(list, index?)` shifts following elements; its default is the last
  element. Assigning `nil` only removes the last list element. An empty nested
  `{}` becomes a list on the first insertion; the root always stays a record.
- `#view` counts entries. Use `for key, value in view do` to iterate. Data views
  are userdata, so use `data.copy(view)` before ordinary `table.*`, `pairs`, or
  `ipairs` operations. `storage.set(key, view)` accepts views directly.
- A nested alias follows its path in the current record. Replacing that path
  with another record or list updates what the alias sees. Deleting it or
  replacing it with a scalar makes the alias raise an error.
- Entity `on_steer`/`on_tick` and block hooks edit a draft applied when the engine
  accepts the hook's answer. Their views expire when the callback batch finishes,
  including on error. Use `data.copy` inside the hook to keep a snapshot, or
  obtain a current entity handle to edit later. Live entity views remain valid
  while the entity exists. An unchanged draft does not overwrite entity data.
- `player.data` remains an ordinary Lua table for the player's session. It can
  hold Lua objects such as HUD handles; it is not saved automatically. Persistent
  entity data saves only with `persist = "save"`; block data saves with its chunk.

Migration: direct and nested assignments now write through on every supported
handle. Replace table operations on persistent data with the `data` helpers or
operate on `data.copy(...)` and assign the result back. Mutating the Lua table
originally assigned to a record does not mutate the stored record.

### the hooks

Every hook gets the block first and `base` last:

| hook | called when | arguments | answers |
|---|---|---|---|
| `on_use` | somebody right-clicked it | `block, player, held, base` | `"used"` or `"pass"` |
| `on_break` | something broke it | `block, player, by, base` | `"none"`, `"table"`, or a drops list |
| `on_step` | a body is standing on it | `block, body, base` | nothing |
| `on_tick` | a scheduled tick came due | `block, base` | nothing |
| `on_random_tick` | the random pass landed on it | `block, base` | nothing |
| `on_place` | a player put it down | `block, player, base` | nothing |
| `on_neighbour` | a neighbour changed | `block, from, announced, base` | nothing |
| `on_trigger` | lit, blasted or burnt | `block, cause, base` | nothing |
| `on_power` | a redstone signal started or stopped reaching it | `block, powered, base` | nothing |
| `on_added` | it has just been stored, whatever stored it | `block, base` | nothing |
| `on_removed` | it has just gone | `block, base` | nothing |

- `player` is a handle. It is `nil` for a break with no player, or once that
  player left.
- `held` is the item in hand.
- `by` is `{ cause = "player" | "fire" | "explosion" | "water" | "support", tool, creative }`.
- `body` is `{ id, kind = "player" | "mob" | "item" | "other" }`. `body.kind` is
  `"mob"` for a cow or a zombie.
- `cause` is `"ignite"`, `"explosion"` or `"fire"`. A redstone signal is
  not a cause: it has `on_power`.
- `powered` is `true` when the signal started and `false` when it stopped.
- `from` is a `vec3`. `announced` is the name the notifying block gave.

**A hook exists only if you write it.** There is no flag such as
`random_ticks = true`. A block with no `on_step` is never asked about steps.

**Hooks answer with words, never booleans.** `"used"` takes the click;
`"pass"` does not. `"none"` leaves nothing. `"table"` leaves what the breaker
would normally leave. An answer nothing reads is an error that names it.

### extends, and base

`extends` takes a handle, a game block's name, a plain table, or a list of
those, **innermost first**. Data fields merge; hooks *wrap*.

```lua
-- A mixin is only a table.
local glowing = { light = 12 }
game.blocks.define { name = "lamp", looks = "gold_block", extends = glowing }

-- A crate that is a tnt underneath.
game.blocks.define {
    name = "bomb",
    looks = "tnt",
    extends = "tnt",
    drops = { { item = "stick", count = 1 } },
    on_break = function(block, player, by, base)
        base(block, player, by)    -- a0.1.0 lights every tnt a player digs
        return "none"              -- ...but this one leaves what *we* said
    end,
}
```

Every hook takes **`base` as its last argument**. Call it to extend the
block underneath; leave it out to replace it. Its effects land when your hook
returns, and a second call counts once.

Two rules for merging:

* **A game block's data is the floor**, wherever it is in the list.
  `extends = "tnt"` gives tnt's hardness and blast resistance unless you or a
  mixin set them. Your values beat inherited ones.
* **A hook you do not write is not asked.** The block underneath answers it.
  Extending tnt with no hooks costs nothing, even while your pack sleeps.

### amending the game's own

```lua
game.blocks.amend("tnt", {
    on_break = function(block, player, by, base)
        player:message("careful")
        base(block, player, by)
    end,
})
```

- **Hooks only.** A data field is an error that names it. For different
  numbers, use `game.blocks.define { extends = "tnt" }`.
- **Only the game's own blocks.** Never another pack's.

### what a missed deadline means, per hook

These rows add to the table under "saying no". Each hook has a deadline.
This is what a miss means:

| hook | a missed deadline means | why |
|---|---|---|
| `on_use` | **the click passes through** (`"pass"`) | fail-open. A busy pack must not stop people using the rest of the world, and a click that did nothing is visible where a click that was silently eaten is not. |
| `on_break` | **the block leaves the drops its definition declared** — never the looks block's | fail-**closed**. `drops = "table"` on a crate that looks like TNT would drop TNT, and anything that makes items must never make them twice. A definition that declared nothing leaves nothing. |
| `on_step`, `on_tick`, `on_random_tick`, `on_place`, `on_neighbour`, `on_trigger`, `on_power`, `on_added`, `on_removed` | **the block did not react this tick** | fail-open, and it costs nothing: the engine had already decided what it was doing. These are batched — five hundred crops taking their random tick are one message under one deadline — and answered at the end of the tick that asked. |

`can_stay`, `can_place_at` and `power` are **not** pack hooks. A pack block
answers them from its definition's data and what it extends: `power` is a
field, below.

### power

A block gives a redstone circuit power, hears one, or both. A script flips
it from anywhere with `world.block(pos)`:

```lua
-- A card reader: a click gives power for two seconds.
game.blocks.define {
    name = "reader",
    looks = { "iron_block", "redstone_block" },
    power = { 0, 15 },                    -- one value per state
    tick_every = 2,
    on_use = function(block) block.state = 2  block:schedule()  return "used" end,
    on_tick = function(block) block.state = 1 end,
}

-- A receiver: something happens when a wire reaches it.
game.blocks.define {
    name = "receiver",
    looks = "note_block",
    on_power = function(block, powered)
        if powered then sound.play("block.note_block.pling", { at = block.at }) end
    end,
}

local door = world.block(vec3(10, 65, 10))   -- the block there, or nil where the chunk is not loaded
if door and door.powered then print(door.name, "has a signal") end
world.block(vec3(4, 65, 4)).state = 2        -- a timer, a command or a zone turns the reader there on
```

`power` says what a state gives:

- A number is every face: `power = 15`. A list is one value per state, like
  `looks`.
- A table keyed by face gives it on those faces only, with the names
  `texture` takes: `power = { top = 15 }`, `power = { 0, { front = 15 } }`.
  `front` and `back` need `facing = true`.
- A value is 0 or 15. The game's signal has one strength, and a wire fades
  it by itself. Any other number is an error.
- It is the power a block of redstone gives: it lights the wire, lamp or
  piston that touches the face, and does not pass through a solid block.
- A state change that changes the power tells the neighbours. There is no
  `block:notify()` to remember.
- Without `power`, a block gives what it extends gives: `extends = "lever"`.
- Before 1.13 the client draws a wire's shape itself, from the `looks`
  block. A wire only bends toward a block that looks like a redstone part.

`on_power` says when the signal changed:

- It is called once when a signal starts to reach the block and once when
  it stops, not for every change beside it. `block.powered` reads it at any
  time, in any hook.
- The signal is the one a lamp reacts to: a lever or a lit wire beside the
  block, or a powered solid block next to it. The block's own power counts
  when it comes back through a wire.
- The last answer is saved with the block, so a restart repeats nothing.
  For a block of the game (`game.blocks.amend`) it is kept in memory: after
  a restart the first change beside it reports the signal as it is.
- A block of the game that becomes another block when it is powered is two
  blocks: `redstone_lamp` and `lit_redstone_lamp`.
- A pack's part reacts at the end of the tick, so it is a tick behind the
  game's own. For exact timing, extend a repeater.

`world.block(pos)` is the handle a hook gets, for any block:

- Reads are the world as it is now. What it does lands on the next tick,
  like `world.set_block`.
- `block.state` and `block.data` are for blocks this pack defined. On any
  other block they are an error.
- A handle you keep does nothing once its block is gone.

`world.rules{ redstone = false }` stops every signal in a room. See "Room
rules".

## Time and tweens

Ticks, timers and tweens: what runs later, and what changes smoothly.

```lua
time.on_tick(function(tick) end) -> connection   -- 20 times a second; keep it short
time.every(seconds, fn) -> connection            -- precise (1 ms), never drifts; use it for music
task.delay(seconds, fn, ...) -> thread            -- once, later; cancel with task.cancel(thread)
connection:cancel()                              -- stops it; every connection has this and only this
time.now()                           -- seconds since the pack started
os.time()                            -- whole seconds since 1970 (UTC), the wall clock
os.date("!*t")                       -- that time as { year, month, day, hour, min, sec, wday }; "!" is UTC
```

`time.now()` starts again at zero when the pack does. Use it for what
happens while the pack runs: a race, a cooldown. For something that ends
after a restart, such as a rental of a week, keep an `os.time()` in
`stores` and compare with it. It is UTC, so every server of an
experience reads the same clock, whatever its region:

```luau
local s = stores.open()
local ends, version = s:get("rent:" .. player.uuid)
if not ends or os.time() >= ends then          -- over, even if no server ran meanwhile
    s:set("rent:" .. player.uuid, os.time() + 7 * 24 * 3600, version)
end
```

### tween

`tween` eases a live number, `vec3`, `color` or `rotation` field, once a tick, such as
a display's `at` or a player's `speed`.

```lua
tween(door, { at = door.at + vec3(0, 3, 0) }, { duration = 0.5, easing = "out" })
tween(bar, { progress = 0 }, { duration = 30, on_done = function() ui.title{ title = "Time" } end })
local t = tween(sign, { scale = 2, color = "gold", rotation = { yaw = 90 } }, { duration = 1 })   -- a number is every axis of a vec3; a name is its colour
t:cancel()                           -- leaves it where it got to
t.done                               -- true once it landed
```

`easing` is `"linear"` (the default), `"in"`, `"out"`, `"in_out"` or
`"bounce"`. A `duration` that is not a number, or an `easing` that is not
one of these names, is an error. A display's own `animate` tweens on the client: smoother, but
1.19.4 and later only. Use `tween` for everything else and every client.

## Game data

`game` describes this room's game version. `rooms.create` inherits the
server's version. A world imported from a vanilla folder carries its own.

```lua
game.version                         -- "a0.1.0"
game.world_height                    -- 128; a 1.8.9 world is 256
game.sea_level
game.entities.names { mob = true }   -- {"pig", "sheep", "cow", ...}
```

### Blocks

`game.block(name)` returns one block in **this version's** numbers, or `nil`
if this game lacks it. `behaviour` is the rule Citadel runs for the block
(`"grass"`, `"flowing"`, `"torch"`, `"falling"`), or `nil` for an inert
block.

```lua
local stone = game.block("stone")
print(stone.hardness)                -- 1.5 in a0.1.0
print(stone.behaviour)               -- nil: stone just sits there
print(game.block("grass_block").behaviour)   -- "grass"
print(game.block("water").random_ticks)      -- does the random tick land on it
print(game.block("torch").light)             -- 14; what it gives off, 0..15
print(game.block("glass").light_filter)      -- 0; what a step through it takes away
print(game.block("obsidian").resistance)     -- what an explosion ray loses to it
print(game.block("oak_planks").flammability) -- { catches = 5, burns_away = 20 }
print(game.block("water").material.liquid)   -- the jar's Material, as its five questions:
--   solid, covers (grass under it dies), firm (snow and ice need it), liquid, burns
```

`resistance`, `flammability` and `material` are `nil`, not zero, in a game
with no block-update tables.

Everything above is read-only.

#### `drops` — `true`, `false` and `nil`

`drops` is the field of a game block that a pack writes. It says whether a
block of this kind leaves its item when the world breaks it by itself: a
torch whose wall is gone, a leaf that decays, a block an explosion or a
piston breaks, sand that cannot land.

On a `mode: lite` world, the world leaves no such item. The pack switches a
block on:

```lua
-- citadel.yml: mode: lite
game.block("torch").drops = true        -- a torch that falls off leaves a torch
game.block("wall_torch").drops = true   -- a torch on a wall is another block
print(game.block("torch").drops)        -- true
game.block("torch").drops = nil         -- the pack says nothing: the world's default
```

| Value | Meaning |
|---|---|
| `true` | The world leaves the block's normal drops, on a lite world too. |
| `false` | The world leaves nothing for this block, with `survival` on too. |
| `nil` | The pack sets nothing. The world's default applies. |

- The world's default is off on a `mode: lite` world and in a room made by
  `rooms.create`. It is on on a `mode: full` world and after
  `world.rules{ survival = true }`.
- The value is for every state of the block, and for this block name only.
  `oak_planks` and `spruce_planks` are two blocks.
- It reads what this pack set, not another pack's value. Where two packs
  disagree, `false` wins.
- It is not a player's dig. Without `survival`, a dig reaches no block.
- Use it for the game's blocks. A block from `game.blocks.define` leaves the
  drops its definition lists.
- A reload removes a value that the script does not set again.
- `true` is an error in a game version with no items on the ground.

### Items

`game.item(name)` does the same for items: the item's table, or `nil`. It
never raises an error.

```lua
if game.item("bucket") then player:give("bucket") end
print(game.item("stone").stack_size)   -- 64
```

### Entity kinds

A kind is a `mob` when the game gives it health and a mind of its own: a cow,
a zombie. An arrow, an item and a boat are not mobs. A player is not an
entity here: players are in `players`, never in `world.entities`. `game.entities.<kind>`
has the facts of one kind of the game. `game.entities.cow` and `game.entities.Cow` are the same
kind. A kind that this game does not have is `nil`:
`if game.entities.creeper then`.

```lua
local cow = game.entities.cow
print(cow.max_health, cow.width, cow.height, cow.speed)   -- cow.health is an error: a kind has a maximum
print(cow.drop)                      -- "leather"
print(cow.hostile)                   -- false
print(cow.registry_name)             -- "Cow", this version's own spelling
print(cow.mob)                    -- true: a cow is a mob

for name, kind in game.entities do   -- every mob kind this version has, in its own order
    if kind.hostile then print(name) end
end

local arrow = game.entities.arrow    -- a kind that is not a mob has a row too
print(arrow.mob)                  -- false
print(arrow.width, arrow.height, arrow.physics)

game.entities.names()                    -- every kind: the pack's own and the game's, mob or not
game.entities.names { mob = true }    -- the mob kinds only
game.entities.names { mob = false }   -- the kinds that are not mobs
```

- Use `for name, kind in game.entities do`, not `pairs(game.entities)`.
- A game kind that is not a mob (an arrow, a boat, primed TNT) has the facts
  `name`, `mob` (`false`), `width`, `height` and `physics` (`"item"`,
  `"falling"`, `"vehicle"` or `"none"`). Every other fact is `nil`. A write to
  `spawn`, `attacks` or `interact` is an error, and so is `:amend`: they are
  for mob kinds.
- Iteration and `game.entities.names()` cover all kinds, once each. Use
  `game.entities.names { mob = true }` or check `kind.mob` for mob settings.
- A pack kind (`rave:rocket`) reads as a definition handle, with `name` and
  `mob = false`. Pass it to `world.spawn` just like the handle from `define`.
- `define`, `amend` and `names` are functions on the same table (see "Custom
  entities"). `game.entities.cow:amend { ... }` is the same as
  `game.entities.amend("cow", { ... })`.

Everything above is read-only.

### Spawn rules — `true`, `false` and `nil`

`spawn` is the field of a mob kind that a pack writes. It says whether the
kind is in this world by itself.

On a `mode: lite` world, no mob spawns by itself. The pack switches
a kind on:

```lua
-- citadel.yml: mode: lite, game: "b1.7.3", world: overworld
game.entities.cow.spawn = true    -- cows are in this world, as the game has them
```

Cows now spawn by the game's own rule. No other kind spawns. A player's right
click on a cow with a bucket gives milk.

```lua
game.entities.cow.spawn = false   -- cows never spawn by themselves in this world
print(game.entities.cow.spawn)    -- false
game.entities.cow.spawn = nil     -- the pack says nothing: the world's default
print(game.entities.cow.spawn)    -- nil
```

| Value | Meaning |
|---|---|
| `true` | The kind is in this world as the game defines it. It spawns by the game's own rule, and it is the game's entity in full. |
| `false` | The kind never spawns by itself. |
| `nil` | The pack sets nothing. The world's default applies. |

- The world's default is off on a `mode: lite` world and in a room made by
  `rooms.create`: no mob spawns by itself. The default is on on a `mode: full`
  world and after `world.rules{ survival = true }`: each kind spawns by the
  game's own rule. `world.rules{ survival = false }` sets the default to off
  again.
- `true` makes the kind the game's entity in full, on a lite world too. It
  spawns by the game's own rule. Its hits hurt players and a player's right
  click on it has the game's effect. See "`attacks` and `interact`" below.
- A monster that comes to a sleeping player obeys the same value.
- `true` does not make a kind spawn where the game cannot spawn it. On 1.8.9
  the game takes the kinds it spawns from the biome. A world with no biomes (a world the
  scripts make) spawns nothing, and `true` is an error there.
- `false` stops natural spawning only. A spawner block, `world.spawn`,
  `/summon` and breeding still make the entity.
- Mobs already in the world stay.
- Reading gives what this pack set: `true`, `false` or `nil`. It does not
  give the game's own rule or the value of a different pack.
- Each pack has its own value. If one pack sets `false`, the kind does not
  spawn. If no pack sets `false` and one pack sets `true`, the kind is on.
- The value is for one room. `game` is the main room's table. A room from
  `rooms.create` has its own: `room.game.entities.cow.spawn = true`.
- On a script reload, the values of the last run stay until the new script
  has loaded. Then each value that the new script did not set is removed.
- On a game with no natural spawning, every write is an error, `nil` included.
  a0.1.0 to a0.1.3 are such games.
- An error is a plain string for `pcall`.

### `attacks` and `interact`

`attacks` and `interact` are two more fields of a mob kind that a pack writes. Each is `true`,
`false` or `nil`. A different value is an error.

```lua
game.entities.zombie.attacks = false  -- a zombie's hit does not hurt a player
game.entities.cow.interact = false         -- a right click on a cow does nothing
game.entities.zombie.attacks = nil    -- the pack says nothing
```

| Field | `true` | `false` |
|---|---|---|
| `attacks` | The entity's hits hurt players. | The entity's hits do not hurt players. |
| `interact` | A player's right click on the entity has the game's effect (milk from a cow, a saddle on a pig). | The right click has no effect. |

With `nil`, the engine uses the first line that applies:

1. The kind has `spawn = true`: the field is on.
2. The room's rule: `damage` for `attacks`, `survival` for `interact`.

- **The kind's own setting is stronger than the room's rule.** Thus
  `game.entities.zombie.spawn = true` makes a zombie's hit hurt in a room with
  `world.rules{ damage = false }`. To keep the zombie harmless there, set
  `game.entities.zombie.attacks = false`.
- A zombie from `world.spawn` on a lite world does not hurt players until
  the pack sets `spawn = true` or `attacks = true` for zombies, or the room
  has the `damage` rule.
- `interact` changes the item in the player's hand as the game does: an empty
  bucket becomes a bucket of milk.
- `interact` is not available on 1.8.9: that game version has no right click on a
  mob in Citadel. `interact = true` is an error there, and `spawn = true` does not
  give the right click.
- `attacks` covers the entity's own hit, its arrow and its blast. An arrow
  keeps the kind of its shooter, so the arrow of a dead skeleton follows
  `game.entities.skeleton.attacks`. The blast of a creeper follows
  `game.entities.creeper.attacks`.
- `attacks = false` stops the damage to players only. The blast of a creeper
  still breaks blocks, as the game says, and still hurts other entities.
- A blast of TNT, of a bed and of `world.explode` has no kind. It follows the
  room's `damage` rule.
- The fields are for one room and one pack, as `spawn` is. If one pack sets
  `false`, the field is off.

To put mobs in a world, use `world.spawn(name, pos)` (see "Mobs and
drops"), `/summon`, or a dungeon spawner the terrain placed.

> **a0.1.0 spawns nothing on its own.** Only its dungeon spawner makes mobs.

### Terrain

`game.terrain` describes this world's overworld: `snow`, and `steps` in the
shape `citadel.yml` uses. It is read-only, and `nil` where the engine has no
list.

```lua
for i, step in ipairs(game.terrain.steps) do
  print(i, step.step, step.block, step.count)   -- 1 dungeons nil 8
end
print(game.terrain.snow)                        -- false
```

## Building well

The plan and the build order make a build look handmade, not the API.

**Plan before code.** Write the plan as a comment at the top of the build:

1. What makes it recognisable at a glance? A keep is tall, square and
   crowned; a market is low and crowded.
2. Its parts, each with bounds, material and joins: footing, body, openings,
   roof, trim, props.
3. Its setting: neighbours, ground, and the way a player approaches.
4. Where detail goes: the skyline, doors, windows, corners, the roof line,
   places a player stops.

**Build in that order, and look at each stage before the next.** End each
stage with a render and a check. Name the parts as you go (`b:part`), so
renders and the check can name them.

| stage | what is built | look with | ask |
|---|---|---|---|
| 1. massing | the footprint, the main volumes, the roof shapes | `--view sides,roof` | Does the outline say what it is? Are the proportions right: towers tall enough, roof steep enough, wings in scale? |
| 2. architecture | openings, wall depth, eaves, how parts join | `--view approach,entrance,plan` and `citadel check` | Are windows holes with sills and frames? Does the way in read? Can a player walk to every floor? |
| 3. setting and detail | paths, ground, lighting, props, trim | `--view approach,cutaway` and `citadel check` | Does it sit in a place? Is the detail where the eye goes? |

At each stage:

- Write down the three worst problems the pictures and the check show.
- Fix those, then look again with the same views.
- Finish every fix before the next stage.
- Render again only after a change or for a new question.

**The four ways a build fails:**

- *Painted flat.* A window keeps its glass in the wall's plane, with a sill
  and a frame that stand out in front of it; glass pushed behind a wall one
  block thick sits inside the room. Give walls depth: plinths, beams, cornices.
- *Visible boxes.* Taper what grows: a tower narrows, a roof flares at its
  eaves. Break long edges. Let parts overlap and sink into each other.
- *No setting.* Add a path, a fence, a tree, a barrel, a lamp, and shape the
  ground to meet them.
- *Detail everywhere, or nowhere.* Put detail where the eye goes.

**Half blocks are the detail.** Use `detail = 2` for shapes finer than a
block: roofs, eaves, sills, steps, cornices, arches. The build turns half
steps into stairs and slabs. Name `oak_fence` or `glass_pane` and the build
joins them.

**Conventions that keep a build square.**

- An axis of symmetry runs through a block's middle, so a symmetric thing is
  odd: a door 1 or 3 wide, a gate 5, a path 3.
  `build:mirror("x")` of one half gives the other.
- A block is inside a circle when `math.sqrt(dx * dx + dz * dz) <= r + 0.5`.
  The `+ 0.5` gives flat edges.
- Mix a large surface from two or three blocks of one family, chosen by a
  hash of the position. A restart then builds the same wall.
- Write a part once, round its own middle. Place it with `build:rotate` and
  `build:mirror`.

```lua
-- Helpers a pack writes for itself; nothing here is the engine's.
local function hash(x, y, z)                         -- 0..1, the same every time
    local v = math.sin(x * 12.9898 + y * 4.1414 + z * 78.233) * 43758.5453
    return v - math.floor(v)
end
local function mix(x, y, z, blocks)                  -- { "stone_bricks", "stone_bricks", "cracked_stone_bricks" }
    return blocks[math.floor(hash(x, y, z) * #blocks) + 1]
end
local function disc(b, at, r, block)                 -- 2r + 1 across, round the block `at`
    for dx = -r, r do
        for dz = -r, r do
            if math.sqrt(dx * dx + dz * dz) <= r + 0.5 then
                b:block(at + vec3(dx, 0, dz), block)
            end
        end
    end
end
local function cone(b, at, r, height, block)         -- a tower roof, widest at `at`
    for y = 0, height do
        local rr = r * (1 - y / (height + 1))
        for dx = -r, r do
            for dz = -r, r do
                if math.sqrt(dx * dx + dz * dz) <= rr + 0.5 then
                    b:block(at + vec3(dx, y, dz), block)
                end
            end
        end
    end
end
```

**Look at it, and say what you saw.** Only `citadel render` and `citadel
check` (see "seeing what you built" and "checking what you built") prove a
build good.

- Judge only pictures taken after the last edit.
- Fix every `fix` from `citadel check`, or say it is deliberate. Weigh
  advice against the build's purpose, and say what you chose.
- After an edit to one part, run `citadel check --since` to show the other
  parts did not change.
- The pictures are flat colour. Report textures as unchecked.
- Report what you looked at, what you fixed, and what is left.

# Players

Who is here, how they move and see, what they type and click, and what they may do.

## Players

Join and leave, messages, health, inventory, and who sees whom.

```lua
players.on_join(function(player) end) -> connection
players.on_leave(function(player) end) -> connection   -- the same player value; it can no longer be sent to
players.list()        -- array of player
players.get(name)     -- player or nil
players.count()

-- player
player.name           -- string
player.uuid           -- the account's own id, as a string
player.at             -- vec3, where they stand now
player.data           -- a table of your own, kept until 10 seconds after they leave
player.gamemode       -- 0 survival, 1 creative, 2 adventure, 3 spectator; set it to change it
player.ui.title{ title = "RAVE", subtitle = "", color = "white", fade_in = 0.25, stay = 2, fade_out = 0.5 }   -- text; seconds
player:message(text, color)   -- text; color is for the words that did not pick one
player:sound(name, { at = player.at, volume = 1, pitch = 1, category = "record" })
player:teleport(pos, { yaw = 0, pitch = 0 })   -- a rotation; an angle left out keeps the way they face
player:move_to(room)   -- see rooms; `player.room` is the Room the player is in
player:give("stone_pickaxe")      -- one; canonical item name; errors on a name this game version lacks
player:give{ item = "arrow", count = 16 }
player:held()          -- { item = "cobblestone", count = 3 } in hand, or nil; a pack item adds `id`, a worn tool `damage`
player:inventory()     -- { { item = "cobblestone", count = 3 }, ... }, one entry per filled slot, the same rows
player:count("iron_ingot")  -- how many of one item, across every slot; see "items of your own" for what matches
player:take("coal", 8)      -- takes up to 8, the hand first; answers how many it took
player:set_held(item)       -- the stack in hand, replaced; nil or false empties the hand
player:supports("light")  -- can this player's client show it? see "Client versions"
player.visible = false    -- nobody else sees this player; true or nil shows them again; see "who sees whom"
player:hide(other)        -- this player stops seeing `other`; player:show(other) undoes it
player:can_see(other)     -- true unless `other` is not visible or is hidden from this player

-- survival: nil on a game version that has no such rule
player.health          -- their health now, 0 to player.max_health; nil where the version has no damage rules
player.max_health      -- the most health they can have: 20 unless a pack set it; nil for the same reason
player.food            -- 0..20, or nil where the version has no food bar
player.saturation      -- number, or nil for the same reason
player.dead            -- true while they are on the death screen
player:kill()          -- true if it happened; false on a version with no damage rules
player.health = 12     -- set outright, no flash; 0 is a death. See "Body and movement"
player.max_health = 40 -- 20 hearts; nil gives the game's own (20) back. See "health, food and `nil`"
player:damage(4)       -- a hit: two hearts, the flash, the sound, the resistance window

players.on_death(function(player, cause, message, by) end) -> connection   -- by: the player who did it, or nil
players.on_respawn(function(player) end) -> connection
```

`player:give`, `player:take`, `player:inventory` and `player:count` work on
inventory stacks.

- A given stack merges into existing stacks, hotbar first.
- What does not fit is dropped from the give, not duplicated.
- Clicks in the player's own window work as in the game, all seven click
  modes included.
- A pack's own menu over the inventory is `player.ui.menu{}` (see "Menus").
- A chest's stacks are `world.container` (see "containers").

### who sees whom

A player sees others in their room who are in view. Two settings remove a
player's body from a client:

```lua
player.visible = false        -- from everyone; true or nil brings it back
viewer:hide(player)           -- from this viewer only; viewer:show(player) undoes it
viewer:can_see(player)        -- what the two add up to

-- a lobby where nobody sees anyone
room.players.on_join(function(p) p.visible = false end)
room.players.on_leave(function(p) p.visible = true end)

-- teams: each side sees only its own
for _, a in players.list() do
    for _, b in players.list() do
        if a.data.team ~= b.data.team then a:hide(b) else a:show(b) end
    end
end
```

- A hidden player is gone from that client: no body, name, armour or hitbox.
  The `invisibility` effect differs: it shows armour and the held item.
- The tab list still shows hidden players.
- Both settings last across rooms.
- `hide` is by account, so it lasts when the other player rejoins.
- A new session resets both: nothing hidden, and `visible` is true.

### health, food and `nil`

`player.health`, `player.max_health`, `player.food` and `player.saturation`
are `nil`, not `0`, on a game version with no rule for them. Every Alpha node
is one (a0.1.0 has no food and no damage). Across the engine, what a version
lacks is absent, not zero.

`health` is always the health of one individual now. `max_health` is always
the most it can be. This is the same for a player, for an entity in the world
and for a kind (a kind has `max_health` only).

- `player.max_health = n` takes 1 to 1024. `nil` gives the game's own (20)
  back. Another type or a number out of range is an error. It is an error on
  a version with no damage rules.
- A lower maximum takes `player.health` down to it. A higher maximum does not
  heal.
- `player.health = n` with `n` above the maximum gives the maximum. Food,
  regeneration and peaceful healing stop at the maximum. A respawn fills to
  it.
- Every Java client (1.7 to 26.3) draws the hearts of the maximum. A Bedrock
  client draws no health today.
- The maximum lasts for the session, also across rooms and deaths. Set it in
  `players.on_join`.

`cause` in `players.on_death` is one of `fall`, `drown`, `suffocate`, `void`,
`lava`, `fire`, `cactus`, `starve`, `attack` (a mob's or a player's hit),
`shot` (an arrow), `blast`, `magic` and `other` (a pack's own
`player:damage`). `message` is the broadcast English death line. `by` is the
player who hit or shot them, or `nil`.

**A player is one value while connected.** Every event passes the same
`player`:

- `a == b` compares players, and a player can be a table key.
- `player.data` holds your own state. You need no table keyed by name.
- In `players.on_leave`, `player.name` and `player.data` still read. `data`
  is kept for 10 seconds after they leave; after that a value you still hold
  reads an empty table.
- `data` may name the player (`p.data.state = { player = p }`, a function
  that uses `p`); it is let go with them all the same.
- A player who rejoins is a new value with empty `data`.

```lua
players.on_join(function(p) p.data.coins = 0 end)
players.on_leave(function(p) storage.set("coins." .. p.uuid, p.data.coins) end)
```

## Body and movement

Fields read back the last value set, and the client gets the change at
once. Nothing here needs `player:supports`: a client too old for a feature is
left alone.

```lua
player.speed = 2           -- walk speed as a multiple of normal; 0 pins them, 1 is normal
player.can_fly = true      -- may fly in a mode that cannot (adventure, survival); false takes it back
player.scale = 0.5         -- half size, 1/16 to 16; needs 1.20.5, older clients stay as they are
player.reach = 64          -- how far a block can be clicked or dug, 0..64 (4.5 is vanilla); needs 1.20.5
player.level = 7           -- the number over the experience bar
player.xp = 0.5            -- how full the bar is, 0..1

player:effect("speed", { level = 2, duration = 30, particles = false })
--   a potion effect by its modern name: speed, slowness, haste, jump_boost, regeneration,
--   resistance, fire_resistance, water_breathing, invisibility, blindness, night_vision,
--   glowing (1.9), levitation (1.9), slow_falling (1.13), darkness (1.19), ... ; `level` from 1,
--   `duration` in seconds (30 by default; math.huge is for ever). A client too old for the
--   effect is not sent it; a name no version has is an error naming them all.
player:clear_effect("speed")

player:push(vec3(0, 1, 0))     -- a shove, in blocks per tick, on top of what they are doing
player:damage(4)               -- two hearts, with the flash and the sound; "<name> died" if it was the last
player.health = 20             -- set outright, no flash; 0 is a death; above player.max_health it stops there
player:look_at(pos)            -- turn their head to a point, where they stand
player.camera = cam            -- look out of a camera (see cameras); nil or false is their own eyes
player.time = "midnight"       -- this player's sky alone, held there (ticks or a world.time name);
                               --   nil or false gives them the room's again, as does moving rooms
player:stop_sound("rave.kick") -- one sound by name, or every sound with no name (1.13 and later)
player:kick("Server full")     -- disconnect them, with that text on their screen
player:connect("hub")          -- ask Minefort to move them to another server, by its name
```

- `player:connect(server)` asks Minefort's proxy to move the player: a BungeeCord `Connect` for a Java player, a `Transfer` to that name for a Bedrock player. It returns nothing and does not yield.
  - `server` is a server name: the `id` of an instance (see Network), the name of the network, or `hub`.
  - The name of the network sends the player to its default member. `network.info().network` is that name. `hub` is Minefort's hub.
  - The name is 1 to 128 characters of letters, digits, `.`, `_` and `-`. Any other name is an error, and nothing is sent.
  - Minefort decides. It does not move a player to a server out of the network, and it does not tell the pack.
  - The call does not tell the pack the result. A player who is still here some seconds later was not moved.
  - It moves a Bedrock player, and a Java player on 1.7 or later. A Java player on an older version stays.
  - On a local run there is no proxy. A Java player stays. A Bedrock client reads the name as an address, and leaves the server.

- On a pack server, only `damage` and `health` hurt a player. Creative and
  spectator players take no damage.
- At zero health the player dies. `players.on_death` fires with cause
  `"other"`, and the client shows the respawn screen.
- On a pack server a death drops and clears nothing. The hotbar is a menu,
  not an inventory.

## Cameras

A camera takes over what a player sees: a fixed shot, free look, an orbit, or an intro that eases from shot to shot.

A camera is a value you put on a player. There are four kinds, and `camera.path` (below) eases from shot to shot:

```lua
local cut = camera.fixed{ at = vec3(0, 80, 30), look_at = vec3(0, 64, 0) }  -- no mouse; look_at = player works too
local window = camera.fixed{ from = car_cam }            -- look out of a display, an npc, an entity
local look = camera.free{ at = vec3(0, 70, 0) }           -- the mouse looks around from `at`
local orbit = camera.orbit{ follow = car, distance = 6, height = 1.6 }  -- the mouse circles `follow`
local chase = camera.chase{ follow = car, distance = 5, height = 3, pitch = 12 }  -- behind and above `follow`, turning with it; no mouse

player.camera = orbit
tween(cut, { at = vec3(0, 70, -10) }, { duration = 4, easing = "in_out" })  -- its fields tween
player.camera = nil                                       -- their own eyes again
```

- `cam.look_at = nil` removes the point or thing a camera looks at. `false`
  does the same. Reading `look_at` returns the point or target handle; reading
  `follow` returns the followed handle. A removed target reads `nil`.
- Each mode exposes only its relevant fields. `fixed{ from = target }` exposes
  `from`; `fixed{ at = point }` exposes `at` and `look_at`; `free` exposes `at`;
  `orbit` and `chase` expose `follow`, `distance` and `height`, and `chase` adds
  `pitch`. `mode` and `from` are read-only. Ineffective fields are errors.
- `fixed` takes either `from` or `at` with optional `look_at`. Combining them
  is an error. Distances must be finite and nonnegative, and angles/heights finite.
- **fixed** works in every mode. A player or thing as `look_at` (a model
  too) is followed by its head. The player still walks and sees their own body: set
  `player.speed = 0` for a cutscene. Do not use `gamemode = 3`.
- **free** and **orbit** seat the player, hidden and locked, on an engine seat. `orbit`
  puts the eyes `distance` blocks behind `follow` (anything with an id),
  `height` over its feet, opposite the look direction, and in front of walls.
  Both need 1.19.4 (`player:supports("display")`). `free` means mouse look
  from a point, not free flight. Because these modes need the player's seat,
  assigning either while riding is an error. The previous ride and camera
  remain intact. Use `chase` while riding, or dismount before assigning one.
  Likewise, `player:ride` while a free/orbit camera is active is an error;
  clear `player.camera` or switch to `chase` first.
- **chase** is the view from behind a car. The engine keeps the eyes
  `distance` blocks behind `follow` (a model, a vehicle, an npc, a player),
  `height` over it, looking the way it heads and `pitch` degrees down, and in
  front of walls. It moves with `follow` in the same step, so `follow` does
  not shake in the view. **Use this to follow a thing a pack moves. Do not
  move a display of your own behind it and look out of that**: the two are
  sent as two things and drift against each other. A barrier does not pull
  it in. 1.19.4 and later.
- A chase camera is aimed as its `follow` is. Submit the target's current
  position; the engine keeps its picture, seats and camera moving together.
  Custom physics needs no future-position simulation or client timing constants.
- Chase and orbit move as their `follow` moves, with its `glide` and
  `lead`. Smooth movement needs Java 1.20.2 or later.
- For the driver's own eyes, seat them: `player:ride(car, { locked = true })`
  and `player.camera = nil`. A chase camera and a seat go together: the body
  is in the car and the view is behind it.
- `player.eye` is where a player's view is from, as a vec3: the camera they
  look out of, or their own eyes.
- One camera can be on many players. A change (`cam.at`, `cam.distance`,
  `cam.follow = other`) shows on all of them next tick.
- Ending the camera, or leaving the room, gives back body, feet and eyes.
- Free/orbit cameras hide the body independently of potion effects. Ending
  one preserves those effects and any ride assigned after the camera's seat.
- Destroying a camera's source or follow/look-at target ends the camera
  automatically. A remote camera keeps terrain loaded around both the view
  and the player's body, including when looking out of another player.
- Creating a target and assigning its camera in the same callback needs no
  delay. The engine spawns the target before selecting it and switches to a
  replacement camera before removing the previous one.
- A server cannot set the field of view, force third person or hide the
  hotbar.

`camera.path` is a fixed camera that eases from shot to shot. Each shot
after the first takes its own `duration`, or the path's (5 seconds by
default). It returns the camera and a handle with `cancel()`.

```lua
local cam, run = camera.path({
    { at = vec3(0, 80, 30), look_at = vec3(0, 64, 0) },
    { at = vec3(40, 70, -10), look_at = vec3(0, 64, 0), duration = 5 },
    { at = vec3(10, 66, -20), look_at = vec3(0, 65, 0), duration = 3, easing = "out" },
}, { easing = "in_out", on_done = function() player.camera = nil player.speed = 1 end })
player.speed = 0
player.camera = cam
```

A shot `{ at = player }` is the player's eyes, looking where they look. A
player or thing in a shot is read when the shot starts:

```lua
camera.path({
    { at = vec3(0, 90, 60), look_at = vec3(0, 64, 0) },     -- over the map
    { at = vec3(4, 67, 4), look_at = player, duration = 4 }, -- down to them, standing there
    { at = player, duration = 2 },                           -- into their eyes
}, { on_done = function() player.camera = nil player.speed = 1 end })
```

- End on `{ at = player }` so removing the camera does not jump.
- To hold a shot, repeat it.
- A camera moves 20 times a second. From 1.20.2 the client glides between
  moves.

## Input

Input events are per room, like `players.on_join`.

```lua
players.on_click(function(player, hit) end) -> connection
--   hit.button = "left" | "right"      left is attack / swing, right is interact / use
--   hit.entity = display | hitbox | npc | puppet | nil   the thing itself, so `hit.entity == dealer` works
--   hit.entity_id = number?            its raw id; all there is for a screen's own frames,
--                                      and for anything the script no longer keeps a handle to
--   hit.player = player?               another player, when that is what was clicked: a hit in a game
--   hit.block  = vec3?                 the block, when the click hit one
--   hit.face   = "up" | "down" | "north" | "south" | "west" | "east" | nil
players.on_sneak(function(player, down) end) -> connection    -- once per press and release
players.on_slot(function(player, slot) end) -> connection     -- hotbar 1..9
players.on_chat(function(player, text) end) -> connection     -- return false and the line is not said
player.rotation            -- { yaw, pitch } in degrees, live; read only
player.sneaking            -- boolean, live
player.input               -- { forward, sideways, jump, sneak, sprint, attack }: the keys held right now
--   attack is the left button held on a block in reach: a client reports a held left button only
--   while it digs, so it is false on air, and an adventure client never digs. A held left button
--   on anything is: survival, `player.reach` long enough for the crosshair to land, and
--   `player:effect("mining_fatigue", { level = 5 })` so no block cracks
--   forward is 1, 0 or -1 (W and S); sideways is 1 for left, -1 for right (A and D); the rest are booleans
player:ride(thing) -> boolean   -- sit on a display, a model, a hitbox or an npc, and go where it goes;
--                                 false when somebody sits in that seat of a model
player:dismount()          -- get off; sneaking does the same, as off a horse
player.riding              -- boolean, live
player:look() -> vec3      -- unit vector the player faces
player:set_slot(n)         -- selects hotbar slot 1..9
```

- One click is one event.
- A held button repeats every 200 ms. That is not a click.
- A left click on the world carries the block under the crosshair, up to
  five blocks from the eyes.
- On a pack server, a click never changes the world.

The first `players.on_chat` takes over chat in its room. Each line is then
said once as `<name> text`, unless a listener returns `false`. With several
packs, each gets every line; it is still said once or not at all.

## Commands

The client shows, completes and checks each argument of the usage as the
player types. The function runs only when the
arguments fit. Otherwise the player gets the reason and the usage in red.

```lua
commands.add(usage, function(player, args) end, opts?) -> command
--   opts = { permission = "casino.play", aliases = { "hub" }, help = "Set your bet",
--            suggest = { place = { "roulette", "arcade" }, item = function(player, typed, args) return { ... } end } }
command:suggest(arg, words)   -- a list, a function, or nil or false for nothing: what `arg` offers from now on
command:cancel()              -- takes the command away
commands.run(player, line) -> boolean   -- runs a pack's command for player, as if they typed it

commands.add("bet <amount:integer 1..10000> [color:red|black]", function(player, args)
    bank.bet(player, args.amount, args.color or "red")   -- args.amount is a number
end, { permission = "casino.play", help = "Bet on the wheel" })

commands.add("spawn", function(player) player:teleport(SPAWN) end, { aliases = { "hub" } })
commands.add("tekkit give <item:word> [count:integer 1..64]", give, {
    permission = "tekkit.give",
    suggest = { item = function(player, typed) return item_names() end },
})

-- A tooltip shows beside a suggestion; `args` holds what was typed before.
commands.add("pay <to:player> <amount:integer 1..>", pay, {
    suggest = { amount = function(player, typed, args)
        return { { text = tostring(bank.of(player)), tooltip = "Everything you have" }, "10", "100" }
    end },
})

-- The handle changes a list while the pack runs.
local go = commands.add("go <place:word>", go_to, { suggest = { place = { "lobby" } } })
go:suggest("place", open_places())
```

A usage is the name, any fixed words, then the arguments. `<name:type>` is
required and `[name:type]` is optional. A required argument never follows an
optional one. The types:

| type | the player types | `args.name` is |
|---|---|---|
| `word` | one word | a string |
| `integer`, `integer 1..64` | a whole number, in the range if there is one | a number |
| `number`, `number 0..1` | any number, in the range if there is one | a number |
| `player` | the name of someone in this room | that player |
| `red\|black` | one of the listed words | the word, in lower case |
| `text...` | the rest of the line | a string |
| `words...` | the rest of the line | a list of words |

A range may leave out either end: `integer 1..` or `integer ..64`.
`text...` and `words...` come last. An optional argument not typed is `nil`.

- **The function** may `task.wait`. A returned string shows to the player in red, such as
  `return "Finish this match first"`.
- **`permission`**: without the node, a player does not see or run the
  command.
- **One name, several shapes.** Calls with one name, such as `"tekkit"` and
  `"tekkit give <item:word>"`, make one command. Each shape has its own
  permission. The first shape the line fits runs.
- **`suggest`**, per argument: a list of words, or a function
  `(player, typed, args)` that returns one. `args` holds the earlier
  arguments that parse. It runs as the player types: no `task.wait`. A word may be `{ text = "arcade", tooltip = "Games" }`; 1.13+
  clients show the tooltip. Only words that start with the typed text are
  kept. `player` arguments and word lists (`red|black`) suggest themselves.
- **The command** handle: `command:suggest` sends the new list to every
  player.
- **`help`** is the text `/help` shows after the usage. The engine's `/help`
  lists every command the player may run.
- **One pack owns a name** in a room. A second pack that adds the name or an
  alias of it gets an error. `/help` and `/world` belong to the engine. A
  pack command replaces a game command of the same name.
- **Per room**: `commands` is the main room's, `room.commands` another
  room's. Destroying a room removes its commands.
- **`commands.run`** runs a line for a player as if they typed it, so one
  pack opens what another declared: a compass runs `"/servers"`, whichever
  pack owns it. The player's own permissions apply. Only a command a pack
  declared in the player's room runs; `false` means none did, and the
  engine's and the game's commands are never run this way.

## Permissions

A permission is a dotted node: `casino.admin`, or the engine's `minecraft.command.gamemode`, `minecraft.command.summon` and
`citadel.build` (build mode; see "Named parts").

- `casino.*` covers everything under `casino`. `*` covers everything.
- A leading `-` takes a node away.
- The most specific node wins. Between two equally specific nodes, the `-`
  wins.

The pack's `citadel.yml` defines groups. Every player is in `default`.

```yaml
permissions:
  default: { nodes: [casino.play] }
  vip:     { inherits: [default], nodes: [casino.vip] }
  staff:   { inherits: [vip], nodes: [minecraft.command.gamemode, "casino.*", "-casino.debug"] }
```

The script puts players in groups:

```lua
player:add_group("vip")          -- errors on a group citadel.yml does not define
player:remove_group("vip")
player:groups()                  -- { "vip" }; `default` is not listed
player:has("casino.vip")         -- true
```

- Groups last until the player leaves. Store them and re-add them in
  `players.on_join`.
- Server operators (`operators:` in the server's `citadel.yml`) have every
  node.
- Gate your own commands with `player:has`.
- Same-name groups in two packs merge.
- The server stops on a group that inherits an undefined group, or on a
  group named `operator`.

## Client versions

Citadel serves Java clients 1.8 to 26.2. A script never reads a version
number. It asks:

```lua
if player:supports("display") then
    world.display{ kind = "text", text = "Bet 50", at = pad }
else
    board:text(8, 8, "Bet 50", colors.white, 24)   -- a screen works from 1.8
end
```

| feature | what needs it | from |
|---|---|---|
| `bossbar` | `ui.bossbar`, `player.ui.bossbar` | 1.9 |
| `potion_color` | an item's `color` | 1.11 |
| `floor_frame` | a screen or frame with `facing = "up"` | 1.13 |
| `light` | `world.light` | 1.14 |
| `hex_color` | a colour outside Minecraft's sixteen names | 1.16 |
| `glow_frame` | `glow = true` on a screen | 1.17 |
| `display` | `world.display`, any kind | 1.19.4 |
| `hitbox` | `world.hitbox` | 1.19.4 |
| `model` | `world.display{ kind = "model" }` | 1.21.4 |
| `layout` | `player.ui.show` | 1.21.4 |
| `dialog` | `player.ui.dialog` | 1.21.6 |
| `overlay` | `player.ui.overlay` | 26.3 only |
| `resource_pack` | the pack's textures, models and sounds | a client that did not turn the pack down |

- A name not in this table is an error.
- A client that turns the resource pack down answers false to
  `resource_pack`, `model`, `layout`, `dialog` and `overlay`, from the
  moment it answers. It is sent no layout and no dialog: they are drawn in
  the pack's fonts. An open dialog closes.
- A Bedrock client answers false to every feature in this table.
- Unguarded calls are safe: a client that cannot show a feature is not
  sent it. Guard only to show something else.
- Or set `min_client` in `citadel.yml` to refuse old clients.

# Interface

What a player reads: titles, bars, the HUD, menus, and pictures on walls.

Everything on the screen is under `ui`, at three levels with the same calls:

| call | who sees it |
|---|---|
| `ui.actionbar(...)` | everyone in the main room (`ui` is `rooms.main.ui`) |
| `room.ui.actionbar(...)` | everyone in that room |
| `player.ui.actionbar(...)` | that player alone |

`title`, `actionbar`, `bossbar`, `sidebar` and `tab` work at all three.
`menu`, `overlay` and `show` (see "Layouts") are on `player.ui` only.

Chat is not part of the screen, so it is not in `ui`. A chat line to one
player is `player:message(text, color)`; `room:message(text, color)` sends
one to everyone in that room, and `message(text, color)` to everyone in the
main room.

## Titles and bars

Chat lines, titles, the action bar and boss bars, for one player or for everyone.

```lua
ui.title{ title = "DROP", subtitle = "hands up", color = "red", fade_in = 0.1, stay = 0.7, fade_out = 0.4 }   -- seconds
message(text, color)                 -- chat line to everyone in the main room; text, see "Text formatting"
ui.actionbar(text, color)            -- the line above the hotbar, to everyone
```

## HUD

A layer drawn over the player's own screen: text, bars and a canvas.

```lua
player.ui.actionbar("Bet 50 · Chips 1200", "light_purple")   -- the line above the hotbar

local bar = ui.bossbar{ title = "Race starts in 30 s", color = "purple", progress = 1 }
bar.title, bar.progress, bar.color, bar.visible   -- live; progress 0..1
bar.visible = false   -- off every screen; true or nil shows it again
--   a bar's colour is its own closed set: pink, blue, red, green, yellow,
--   purple, white. It is not a colour value and has no hex form; anything
--   else is white. While a layout hangs from the top (see "Layouts"), pink
--   is the engine's, and a pink bar is an error.
bar:destroy()
local mine = player.ui.bossbar{ title = "Your horse: Lightning" }   -- one player's bar, the same handle

ui.sidebar{ title = "INDIGO", lines = { "Chips  1200", "Bet  50", "", "Roulette" } }   -- everyone in the room
player.ui.sidebar{ title = "INDIGO", lines = { ... } }   -- one player; lines run top to bottom
ui.sidebar(false)   -- removes the sidebar, as nil does; player.ui.sidebar(false) for one player
ui.tab{ header = "INDIGO", footer = "minefort.com" }
--   every title, line, header and footer here is text: { "Chips ", { "1200", color = "gold" } }
```

- A boss bar re-sends on every change. A late joiner sees it at the next
  change.
- 1.8 has no boss bars. A 1.8 client shows the title on its action bar.
- The sidebar sends only changed lines. Repeated lines are fine. Long or
  extra lines are trimmed.

### a canvas on the screen

`player.ui.overlay` puts a 128×128 canvas in a corner of one player's
screen. It draws like a canvas. Only that player sees it.

```lua
local map = player.ui.overlay{ corner = "top_right", size = 96, margin = 4 }   -- nil where player:supports("overlay") is false
if map then
    map:clear()                                  -- see-through: the game shows through
    map:rect(0, 1, 128, 127, "#101820", 10)      -- rows 1..127; row 0 is the engine's and never shows
    map:text(8, 6, "MAP", colors.white, 12)
    map.open                                     -- false after destroy or when the player leaves
    map:destroy()
end
```

- `corner` is `top_left`, `top_right`, `bottom_left` or `bottom_right`.
  `size` is screen pixels a side at GUI scale 1 (16 to 511). `margin` is
  the gap to the edges (0 to 63). The client's automatic GUI scale
  multiplies both.
- It stays over room moves and respawns. It goes when the player leaves.
- Changed pixels go to that player once per tick.
- Only 26.3 draws it, with the engine's shader in the resource pack. A pack
  that names `player.ui.overlay` makes the pack required for 26.3. A player who
  declines it is disconnected with a how-to message.
- Several at once are fine: each is its own canvas.
- Shader mods (Iris, OptiFine) replace the shader. There the HUD does not
  show.

## Layouts

A layout is a HUD made of boxes, pictures and labels: a health bar, a level
badge, a frame round the hotbar. Define it while the pack loads, then show it
to a player and change its values.

```lua
local STATUS = ui.define("status", { anchor = "bottom", margin = 42,
    ui.row{ gap = 6, align = "end",
        ui.column{ gap = 1,
            ui.label{ id = "hp_text", text = "20 / 20", width = 82 },
            ui.stack{
                ui.box{ width = 82, height = 9, color = "#1c1410", radius = 2 },   -- the frame
                ui.box{ id = "hp", width = 80, height = 7, color = "red", radius = 1 },
            },
        },
        ui.label{ id = "level", text = "1", color = "gold" },
    },
})

players.on_join(function(player)
    local hud = player.ui.show(STATUS)
    hud:set{ hp = 0.7, hp_text = "14 / 20", level = "22" }
    hud.hp.color = "orange"                          -- every value is a live field too
    tween(hud.hp, { fill = 0 }, { duration = 2 })
    player.data.hud = hud                            -- hud:destroy() takes it off the screen
end)
```

**The tree.** Three things to show, three ways to place them:

| call | what it is | options |
|---|---|---|
| `ui.box{}` | a plain shape | `width`, `height` (1 to 256; 2048 with no `id` and no `radius`), `color`, `radius` |
| `ui.image{}` | a picture | `image` (a `game.texture`), `color` (a tint) |
| `ui.label{}` | words | `text`, `color`, `width`, `align`, `bold` (each letter a pixel wider) |
| `ui.row{}` | its children side by side | `gap`, `align`, then the children |
| `ui.column{}` | its children under each other | `gap`, `align`, then the children |
| `ui.stack{}` | its children over each other, the last on top | `align`, then the children |

- There are no coordinates. Rows, columns and stacks place everything.
  `gap` is the pixels between two children. `align` is `"start"`,
  `"center"` (the default) or `"end"`, across the row or column.
- A pixel is one pixel of the game's own HUD: the hotbar is 182 wide and 22
  high.
- A bar is two boxes in a stack. The one with an `id` gets a fill.
- A label is as wide as its first words. Give a label whose words change a
  `width`: its place is fixed when the pack loads.
- `ui.define(name, { anchor, margin, child })` takes one child. A layout
  is centred across the screen. `anchor` is the edge it hangs from:
  - `"bottom"` (the default): its bottom edge is `margin` pixels above the
    screen's bottom. The default is 40, over the hearts, or 25, just over
    the hotbar, when `hide_hud` takes the hearts and the food away.
  - `"top"`: its top edge is `margin` pixels below the screen's top. The
    default is 4. It can reach down the whole screen.
- A plain box (no `id`, no `radius`) is up to 2048 a side: a backdrop
  that covers the whole screen at every GUI scale. The game shows through
  nowhere it covers. Make the backdrop its own layout (`margin = 0`) and
  show it first; then show the menu as a second top layout with its own
  `margin`. In one stack the menu would be centred on the backdrop, far
  below the bottom of a screen that is 270 pixels tall.
- A top layout is drawn over the crosshair, the hotbar and the hearts, and
  under the sidebar, the chat and every bottom layout: a bottom layout can
  sit on a top layout's backdrop.

**A cursor.** `cursor = true` in `ui.define` (a top layout only) puts a
pointer on it that the mouse moves, three pixels a degree, and stops at
the layout's edges. The view and the head stay still: while it shows, the
player sits on a seat of the engine's where they stood, and looks out of a
still view at their eyes. Destroying it gives back their feet and eyes.

```lua
local MENU = ui.define("menu", { anchor = "top", margin = 40, cursor = true,
    ui.column{ gap = 4, ui.box{ id = "solo", width = 120, height = 18, color = "#2a3550" },
                        ui.box{ id = "group", width = 120, height = 18, color = "#2a3550" } } })
local m = player.ui.show(MENU)
m.on_hover = function(id) end          -- the id under the pointer changed; nil is none
m.on_click = function(id, button) end  -- a click; id is what is under the pointer, or nil
m.hover                                -- the id under it now
m.cursor                               -- { x, y }: where it is, in the layout's pixels
```

- Only an item with an `id` is found under the pointer, the topmost one.
  Give the button's box the id, not its label: a label is only as tall as
  its letters.
- The view looks level, the way the player faced. A player who rides
  something or looks out of a camera keeps it: their view then turns with
  the mouse.
- The pointer moves as each turn the client sends arrives: 20 times a
  second, evenly.
- `players.on_click` still fires for the same click.

**The values.** An item with an `id` is live. `hud:set{}` takes a value per
id, and `hud.<id>` has the same values as fields:

| field | in `hud:set{}` | what it is |
|---|---|---|
| `fill` | a number | how much of a box or picture shows, from its left edge, 0 to 1 |
| `text` | a string | a label's words |
| `visible` | `true` or `false` | whether it shows; `hud.<id>.visible = nil` shows it again |
| `color` | (field only) | a box's colour, a picture's tint, a label's ink |

An unknown id is an error that lists the layout's ids.

**What is fixed.** A client gets the resource pack when it joins, and never
again. So the shape, size, picture and place of every item are fixed when
the pack loads, and `ui.define` in a callback is an error. Show different
layouts to different players; do not look for a way to change one.

- Only Java clients from 1.21.4 with the resource pack draw a layout
  (`player:supports("layout")`). On any other client, `player.ui.show`
  returns a handle that takes every call and shows nothing. Send that player
  `player.ui.actionbar` instead. A client that turns the pack down stops
  getting its layouts.
- A bottom layout uses the action bar. While one shows,
  `player.ui.actionbar` text is replaced by it within a second.
- A top layout uses a boss bar of the engine's. A pack's own boss bar made
  before it shows above it and moves it 19 pixels down; make pack bars
  after `player.ui.show`, or not at all on that screen.
- At the bottom a label starts at most 73 pixels up; at the top at least
  2 down. A label uses the letters from space to `~`. Any other letter
  shows as `?`.
- A layout holds 254 items. A live box or picture is at most 256 wide.

**The game's own HUD.** `hide_hud` in `citadel.yml` takes parts of it off
the screen, for the whole server and clients from 1.21.4:

```yaml
hide_hud: [hearts, food, armor, air, xp, hotbar, crosshair, dialog_warning, menu_blur, menu_background]   # any of these
resource_pack: required                            # or a player without the pack sees no hearts and no layout
```

`xp` hides the bar; the level's number stays. `hotbar` hides the frame; the
items stay. `menu_blur` and `menu_background` take the blur and the dark
shade from behind every screen opened in the world (a dialog, a chest, the
pause menu), for clients from 1.21.6: the world shows sharp round a
dialog, as round a panel of your own. `dialog_warning` hides the ⚠ that the client puts next to the
title of every dialog from this server: that sign tells a player the screen
is the server's, not the game's, so hide it only for screens no one could
mistake for the game's own.

**Look at it.** `citadel ui render` draws a layout with no client:

```sh
citadel ui render ./pack                 # every layout: its size and its ids
citadel ui render ./pack status --out hud.png --set hp=0.5 --set "hp_text=10 / 20" --scale 6
```

Boxes and pictures are exact. A label is drawn as blocks as wide as its
letters, because the letters are the client's own: report a label's words
as unchecked. `--words labels.json` leaves the labels out of the picture
and writes each one's words, place (`x`, `y` from the picture's corner),
`width`, `align` and `color` to the file, for a tool that has the
client's letters.

## Menus

A menu is a titled grid of up to 54 items. **A menu is not an inventory**: the player cannot take or put items. A click only picks an item.

```lua
commands.add("kit", function(player)
    local m = player.ui.menu{
        title = "Trains",
        items = {
            { item = "coal", name = "Steam locomotive", lore = { "right click a rail holding it" } },
            { item = "redstone", name = "High-speed electric" },
            "iron_ingot",                 -- a bare name works, as everywhere
        },
        on_pick = function(p, n)          -- n is the item picked, 1 up
            p:give(({ "coal", "redstone", "iron_ingot" })[n])
        end,
        on_close = function(p) end,       -- put away without picking
    }
    -- m:destroy() takes it down again; m:update(items) redraws it in place
end)
```

The rules:

- **Every client draws a menu.** Java (1.7 to 26.3) shows a chest. Bedrock shows a form with one button per item, labelled with `name` or the item's name. No `player:supports` check is needed.
- An item is an item (see "items") with `name`, `lore`, `color`, `dye`, `glint`, `skin` and `count`. The count shows on the stack, for a price or a quantity.
- `on_pick` may `task.wait`.
  - On Java the menu stays open. Destroy it in `on_pick` if one pick is enough.
  - A Bedrock form closes on the press. Open it again for another pick.
- `menu:destroy()` and a Bedrock pick do not fire `on_close`.
- `menu:update` returns `false` after the player closes the menu. Picks still answer by position. A Bedrock form keeps its first items.
- A new menu replaces the old one.
- Only the pack that opened a menu gets its picks. The menu ends when the script ends, the player leaves, or the pack calls `destroy`.
- Under a Java menu, the player's inventory shows. Clicks in it change nothing.

## Dialogs

A dialog is a screen of boxes, words and pictures over the player's view: a
server list, a shop, a page of rules. It needs Java 1.21.6 or newer
(`player:supports("dialog")`); on any other client `player.ui.dialog`
answers `nil`, so give those players a menu or chat instead.

```lua
local kit = ui.kit

local function servers(player)
    local tab = 1
    local d = player.ui.dialog(function()           -- a function: drawn again after every click
        return kit.window{
            title = "Servers", size = "screen", button = false,
            kit.tabs{ "Featured", "Popular", selected = tab, on_change = function(p, i) tab = i end },
            kit.grid{ columns = 3,
                kit.card{ image = "https://example.org/carball.png", title = "Carball", text = "by Melvin",
                    badges = { kit.badge{ "LIVE", color = kit.theme.live, dot = true } },
                    on_click = function(p) p:message("Joining Carball") end },
            },
            kit.row{ justify = "end", kit.close() },
        }
    end)
    if not d then player.ui.menu{ title = "Servers", items = { "slime_ball" }, on_pick = function() end } end
end
```

A pack that opens dialogs says so in its `citadel.yml`, so their fonts are
in the resource pack from the first join:

```yaml
dialogs: true
```

Without it, `player.ui.dialog` is an error that names the line to add.

`player.ui.dialog(view)` takes a `ui.kit.window{}`, or a function that
returns one. With a function the dialog is live: after every click it
calls the function again and draws what it returns, so a click only has to
change your state. It returns a handle:

- `d:refresh()` draws a live view again (after a change that was not a click).
- `d:update(view)` puts a new view (a window or a function) in place.
- `d:destroy()` closes it. `d.open` is `false` once the player closed it.

`ui.kit` is what a dialog is made of. Six primitives the engine draws, each
a table you can also write by hand:

- `kit.row{ ... }`, `kit.column{ ... }`, `kit.stack{ ... }` (children on top
  of each other): the children are the list part. Keys: `gap`, `pad` (a
  number, `{ y, x }` or `{ top, right, bottom, left }`), `align` and
  `justify` (`"start"`, `"center"`, `"end"`, and `"stretch"` or
  `"between"`), `fill` and `fill_to` (a gradient), `border`,
  `border_width`, `radius`, `shadow` (0 to 8). A root box may also set
  `edge_glyph = "namespace:name"` to paint that pack glyph behind the body
  and across the native widget's padding; the body retains its own hit boxes.
  Alternatively, `bleed = true` on the root lets its children occupy the
  widget's padding itself, for artwork that must meet the dialog edges.
- `kit.space{}`: an empty box that takes `width`, `height` or `grow`.
- `kit.text("Hi")` or `kit.text{ "Hi", color = ..., bold = true, shadow = false, align = "center" }`.
  `font_size` selects a native bitmap font height from 2 to 16 GUI pixels
  (default 8). `tracking` adjusts the advance between letters by -1 to 4
  GUI pixels (default 0). The engine uses the same metrics to fit the text.
  `font = "namespace:heading"` selects a pack-authored bitmap typeface; its
  declared ink height replaces `font_size`. Labels stay anchored at their
  top edge, including when layered over image-backed controls.
- `kit.image{ image = ..., radius = 4, detail = 2 }`: `image` is an
  `https://` URL (fetched once by the engine), a PNG or WebP file in the
  pack, or a `game.texture`; `detail = 2` has four times the pixels. Set
  `pixel_art = true` to use nearest-neighbor sampling and preserve exact
  colors for small pixel art such as player avatars.
  Use `kit.image{ glyph = "name" }` for one of the pack's own glyphs. A picture
  still on its way shows a placeholder, and the dialog is drawn again when
  it arrives.

Every node also takes `width`, `height`, `grow`, `on_click` (a
`function(player)`, or `"close"`) and `hover` (words shown under the
pointer).

Pack-authored typefaces live in `assets/<namespace>/dialog-fonts/<name>.json`:

```json
{
  "source": "font/heading.png",
  "cell": [36, 60],
  "chars": ["ABCDEFGHIJKLMNOPQRSTUVWXYZ?"],
  "density": 6,
  "spacing": -0.5,
  "space": 2,
  "advances": { "A": 3.5, "I": 1.5 }
}
```

The PNG lives under the namespace's `textures` directory. Each character
uses one cell, in row order; `\u0000` skips a cell and `?` is required as a
fallback. Draw white ink at the cell's top left on transparency; `color`
tints it at runtime. Every row must have the same number of cells. `density`
is source texels per GUI pixel (1–8). Cell height must be divisible by density
and at least eight GUI pixels, with extra transparent rows under small ink.
Both cell dimensions must fit a 256-texel native font atlas page. `spacing`
is -1 to 4 GUI pixels, added between characters; `space` is the native space
advance (1–16 GUI pixels). Optional `advances` supplies authored layout
advances per character, including spaces, as finite numbers from 1 to 64 GUI
pixels. These replace the rounded bitmap advance plus `spacing`. The engine
accumulates fractional advances and places each glyph to the nearest 1/64
GUI pixel, keeping layout, clipping, previews and packets consistent.
Font changes require a resource-pack rebuild and reconnect.

For high-resolution artwork, put a JSON atlas beside glyph PNGs at
`assets/<namespace>/textures/glyph/atlas.json`:

```json
{
  "source": "browser.png",
  "density": 5,
  "sprites": {
    "browser": { "rect": [0, 0, 1672, 941] },
    "join": { "rect": [1248, 805, 380, 76], "offset": [3, 0] }
  }
}
```

`source` is relative to that namespace's `textures` directory and must stay
inside it. `rect` is `[x, y, width, height]` in source texels; `density` is
1 to 8 source texels per GUI pixel. The engine preserves the source pixels,
pads incomplete GUI pixels transparently, and splits large sprites into
tiles that fit Minecraft's 256-pixel font atlas pages. Existing glyph PNGs
keep their two-texel density. Use `kit.image{ glyph = "namespace:join" }`.

Optional `offset = [x, y]` adds fewer than `density` transparent texels before
the crop to align artwork to its source grid. `size = [width, height]`
resizes a texture strip with nearest-neighbor sampling. Optional `patches`
is a list of `{ "source": [x,y,w,h], "target": [x,y,w,h] }` crops from the
same source image, composited into the sprite in order; targets are relative
to its unpadded output. This supports textured button and card variants.
Optional `ink_mask` extracts lettering onto transparency: `"light"` keeps
pixels with RGB channels above `[180, 180, 140]`; `"dark"` keeps pixels below
`[100, 80, 70]`. With a mask, `tint = [r, g, b]` recolors the retained ink.
This lets a label be layered over different button backgrounds without
bringing its old background along.
Atlas changes require a new resource pack and reconnect; Luau state changes
and text updates do not.

Use `kit.stack` to layer images, text, and controls in child order, from back
to front. Transparent glyph texels preserve the layers underneath. Place
invisible `kit.space{ width, height, on_click }` controls last when their
click rectangles span several visual layers. Their native cursor bounds
match the rectangle, independently of the images' text baselines.

How an image is drawn: one `width = 144, height = 80` directly in
`kit.window`, or first in a `kit.row` directly in it (the row's other
children sit beside it), is one picture the client renders once, so it is
cheap. Only the first such image in a window is drawn this way; every other
image is drawn in glyph cells, which the client draws every frame.

Made of those, in plain Luau (copy one to make your own): `kit.window{
title, button, on_close, input, size = "screen", ... }` (the dialog;
`button` is its button's label, `false` for none; `input = { label, value,
width, on_submit = function(player, text) end }` adds a text field;
`size = "screen"` is `kit.SCREEN`, a body that fits every screen without a
scrollbar), `kit.button{ "Play", style = "primary" | "secondary" | "ghost" |
"danger", on_click }`, `kit.tabs{ "A", "B", selected, on_change }`,
`kit.close{}`, `kit.badge{ "LIVE", color, dot }`, `kit.dot{}`,
`kit.progress{ value = 0.5 }`, `kit.divider{}`, `kit.card{ image, title,
text, badges, on_click }` and `kit.grid{ columns = 3, gap = 6, ... }` (any
nodes, in rows of `columns`).
`kit.theme` holds the colours they use when a call names none: change it
once to restyle them all. `kit.theme.shadow` (false) is whether kit text
draws the game's drop shadow when a call does not say.

A `game.texture` in `kit.image` is pixel art: each pixel grows into a
block of the same colour, and its see-through pixels show the box under
it. Give the image a `width` and `height` that are whole multiples of the
texture's for even pixels. `kit.mix(a, b, t)` mixes two `"#rrggbb"` colours.

The rules:

- A new dialog replaces the open one. Escape closes it and calls the
  window's `on_close(player)`.
- Clicks may `task.wait`. Only the pack that opened a dialog gets its clicks.
- A player who turned the resource pack down is sent no dialog: it is drawn
  in the pack's fonts.

## Hotbar menus

The hotbar is a menu of nine items, set per player.

- Selecting a slot fires `players.on_slot`.
- A click while holding a slot fires `players.on_click` with `hit.slot`
  set. Any target and either button counts.
- Right clicks never merge into a hold. The halves of one click (block
  use, item use, both hands) are one event.
- In pack mode the rest of the inventory is locked.

```lua
player:hotbar{                       -- replaces the nine hotbar slots; a missing index is empty
    [1] = { item = "lapis_block", name = "HIT", count = 1 },
    [7] = { item = "gold_nugget", name = "Bet: 50" },
    [8] = { canvas = minimap, name = "Map" },   -- a filled map of a canvas: a live picture in the hand
}
player.slot                          -- the slot in hand, 1..9, live
hit.slot                             -- on every players.on_click, 1..9
```

A slot is an item (see "items"), with the same meta. An item name that the
game version lacks is an error.

With `canvas = c`, the map shows the picture on every client
from 1.8, and it updates as the script draws.

## Text formatting

Every call that shows words takes **text**: chat, the action bar, titles,
kicks, boss bars, the sidebar, the tab header and footer, item `name` and
`lore`, menu titles, text displays, npc speech and name tags.

Text is a string or a table:

```lua
"Lap 2/3"                                                   -- words, in the surface's own colour
{ "1st", color = colors.gold, bold = true }                 -- one styled run
{ "Lap ", { "2", color = "white", bold = true }, "/3", color = "gray" }
player.ui.sidebar{ title = { "KART", color = "gold", bold = true }, lines = {
    { { "1. ", color = "yellow" }, "Mario" },
    { "2. Luigi", color = color(0.4, 1, 0.4) },
} }
```

- A table's entries are its **runs**: strings or tables.
- Its named fields style all its runs: `color`, `bold`, `italic`,
  `underline`, `strike`. A run's own style wins.
- A call's own colour (`player:message(text, color)`, `ui.actionbar(text,
  color)`, a title's `color`, a text display's `color`, `npc:say(text,
  color)`) colours the words with no colour.
- Any other field is an error that names the five style fields.
- A live text field (`bar.title`, a display's `text`) reads back the words.

### text that moves

A text table's `effect` styles **every letter**. A whole text can also be a
**function of the time**.

- The sidebar, boss bars, the tab list and text displays recompute them ten
  times a second. Other surfaces show the frame at send time.
- Only what moves is recomputed: a sidebar's still lines are read when it is
  set. To change one, set the sidebar again.
- A moving text table shown to many players at once, such as one title
  table every player's sidebar uses, is worked out once a frame.

```lua
-- a rainbow, one cycle a second: letter, its number i of n, and t = time.now()
local rainbow = function(letter, i, n, t) return { color = color.hsv((i - 1) / n + t, 1, 1) } end
p.ui.sidebar { title = { "KART", effect = rainbow, bold = true } }

local sparkle = function(letter, i, n, t)
    if (i + math.floor(t * 8)) % 4 == 0 then
        return { color = "white", bold = true }
    end
    return { color = "gold" }                -- or nil: the letter as it was
end
world.display { kind = "text", at = vec3(0.5, 70, 0.5), text = { "WINNER", effect = sparkle } }

-- a text that is a function of the time: rebuilt every frame
ui.sidebar { title = "Lobby", lines = {
    function(t) return { "Next race in " .. math.max(0, math.ceil(race_at - t)), color = "yellow" } end,
} }
```

- An effect returns a style (`color`, `bold`, `italic`, `underline`,
  `strike`, plus `text` to replace the letter, `""` to hide it) or `nil`.
- More effects, each one line:

  ```lua
  -- colours across the letters, flowing at `speed` cycles a second
  function(_, i, n, t) return { color = color.gradient(list, (i - 1) / n - t * speed, true) } end
  -- the whole text in one colour at a time, `speed` times through the list a second
  function(_, _, _, t) return { color = list[math.floor(t * speed * #list) % #list + 1] } end
  -- the letters appear one after another, `rate` a second from `from = time.now()`
  function(_, i, _, t) if i > (t - from) * rate then return { text = "" } end end
  ```
- An effect or text function that errors keeps its last frame and logs why.

Clients from 1.16 get exact colours, older ones the nearest of the sixteen.
Sidebar lines take hex colours from 1.20.3.

A screen or canvas draws text as pixels, in the colour of its `text` call.

## Screens

A screen is a wall of item frames that hold maps: 128 pixels per frame, on
every client from 1.8.

- Put it in the air blocks in front of a wall.
- `at` is the top-left frame as the viewer sees it.
- `facing` is the side the viewer stands on.
- Changes go out once per tick, as each frame's box of changed pixels.
- Colours snap to the map palette (about 250 tones). Each client gets its
  closest tone.
- `color.nearest(c)` does that snap in advance.

```lua
local board = world.screen{ at = vec3(-2, 68, -10), facing = "south", width = 4, height = 2 }
board.width, board.height             -- pixels: 512, 256
board:clear(colors.black)             -- every pixel; default black
board:set(x, y, color)                -- one pixel, (0, 0) top-left
board:fill(x, y, w, h, color)
board:rect(x, y, w, h, color, 12)     -- rounded corners of radius 12, smoothed
board:circle(x, y, r, color)
board:text(x, y, "Jackpot 2500", colors.yellow, 32)   -- 32 pixels tall, smoothed; returns the width
board:measure("Jackpot 2500", 32)     -- the width without drawing, for centring
board:line(x0, y0, x1, y1, color, 3)  -- 3 pixels wide (1 by default), round ends, smoothed
board:ring(x, y, r, color, 2)         -- a circle's outline, 2 pixels wide (1 by default)
board:polygon({ {10, 10}, {60, 10}, {35, 50} }, color)   -- filled, any number of corners, smoothed
board:gradient(x, y, w, h, colors.red, colors.blue)      -- top to bottom; a 7th value "across" runs left to right
board:sprite(x, y, { ".##.", "#..#", ".##." }, { ["#"] = colors.black }, 4)   -- pixel art, 4 pixels a dot
board:pixels(x, y, w, h, data)        -- raw RGB bytes (a buffer or a string), three a pixel, row by row
board:draw(canvas, x, y)              -- another canvas or screen, its top-left at (x, y); its transparent pixels are skipped
board:part(col, row)                  -- one map of it, { id = .. }, for a hand or a single frame
board:play{ file = "video/intro.rgb", fps = 20, loop = true }   -- a video; see "video" below
board:destroy()
```

- Text is DejaVu Sans Bold, anti-aliased, 16 pixels by default. It has every
  Latin letter, digits, symbols and `♠ ♥ ♦ ♣`.
- A screen belongs to its room and ends with the script.
- Players who join later see the current picture.

Set `on_click` (in `world.screen{}` or later) to get the pixel a player
clicks:

```lua
board.on_click = function(player, x, y, button)   -- button "left" or "right"
    board:circle(x, y, 6, colors.red)
end
board.on_click = nil   -- no hook again; false does the same
```

- A click on a block or the air behind the picture also counts.
- `players.on_click` still gets the click, with the frame's `entity_id` and
  no handle.

`board:view(player)` is one player's own layer over the screen, with the same
drawing calls.

- Only that player receives it.
- See-through pixels show the shared picture. A new view is all
  see-through, and `view:clear()` paints see-through.
- The call returns the same view until `view:destroy()` or the player leaves
  the room.
- Canvases have views too.

```lua
local mine = board:view(player)
mine:text(8, 8, "Your turn", colors.yellow, 24)   -- nobody else sees this
mine:destroy()                                    -- back to the shared picture
```

`glow = true` makes glow frames on 1.17 and later, plain frames before. A
glow frame stays bright in a dark room.

Drawing notes:

- `line`, `ring` and `polygon` take fractional positions and blend into the
  pixels under them. Draw them on a background, not on `colors.transparent`.
- A polygon point is `{x, y}` or `{ x = .., y = .. }`.
- Each `sprite` string is a row. Each character is a dot `scale` pixels
  square (1 by default). A character with no colour (the `.` above) leaves
  its pixels unchanged.

For a floor or a table, set `facing = "up"`, in the air blocks on top.

- `up` is the way the top of the picture points, `"north"` by default. Use
  `"south"` for a player north of the table.
- Rows run away from `up`. With `up = "south"`, x runs west and y runs
  north.
- Clients before 1.13 see nothing of a floor screen.

```lua
local felt = world.screen{ at = vec3(2, 66, 2), facing = "up", up = "south", width = 5, height = 3 }
```

## Canvases

A canvas is a picture of one or more maps (128×128 pixels each), with no
item frame. Show it on:

- a frame display, by map id;
- a hand: a hotbar slot with `canvas = c`;
- a screen, after `screen:draw(c)`.

An item display shows a blank map.

- Several walls can show one canvas.
- Drawing another canvas switches a wall's picture. Only changed pixels are
  sent.
- A canvas draws like a screen. Changes go to the whole room once per tick.
  Later joiners get the whole picture.
- A destroyed canvas keeps its last picture on clients that saw it. Its id
  is never reused.

```lua
local c = world.canvas{}              -- one map; world.canvas{ width = 4, height = 2 } is 4 by 2 maps (16 at most a side)
c.id                                  -- the map id of its top-left map, for a filled_map
c.width, c.height                     -- pixels: 128, 128 (512, 256 for 4 by 2)
c:part(col, row)                      -- another of its maps, { id = .. }, from (0, 0) top-left
c:clear(color) c:set(x, y, color) c:fill(x, y, w, h, color)
c:rect(x, y, w, h, color, radius) c:circle(x, y, r, color)
c:text(x, y, "A♠", color, size) c:measure("A♠", size)
c:line(x0, y0, x1, y1, color, width) c:ring(x, y, r, color, width)
c:polygon(points, color) c:gradient(x, y, w, h, from, to, "across") c:sprite(x, y, rows, inks, scale)
c:pixels(x, y, w, h, data) c:draw(other, x, y) c:play{ file = "video/clip.rgb", fps = 20 }
c:view(player)                        -- that player's own layer over it; see screens
c:destroy()
```

### video

`play` shows a video on a screen or canvas, with no script per frame. The
pack file holds raw RGB frames at the picture's size. Make it with ffmpeg:

```sh
# a 4 by 2 screen is 512 x 256 pixels
ffmpeg -i clip.mp4 -vf "scale=512:256,fps=20" -f rawvideo -pix_fmt rgb24 mypack/video/clip.rgb
```

```lua
local tv = world.screen{ at = vec3(-2, 70, -9), facing = "south", width = 4, height = 2 }
local v = tv:play{ file = "video/clip.rgb", fps = 20, loop = true }   -- fps 0.5 .. 20, one frame a tick at most
v.playing                             -- false once it ends (and does not loop) or is stopped
v:stop()
```

- Each frame snaps to the map palette. Only changed pixels are sent.
- A pixel changes at once when one of its channels moved more than 32 of 255
  from what the screen shows. A smaller move, of more than 8, waits for the
  next half second. So movement is as smooth as the video, and the noise of
  a camera is not sent in every frame.
- A fully changed frame costs 16 KB per map per player in the room. A 2 by 2
  screen at 10 fps is about 640 KB/s per player.
- Keep videos small or slow where many players watch.
- A video ends with the script.
- The file streams; it is never loaded whole.
- A **named pipe** in place of the file is a live picture. Another program
  writes the frames into it while the video plays, and the screen shows each
  frame at `fps`. A stream gives frames in bursts, so up to 24 frames wait in
  a queue; with more, the oldest are dropped. It has no end and does not
  loop: with no writer the picture stays, and a new writer continues it.

  ```sh
  mkfifo mypack/video/live.rgb
  ffmpeg -i https://example.org/live.flv -an -vf "fps=10,scale=512:256" -f rawvideo -pix_fmt rgb24 -y mypack/video/live.rgb
  ```

#### stream and sound

`url` plays a live FLV stream (H.264 video, AAC sound) with no other program.
On a screen, the stream's sound is heard too.

`url` can also be an MP3 stream, as a radio station sends it (Icecast,
Shoutcast). It has sound only: the screen keeps the picture the pack draws on
it, so a radio's own buttons and titles stay. The first bytes of the stream
say which kind it is.

A sound with no screen, from several speakers or from no place, is
[`sound.stream`](#sound).

```lua
tv:play{ url = "https://example.org/live.flv", fps = 10 }                       -- picture and sound, heard 48 blocks out
tv:play{ url = url, audio = { distance = 24 } }                               -- heard 24 blocks out (1 .. 128)
tv:play{ url = url, audio = { static = true } }                               -- the same volume everywhere in the room
tv:play{ url = url, audio = false }                                           -- picture only
tv:play{ url = "https://radio.example.org/live.mp3", audio = { distance = 24 } } -- a radio: sound only
```

- Players hear the sound through Simple Voice Chat: Citadel is a voice
  server for it, as a Paper server with the mod's plugin is (UDP port
  24454, `CITADEL_VOICE_PORT`). A player without the mod sees the picture
  only.
- A locational sound comes from the screen's centre and reaches the players
  within `distance`, fading out towards it. A static sound reaches everyone
  in the room, with no place and no fade.
- Sound needs a screen. A canvas has no place in the world, so
  `c:play{ url = .., audio = true }` is an error. A file of frames has no
  sound.
- The sound keeps time with the picture. If the server falls more than half
  a second behind, the sound skips to now and is not played late.
- A client older than 1.13 hears nothing.
- The sound stops with the video, or when the screen is destroyed.

## Map pictures

A client draws a map picture only in an **item frame**. To show a canvas in the world, use a `frame` display (invisible by default).

- The frame hangs in the block `at`, on the side `facing`.
- `"up"` lies flat on a floor (1.13 and later). A wall side works from 1.8.
- The frame does not turn or move.
- Set `canvas` to change the picture. `destroy` removes the frame.

```lua
local card = world.display{ kind = "frame", at = vec3(3, 65, 7), facing = "up", canvas = deck[12], invisible = true }
card.canvas = deck[53]        -- the back
card.id; card:destroy()
```

A canvas or screen pixel painted `colors.transparent` is see-through. `clear(colors.transparent)` empties a canvas.

# Sound and effects

What a player hears and sees in the air: sounds, particles, lasers and light.

## Sound

Play the game's sounds or the pack's own, for everyone or at a point.

```lua
sound.play(name, { at = spawn, volume = 1, pitch = 1, category = "record" })
--   volume above 1 carries further (16 blocks per unit); pitch 0.5..2.0 is two octaves
--   category: "record" (jukebox slider), "music", "master"
--   every call is one packet to every player, sent ahead of particles
sound.stop("rave.track")     -- stops that sound for everyone in the room; sound.stop() stops every sound
--   1.13 and later; older clients play on
```

### sound.stream

`sound.stream` plays a live stream or a pack's sound file through the
players' voice mods, with no screen. A live stream is MP3, as a radio station
sends it, or the sound of an FLV stream. A file is OGG (Vorbis), MP3 or WAV in
the pack; it is decoded while it plays, never loaded whole.

```lua
-- 3D: from speakers. Each player hears every speaker within `distance`.
local radio = sound.stream{ url = "https://radio.example.org/live.mp3", at = vec3(10, 67, 28), distance = 24 }
local pa = sound.stream{ url = url, at = { vec3(10, 67, 28), vec3(-10, 67, 28), captain }, distance = 16 }
local hum = sound.stream{ file = "assets/music/engine.ogg", at = engine_room, loop = true }

-- No place: the same volume for each listener, no fade, no direction.
sound.stream{ url = url }                         -- everyone in the room
sound.stream{ file = "assets/voice/welcome.mp3", to = player }
sound.stream{ url = url, to = { p1, p2 }, name = "Radio" }

radio.playing            -- false once stopped, or once a file that does not loop ends
pa:move(2, vec3(-12, 67, 30))   -- speakers are numbered from 1
pa:add(npc)                     -- a speaker that follows a player or an entity; gives its number
pa:remove(3)
radio:listen(player)            -- starts to hear it
radio:unlisten(player)          -- stops hearing it
radio:stop()
```

- Give `url` or `file`, never both. `loop = true` is for a file only: a live
  stream has no end, and if it drops it is tried again every 2 seconds.
- `at` is a vec3, a player, an entity, or a list of them. A speaker that
  follows a player or entity moves with it, and is silent while they are
  gone. `at = {}` starts with no speakers; `add` gives it some.
- All speakers play the same sound at the same time, as a speaker system
  does. A player hears every speaker in range, each from its own place, and
  the voice mod mixes them. Each one is a packet of its own to that player:
  three speakers in range send three times the sound's data.
- `distance` is 1 to 128 blocks, 48 when not given. It needs `at`: a sound
  with no place has no distance, and giving one is an error.
- `to` is a player or a list of players. Without it, everyone in the room
  hears the sound, players who join later too. `listen` and `unlisten`
  change who hears while it plays.
- `name` (1 to 16 characters, `"Sounds"` when not given) is the sound's own
  volume slider in the mod.
- `move`, `add` and `remove` on a sound with no `at` are an error. On a
  stopped sound, every call does nothing.
- The sound stops with `stop()`, or when the script stops or reloads.
- Players hear it through Simple Voice Chat, as a screen's stream: a player
  without the mod, or on a client older than 1.13, hears nothing.

| | `sound.play` | `sound.stream` |
| --- | --- | --- |
| How it reaches the player | The game's or the pack's resource pack; the client plays it | Simple Voice Chat, from the server |
| Mod needed | No | Yes |
| Control | Start and stop | Speakers, moving sources, a list of listeners, all players in time |
| Best for | Short effects: a click, a door, an alarm | Music, ambience, long voice lines, radios, speaker systems |

## Particles and lasers

Particles at points: a burst, a trail, or a laser drawn as a line of dust.

```lua
fx.particle(name, pos, { count = 1, spread = 0, velocity = nil, speed = 0, color = nil, size = 1 })
```

- `name` is the particle: `dust`, `end_rod`, `explosion`, `firework`,
  `flame`, `note` or `totem_of_undying`. Any other name sends nothing.
- `pos` is a vec3, or a list of vec3s, with the same particle at every point.
  Each point is sent only to players in the same room within 64 blocks of
  its origin in 3D, including the boundary, before spread or velocity.
- `count` particles appear at each point, in a random box `spread` blocks
  out from it. `spread` is a number or a vec3 (one size per axis).
- `velocity` (a vec3) sends one particle that moves along it. It cannot go
  with `count` above 1 or with `spread`. `speed` scales it and is 1 with a
  velocity.
- Without `velocity`, `speed` is how fast the particles scatter. 0 is still.
- `color` and `size` (0.5 to 4) are for `dust` only. Dust is white and size
  1 unless they say. On any other particle they are an error.
- A client whose version lacks a particle does not get it. Before 1.13,
  dust is one particle a point, in its colour, with no count, spread or
  size. 1.7 shows dust only.

```lua
-- a beam: dust at points along a line, in one call
local points = {}
for i = 0, 7 do points[i + 1] = from:lerp(to, i / 7) end
fx.particle("dust", points, { color = colors.red, size = 1.5 })

fx.particle("flame", pos, { velocity = vec3(0, 1, 0), speed = 0.5 })        -- a jet
fx.particle("firework", pos, { count = 40, spread = 2, speed = 0.05 })       -- a burst
```

Particles fade on their own. A beam that stays is drawn again every other
tick:

```lua
local beam = { from = vec3(0.5, 76, 0.5), to = vec3(0.5, 66, 0.5), color = colors.cyan }
local conn = time.on_tick(function(tick)
    if tick % 2 ~= 0 then return end
    local points = {}
    for i = 0, 7 do points[i + 1] = beam.from:lerp(beam.to, i / 7) end
    fx.particle("dust", points, { color = beam.color, size = 2 })
end)
tween(beam, { to = beam.to + vec3(4, 0, 0) }, { duration = 1 })   -- its fields are plain; set or tween them
conn:cancel()                                                     -- and it is gone
```

## Lighting

`world.light` sends players light that no block makes. Each call replaces the
last call's sources. `world.light{}` removes them all.

```lua
world.light{
    { at = vec3(4, 65, -2), level = 12 },   -- 1 to 15 (15 by default), in the air where it shines
    { at = vec3(0, 70, 0) },
}
```

- Light drops one level per block, like block light. Solid blocks stop it.
- The light has no colour. For colour, put coloured blocks or a glowing screen under it.
- The server never sees this light. The world's real light does not change.
- It needs clients 1.14 and later. Older clients ignore it. A pack that depends on it sets `min_client: "1.14"`.
- A block change can erase the light near it. While the light moves, call `world.light` every tick or two.

# Entities

Things in the world: displays, models, NPCs, entities, items, and the zones that notice them.

## Displays

A display is a floating item, text or block with no physics.

- Clients from 1.19.4 see the real display and tween `animate`.
- Older clients see an invisible armor stand holding the `item`, or with
  the `text` as a name tag.
- Older clients see nothing for `block` and `hitbox`. Give them a pad.
- A display belongs to its room and ends with the script.

```lua
-- every kind takes these
local d = world.display{
    kind = "text",                      -- "item", "text" or "block"
    at = vec3(0.5, 66, 0.5),            -- where it sits
    rotation = { yaw = 0, pitch = 0, roll = 0 },   -- degrees; pitch = 90 lays a text flat on a table
    scale = 1,                          -- or vec3(1, 2, 1); a number is the same on every axis
    billboard = "center",               -- "fixed", "vertical", "horizontal" or "center";
                                        --   text defaults to "center", the rest to "fixed"
    glow = colors.cyan,                 -- outline colour; leave it out, or write false, for none
    -- and a text takes these
    text = "BLACKJACK",                 -- text, see "Text formatting"
    color = colors.white,               -- a colour or a name
    background = color(0, 0, 0),        -- behind the words; leave it out, or write false, for none
    line_width = 200, shadow = false,
}
world.display{ kind = "item", at = vec3(2.5, 66, 0.5),
    item = "paper",                     -- canonical item name; or canvas = c, a world.canvas{}: a filled map of the picture
    context = "frame",                  -- how the item is posed: "frame", "none", "menu", "dropped", "worn", "held", "own_hand"
}
world.display{ kind = "block", at = vec3(4.5, 66, 0.5), block = "lapis_block" }
d.id                                    -- entity id, what players.on_click reports in hit.entity_id
d.at, d.rotation, d.scale, d.billboard, d.glow   -- live, every kind
d.item, d.canvas, d.context             -- live, item kind (canvas reads back as the map id)
d.text, d.color, d.background, d.line_width, d.shadow    -- live, text kind; background = nil or false for none
d.block                                 -- live, block kind
d.duration                              -- seconds later changes take to play out (1.19.4+); 0
d.glide                                 -- advanced: movement smoothing seconds (1.20.2+); default 0.1
d.lead                                  -- advanced: true enables linear prediction; false by default, nil restores false
d:animate{ at = ..., scale = ..., rotation = { ... }, text = ..., duration = 0.5 }   -- one tweened change
d:destroy()

local h = world.hitbox{ at = vec3(...), width = 1, height = 1, on_click = function(player, button) end }
h.id; h.at; h:destroy()                 -- button is "left" or "right"
```

A hitbox is an invisible clickable box. Its `on_click` fires through
`players.on_click`. Clients below 1.19.4 get no hitbox.

`world.hitbox{ ..., solid = true }` is also a **wall**. A player cannot walk
through it and can stand on it.

- It works anywhere and moves when you write `at`.
- Its size is `width` (x) by `height` by `depth` (z). `depth` defaults to
  `width`. `at` is its bottom centre.
- It cannot turn. Build a turning thing from several small walls.
- The engine fills it with cubes of its smallest side, 64 at most, and
  warns past 64. Make a thin sheet from blocks.
- Clients from 1.20.5 stop at the exact size. Older clients stop at
  one-block cubes.

### Choosing a world object and moving it

| Need | API | Why it exists |
|---|---|---|
| Reusable appearance and named animations | `models.new` | Defines an asset for visuals or simulated entities. |
| A visual controlled by the pack | `world.display` | Places text, an item, a block or a model without simulation. |
| Physics, gameplay hooks or persistence | `game.entities.define` and `world.spawn` | Gives a body behavior independent of its appearance. |
| A mob appearance moved entirely by the pack | `world.puppet` | Uses a mob body without its AI or gameplay simulation. |
| A player-shaped character with a skin and equipment | `world.npc` | Adds avatar-specific behavior. |
| A player or NPC seated on something | `:ride` | Controls attachment and occupancy. |
| A different viewpoint | `player.camera` | Controls the view; `chase` composes with riding. |
| Authored changes over time | `tween` or `camera.path` | A tween animates fields; a camera path sequences shots. |

Displays, model displays, NPCs, puppets and entity handles share `id`, `alive`, `at`,
`rotation` and `:move(at, rotation?)`. `rotation` is a table of degree angles;
partial writes preserve omitted angles. `move` changes position and rotation
in one operation, and validates both before applying either. Entities continue
simulating after a move; changing their position does not clear velocity.
`at` and `rotation` read `nil` when the object is gone. Cleanup can be repeated.

Displays and models also share `scale`: reads return a `vec3`, writes accept a
number or vector. Models preserve their proportions and accept only equal,
positive axes; plain displays can stretch individual axes. Model entities expose
this same scale contract, or `nil` when they have no model. Bodies and NPCs
support yaw/pitch; roll belongs to displays and model displays. Displays also
accept `rotation = { forward = direction, up = roof }`; reads always return
angles. Use angle targets for `tween`: partial targets preserve other axes,
and angles interpolate as written, so `roll = 360` can author a full turn.

Write current positions with `at` or `move`; the engine smooths visual movement.
Use `display:animate{..., duration = seconds}` for an authored display transition,
`tween` for other live fields and `camera.path` for a sequence of camera shots.
`animate` sets the position interpolation time as well as the transform time.
`duration`, `glide` and `lead` are advanced display controls, not requirements
for moving a model or following it with a camera.

### vehicles

A vehicle is an entity that looks like a model. Seat 1's keys drive it.
The engine does the driving, gravity, walls and steps:

```lua
local car = game.entities.define {
    name = "car",
    looks = models.car,              -- a model from models.new
    physics = "vehicle",             -- the engine drives it
    size = { 1.6, 1 },               -- its body in blocks: width, height
    seats = { vec3(0, 8, 2), vec3(0, 8, 12) },   -- in model units; seat 1 drives
    speed = 16,                      -- blocks a second at full throttle (12 if left out)
    turn = 90,                       -- degrees a second at speed (90)
    accel = 1,                       -- seconds from standing to top speed (1)
    step = 1,                        -- blocks it climbs without a jump (1)
    scale = 1,                       -- the model's size (1)
    fallback = "minecart",           -- what a client older than 1.21.4 sees
}

local c = world.spawn(car, vec3(0.5, 65, 0.5))
player:ride(c)                                -- seat 1: W and S throttle, A and D steer
friend:ride(c, { seat = 2, locked = true })   -- locked: sneaking does not get them off
c.driver                                    -- player supplying seat 1 input; nil for an NPC or empty seat
c.riders[2]                                 -- actual occupant, including NPCs; nil means empty
npc:ride(c)                                   -- an npc at the wheel; it does not drive (see npcs)
c.paint = { paint = colors.blue }             -- this car's colours, by material name
c.scale = 1.5
c:play("drive", { speed = 2 })                -- again with another speed only changes the speed
c:stop("drive")
```

- Every tick, before any hook, the engine writes seat 1's keys into `c.forward` (1 ahead, -1 back),
  `c.strafe` (1 left, -1 right) and `c.jumping`. With seat 1 empty, the car
  rolls to a stop.
- In `on_steer`, call `base(e)`, then adjust. Or skip `base` and set
  `e.velocity` and `e.rotation` yourself:

  ```lua
  on_steer = function(e, base)
      base(e)                                   -- drive as defined
      if e.data.boost then e.velocity = e.velocity * 1.4 end
  end
  ```

  A CPU driver (or an npc in seat 1) writes `e.forward` and `e.strafe`, or
  the velocity, in this hook.
- `rotation.yaw` works as for every entity: 0 faces south (+z), 90 faces
  west. The model's front (-z) faces that way.
- The model and seats glide two ticks between moves. The rider's chunks
  follow the vehicle.
- Without `locked`, sneaking gets a rider off and fires `players.on_sneak`.
  Then `player.riding` is false. `player:dismount()` gets anyone off.
- A seat holds one rider. `player:ride` and `npc:ride` return `false` for a
  full seat.
- Creating a model or entity and mounting it in the same callback needs no
  `task.wait`. The engine sends spawns before passenger attachments.
- Mounting the current seat again keeps the ride. An occupied, invalid, or
  destroyed replacement leaves the current ride intact. Riding cycles are
  rejected. Destroying a mount also clears its rider's locked state.
- To give a player an npc's car: `npc:dismount()`, move the npc with
  `npc.at`, then seat the player.
- Only `physics = "vehicle"` reads `speed`, `turn`, `accel` and `step`, and
  it needs `looks`. Anything else is an error at `define`.

### riding anything else

`player:ride(thing)` also seats a player on a model display, a display, a
hitbox or an npc: anything with an `id` the client sees. The pack moves
these things.

- The player's feet are 0.6 below the thing's position. A model display's
  `seats` work as a vehicle's; with none, seat 1 is the model's origin.
- A ridden display glides two ticks between moves (1.20.2+), unless the
  pack set a `glide` or `duration`.
- Pack-created displays and model displays interpolate the current positions
  a pack supplies. This default does not extrapolate past a stop or bounce.
  Seats and follow cameras use the same movement timing automatically.
- Smoothing introduces a short visual delay; it cannot remove network latency.
  Java 1.20.2 and later interpolate display movement; earlier clients receive
  positions using the features they support.
- Advanced overrides: `glide` changes the interpolation duration on a plain
  display; `lead = true` enables linear prediction and reduces steady-motion
  delay at the cost of possible overshoot at sudden stops. `lead = false`
  sends the supplied positions; `nil` restores this default. Supply real
  positions, not positions you predicted.
- The rider's chunks follow the ridden thing, at any distance. Chunks behind
  are dropped.
- `player.input` reads keys on foot from 1.21.2. Before 1.21.2, a client
  reports keys only while it rides.

## 3D models

A model is a 3D shape a pack writes in code: boxes in a tree of named
parts. The engine shows it as item displays that move together.

```lua
local car = models.new("car", function(m)
    local paint = m:material("paint", colors.red, { grain = 0.1 })   -- a colour a display may repaint
    local glass = m:material("glass", "dark_aqua", { alpha = 0.45 }) -- what is behind shows through
    local door = m:texture(30, 16, { tint = paint })                 -- drawn in greys, coloured by paint
    local grille = m:texture(8, 4)                  -- pixel art for one face, drawn as it is
    grille:fill(colors.black)
    grille:rect(1, 1, 6, 2, colors.gray)            -- x, y, w, h, colour
    grille:pixel(0, 0, colors.transparent)          -- a see-through pixel

    local body = m:part("body", { pivot = vec3(0, 6, 0) })
    body:box(vec3(0, 4, -20), vec3(8, 12, 20), paint, {
        faces = { north = grille },                 -- one side wears something else
    })
    local screen = body:part("windscreen")
    screen:box(vec3(0, 12, -6), vec3(8, 18, 2), glass, { rotation = vec3(22.5, 0, 0) })
    local wheel = body:part("wheel_front", { pivot = vec3(8, 4, -12) })
    wheel:box(vec3(6, 0, -16), vec3(10, 8, -8), paint)
    wheel:box(vec3(6, 0, -16), vec3(10, 8, -8), paint, { rotation = vec3(45, 0, 0) })
    body:mirror("x")                                -- the left half, from the right one

    m:animation("drive", {
        length = 1, loop = true,
        wheel_front = { rotation = { [0] = vec3(0, 0, 0), [0.25] = vec3(-90, 0, 0), [0.5] = vec3(-180, 0, 0),
            [0.75] = vec3(-270, 0, 0), [1] = vec3(-360, 0, 0) } },   -- quarter turns: see the rules
        wheel_front_mirrored = { rotation = { [0] = vec3(0, 0, 0), [0.25] = vec3(-90, 0, 0), [0.5] = vec3(-180, 0, 0),
            [0.75] = vec3(-270, 0, 0), [1] = vec3(-360, 0, 0) } },
    })
end)

local d = world.display{
    kind = "model", model = car,
    at = vec3(10.5, 65, 4.5), rotation = { yaw = 90 },      -- degrees, as every entity turns: 0 faces south, 90 west
    scale = 3.5,                             -- 1 draws it at 16 units to the block
    paint = { paint = colors.blue },         -- keys are material names
    fallback = "minecart",                   -- what a client that cannot show it sees; nil shows nothing
    seats = { vec3(0, 7, 2) },               -- optional: where riders sit, in model units; see "vehicles"
}
d:move(vec3(12.5, 65, 4.5), { yaw = 180 })   -- place and turn it in one step, every part together
d:move(at, { forward = forward, up = up })                      -- pointed: nose along forward, roof toward up (a car on a wall)
d.at, d.rotation                             -- live too; each write is a move of its own
d.scale = 2                                  -- live
d.paint = { paint = colors.red }             -- live
d:play("drive")                              -- from the beginning; an unknown name is an error
d:play("drive", { speed = 2 })               -- twice as fast; on the one already playing, the new speed at once
d:stop("drive")                              -- the parts stay where they are
d:destroy()
```

The rules:

- Make models while the pack loads. `models.new` in a callback is an error.
- `rotation.pitch` and `rotation.roll` tip the whole model about its
  origin, with parts, animations and seats.
- A rider stays upright. For a car on a wall, hide the driver
  (`invisibility`) and use `camera.fixed`.
- **16 units are one block.** The origin is the model's bottom centre, `+y`
  is up, and the front is `-z`.
- A box reaches `-24 .. 24` on every axis: three blocks. For a bigger thing,
  set the display's `scale`.
- A model texture is 128 at most a side, and draws with `pixel`, `rect`,
  `fill` and `draw(picture, x, y)`: a `game.texture` over it, its corner
  at `(x, y)`. A bigger picture goes on several boxes: `t:draw(map, -128, 0)`
  takes the second square of 128 from a PNG loaded with `game.texture`.
- `m:texture(w, h, { scroll = "up", speed = 2 })` is a texture that moves
  when a block is drawn from the model. See "blocks drawn from a model".
- A box turns on **one** axis only, in steps of 22.5 degrees, up to 45
  either way. Anything else is an error. An octagonal wheel is two boxes,
  one turned 45.
- Box corners go in any order and can be fractional. A box's `pivot`
  defaults to its centre.
- Every box is in a part; there is no `m:box`. A part turns around its
  `pivot` (default: the model's origin). `m:part` makes a child of the root,
  `part:part` a child of that part.
- `part:mirror("x")` mirrors what the part has so far, pivots, turns and
  hitboxes too. A child's twin is `<name>_mirrored`. Only `"x"` works in this version.
- `part:hitbox(from, to)` is a box a player can hit on a living body that
  wears the model. See "a living body".
- Between two keys, a part turns **the short way round**. Keep each step
  under 180 degrees. A wheel is `[0] = 0, [0.1] = -90, [0.2] = -180, ...`:
  one key from 0 to 360 does not turn. A `tween` of `rotation` is not like
  this: it turns as written, so there `roll = 360` is a full turn.
- `speed` is 0.01 to 100; a value outside is taken as the nearest end. A
  speed of 0 does not pause: use `stop`. A new speed applies at once.
- An animation is keys per part: `{ [seconds] = vec3 }` for `rotation`
  (degrees about the pivot) and `position` (an offset in model units).
  - Keys can be in any order.
  - An unknown part name is an error that lists the model's parts.
  - Parts cannot share a track. Write a loop.
- A material is flat unless it has a `grain` (`0..1`: how much darker its
  darkest pixel is). `0.1` is a painted panel, `0.4` a tyre. A grained face
  has four tones, one pixel per unit. `alpha` below 1 is glass.
- A texture stretches over its face. For fine detail, draw two pixels per
  unit.
- With `tint = material`, draw in greys. White is the material's colour;
  darker is a seam or a shadow.
- A mirrored box shows a side texture from the other end. Draw an
  asymmetric texture once per side, after the `mirror`.
- `paint` repaints materials by name, and every texture they tint. An
  unknown material name is an error that lists the model's materials.
- Only Java clients from 1.21.4 see a model. Older clients and Bedrock see
  `fallback`. A client that loads the resource pack after it joined gets
  its models again when the pack is in; the pack does nothing for this.
- A client that turns the resource pack down, or cannot load it, sees
  `fallback` from then on, also for the models it already sees.
- `citadel model render <pack dir> <name> --out car.png` draws a model.
  Add `--animation drive --at 0.25` for mid-move. No name lists the models.

## NPCs

An NPC is a player-shaped entity. Every client from 1.8 sees it. A puppet is a mob's body with no mind of its own: the script sets its position. Use a
puppet for anything a race or a show must steer.

```lua
local n = world.npc{ name = "Dealer", at = vec3(0.5, 65, 4.5), rotation = { yaw = 180, pitch = 0 },
                     skin = "Notch" }   -- a player's name; the engine looks the skin up
--   skin = { value = "...", signature = "..." } is the raw profile property, for a skin no account wears
--   leave skin out, or write false, for the default skin; any other value is an error
n.id                   -- entity id, what players.on_click reports in hit.entity_id
n.name                 -- "" for one made with no name
n.at, n.rotation   -- live; set them and the NPC moves
n:look_at(pos)         -- turns head and body toward a point
n:swing()              -- the arm animation
n:hold("paper")        -- item in the main hand; n:hold(nil) or n:hold(false) empties it; errors on an unknown item
n:say("Place your bets.", "light_purple")   -- a chat line "<Dealer> ..." to the room (just the words with no name); text
n:walk{ path = { vec3(4.5, 65, 0.5), vec3(4.5, 65, 9.5) }, speed = 1.4, loop = true }
--   walks the points by itself, facing where it goes; speed in blocks a second
n.walking              -- true until the last point (never, with loop); n:walk(nil) stops it
n.pose = "sleeping"    -- "standing", "crouching", "sleeping" (flat on its back), "swimming" (flat on its front); live
n:wear{ head = "iron_helmet", chest = { item = "leather_chestplate", dye = colors.red } }   -- see "armour"
n:ride(car, { seat = 2 }) -> boolean   -- sits as player:ride does; false when that seat is taken
n:dismount()           -- gets off where it sits
n.riding               -- boolean, live
n:destroy()

local p = world.puppet{ kind = "horse", at = vec3(0.5, 65, -100.5), rotation = { yaw = 90 }, name = { "Lightning", color = "gold" } }   -- name is text
p.id, p.name           -- the name tag is always shown; errors when this game has no such mob kind
p.at, p.rotation   -- live
p:destroy()
```

- A name is at most 16 characters.
- **Leave `name` out and the NPC has no name tag** from 1.8 on. A 1.7 client still shows a tag with an engine-made name.
- An NPC stays in the tab list for two seconds after it appears, then leaves it.
- A `skin` given as a player's name costs two calls to Mojang. The NPC shows its own skin until the answer arrives. If no account has that name, the log says so.
- The engine removes a script's NPCs and puppets when the script ends or reloads.

**Walking.** The engine moves a walking NPC along the path the script gives
once. It faces its direction and moves its legs.

- It walks straight between points, at the points' height. Put points up a stair and at each corner.
- It walks through anything. The pack keeps the path clear.

A **pose** stays during a walk or a ride. A client that cannot show a pose
sees the NPC standing:

| pose | shown from |
|---|---|
| `"crouching"` | 1.8 |
| `"sleeping"` | 1.8: lying on its back, feet at `at`, head toward the yaw's side (to a quarter turn before 1.14) |
| `"swimming"` | 1.13 |

For a client before 1.14, the engine puts a bed under a sleeping NPC, at
height 0 in its column. Do not lay a sleeping NPC where the pack builds at
height 0 in that column.

**Riding.** `n:ride(thing, { seat = n })` takes what `player:ride` takes: a
vehicle's seat, a model display's seat, a display, a hitbox, or another NPC.

- Every client, also a later one, sees the NPC seated and moving with the vehicle.
- A client that cannot see the seat (a display needs 1.19.4) sees the NPC standing at the seat, moving with it.
- `ride` stops a walk. `n.at` reads the seat's position.
- An NPC never drives a vehicle (see "vehicles").
- After `n:dismount()`, set `n.at` to move the NPC somewhere else.

## Mobs and drops

A **mob** belongs to the engine: it decides, walks, falls and drops
its normal drops. `world.spawn` with the name of a mob kind spawns one and
returns a handle.

```lua
local cow = world.spawn("cow", vec3(4.5, 65, 8.5))   -- nil where this game has no such kind
cow.id                 -- entity id, what players.on_click reports in hit.entity_id
cow.name               -- "cow"
cow.at                 -- vec3, live; nil once it is gone
cow.rotation, cow.hostile
cow.health, cow.max_health   -- its health now, and the most its kind gives it
cow.alive              -- is it still in the world
cow:destroy()          -- takes it out on the next tick
world.entities { mob = true }    -- every mob in this room, as handles
world.entities { mob = false }   -- every entity that is not a mob

world.items()          -- the stacks on the ground: { { id, item = "dirt", count = 3, at = vec3 }, ... }
```

- A mob acts on its own on both kinds of server, lite included.
- Each read gets the entity's current state. Check `alive`.
- A mob a pack spawns stays when the script reloads. An NPC does not.
- `tostring(cow)` is `entity(cow, 7)`: the kind's name and the id.
- A mob has the **same handle** as every entity the world moves: `cow.velocity`, `cow:push(v)` and `cow:nearby(8)` work too. See "Custom entities".

> **a0.1.0 spawns nothing on its own.** On an Alpha world every entity in
> `world.entities { mob = true }` comes from a dungeon spawner, `/summon` or this call.

## Custom entities

The facts, switches and hooks of a mob kind of the game are in
`game.entities.<kind>`.

Every entity has an `on_steer` and an `on_tick` hook. Three calls reach them:
**amend** the game's own entity, **define** your own, and **spawn** it.

### amending the game's own

```lua
game.entities.amend("pig", {
    on_steer = function(e, base)
        base(e)            -- vanilla wander
        e.jumping = true   -- but always jumping
    end,
})
```

The amend also changes **pigs already in the world**, with no respawn.

- `base` is the behaviour you wrap: vanilla's, or the previous pack's.
- Wrapped behavior runs first by default. To replace it, pass `{ replace = true }` as the third argument and omit `base`.
- `base` makes a *decision*. What you assign after it wins. Two calls act as one.
- An amend changes **hooks** only. It refuses the keys `size`, `looks`, `physics`, `max_health`, `speed` and `persist`. For an entity that looks different, use `define`.
- You can amend only **the game's own** content. A name with a colon is refused.

### defining one of your own

```lua
local rocket = game.entities.define {
    name = "rocket", looks = "tnt", physics = "falling", size = 0.98,
    on_tick = function(e)
        e.velocity = e.velocity + vec3(0, 0.12, 0)
        e.data.fuse = (e.data.fuse or 60) - 1
        if e.data.fuse <= 0 then
            local at = e.at
            e:destroy()
            world.explode(at, 4)
        end
    end,
}

local it = world.spawn(rocket, vec3(8.5, 66, 8.5), { fuse = 40 })
```

| field | what it is |
|---|---|
| `name` | your name for the kind. The engine adds the namespace: `"rocket"` becomes `"rave:rocket"`. You cannot use another pack's namespace. Lower case letters, digits and underscores. |
| `looks` | a shape the client **already draws**: `"pig"`, `"tnt"`, `"item"`, `"falling_block"`, `"none"`. Two forms take a payload: `{ entity = "falling_block", block = "sand" }` and `{ entity = "item", item = "diamond" }`. A name that this game's oldest client does not know is refused, never replaced. |
| `physics` | the movement order: `"living"`, `"falling"`, `"item"`, `"none"`. Not a table of numbers; the game version sets those. `"living"` is a body with health: see "a living body". |
| `size` | one number, or `{ width, height }`. Depth equals width, so a third number is an error. |
| `persist` | `"save"`: it comes back with the chunk, `e.data` included. Or `"despawn"`, the default. |
| `looks = models.x` | a model a pack made, with `seats`, `scale` and `fallback` next to it. See "vehicles". |
| `physics = "vehicle"` | the engine drives it by seat 1's keys, with `speed`, `turn`, `accel`, `step`. See "vehicles". |

- Call `define` and `amend` **while your pack loads**.
- A world opened without your pack **quarantines** your entities: nothing ticks or shows them, and saves keep them unchanged. Install the pack again and they continue.

### a living body

With `physics = "living"` the entity is a real living thing. It falls, walks,
steps up half a block, swims, and takes fall damage, with the numbers of the
game version. It has health, players can hit it, and it dies. It has no
mind of its own: it moves only as your hooks say.

```lua
local sheep = game.entities.define {
    name = "fluffy", looks = "sheep", physics = "living", size = { 0.9, 1.3 },
    max_health = 8,                       -- 20 if you leave it out
    speed = 3,                            -- blocks a second at forward = 1
    drops = { { item = "white_wool", count = { 1, 3 } }, { item = "mutton" }, { item = "diamond", chance = 0.05 } },
    sounds = { hurt = "entity.sheep.hurt", death = "entity.sheep.death", ambient = "entity.sheep.ambient" },
    on_steer = function(e)
        e.forward = 1                     -- walk
        e.rotation = { yaw = -90 }        -- east
        e.jumping = e.data.stuck == true  -- jump when you ask it to
    end,
    on_damage = function(e, amount, by)
        if by then e.data.angry_at = by.name end
    end,
    on_remove = function(e, why)          -- why is "killed" after a death
    end,
}
world.spawn(sheep, vec3(8.5, 66, 8.5))
```

| field | what it is |
|---|---|
| `max_health` | the most health it has, and what it starts with. A whole number from 1 to 1024. 20 by default. `e.max_health` reads it. |
| `speed` | how fast it walks at `forward = 1`, in blocks a second. By default, the game's own mob walk (about 3). |
| `drops` | what it leaves when it dies. Each row is `{ item = "stick", count = 2 }`. `count = { 1, 3 }` gives a random count. `chance = 0.05` leaves the row after one death in twenty; without it, after every death. A row can be a pack item. `false` or nil: nothing. |
| `sounds` | `{ hurt = ..., death = ..., ambient = ... }`, each a vanilla sound or `"<pack>.<file>"`. Each one is optional. |
| `can_fly` | `true`: it may fly, and it takes no fall damage. Your pack sets `e.flying` to take off and to land. See "flying and swimming". |

- These five keys need `physics = "living"`. On another physics they are an error.
- Steer with the intent fields: `e.forward`, `e.strafe` (-1 to 1), `e.jumping` and `e.rotation.yaw`. A body keeps its intent until you change it. For AI, write them from `on_think`: see "a brain: on_think".
- Writing `e.velocity` still works. It is a push by hand.
- A whole block needs a jump: set `e.jumping`, as a mob does.
- A player's hit hurts it as a mob: the same damage, knockback, a red flash and a short time in which a second hit does not land. Arrows, falls, fire, lava and drowning hurt it too.
- With `looks = models.x`, the model flashes red too, for half a second, on clients from 1.21.4. It stays red while it dies. Older clients do not see the model flash.
- `on_damage(e, amount, by)` is asked before a player's hit lands. `by` is that player. Answer `"ignore"` to stop the hit. Other damage lands without the question.
- At 0 health it dies as a mob: it falls over, leaves its `drops`, and is gone a second later. `on_remove` gets `"killed"`, and `world.on_entity_death` fires.
- With `looks = models.x` clients from 1.19.4 can hit it: the engine gives it an invisible hitbox of its `size`. Older clients cannot hit a model. A long model needs hit volumes: see "hit volumes".

#### hit volumes

A body's `size` is one square box. A long animal is much longer than that,
so a player who swings at its head or tail hits nothing. Give the model
hit volumes with `part:hitbox(from, to)`, in model units like a box:

```lua
local rex = models.new("rex", function(m)
    local skin = m:material("skin", colors.green)
    local body = m:part("body")
    body:box(vec3(-4, 6, -8), vec3(4, 16, 8), skin)
    body:hitbox(vec3(-4, 6, -8), vec3(4, 16, 8))          -- the body
    local head = body:part("head")
    head:box(vec3(-3, 10, -20), vec3(3, 16, -8), skin)
    head:hitbox(vec3(-3, 10, -20), vec3(3, 16, -8))       -- the head, in front (-z)
    local tail = body:part("tail")
    tail:box(vec3(-2, 8, 8), vec3(2, 12, 24), skin)
    tail:hitbox(vec3(-2, 8, 8), vec3(2, 12, 16))          -- the tail, in two parts:
    tail:hitbox(vec3(-2, 8, 16), vec3(2, 12, 24))         -- a hitbox is square from above
end)
local t_rex = game.entities.define {
    name = "rex", looks = rex, scale = 4, physics = "living", size = { 3.2, 5.5 },
}
```

- A hit on any volume is a hit on the body: the same damage, `on_damage` and death.
- The engine measures reach and aim to the volume a player hit, not to the body's feet.
- A volume turns with the body's yaw and tips with its pitch. It does not move with an animation: it stays where the part is at rest.
- A volume is square from above: as wide as its longer side. Split a long thin part into several volumes.
- A model with no volumes is hit on one box of the body's `size`.
- Each volume is an entity on the client. A body that stands still sends nothing; a body that moves or turns sends one move a tick for each volume that moved.
- With `persist = "despawn"` (the default) it goes away when no player is near, as a mob does. With `"save"` it stays, with its health and `data`.

#### flying and swimming

A body with `can_fly = true` walks like any body and flies when `e.flying` is
true. This bird walks, takes off, flies to a perch and lands:

```lua
local perch = vec3(20.5, 75, 8.5)
local bird = game.entities.define {
    name = "bird", looks = models.bird, physics = "living", size = { 0.5, 0.6 },
    speed = 6, can_fly = true,
    on_steer = function(e)
        local to = perch - e.at
        local far = math.sqrt(to.x * to.x + to.z * to.z)
        e.rotation = { yaw = math.deg(math.atan2(-to.x, to.z)), pitch = 0 }
        if e.data.landed then
            e.forward = 0                           -- sits on the perch
        elseif e.age < 60 then
            e.forward = 0.5                         -- walks first
        elseif far > 1 then
            e.flying = true                         -- takes off, flies to it
            e.forward = 1
            e.rotation = { pitch = math.deg(-math.atan2(to.y, far)) }
        else
            e.flying = false                        -- drops onto the perch
            e.forward = 0
            e.data.landed = true
        end
    end,
}
```

- `e.flying = true`: no gravity. `forward` and `strafe` move it along its look, `rotation.pitch` included: a negative pitch climbs, a positive one dives. At `forward = 1` it flies at its `speed` (by default the game's own air speed, about 4 blocks a second). With `forward = 0` it slows down and hovers.
- On the ground and still flying, it walks at its walk speed; a pitch up lifts it off.
- `e.flying = false`: it falls, lands, and walks again.
- A body with `can_fly` never takes fall damage, as the game's own fliers do, also when you move it with `e.velocity`.
- `e.flying = true` on a body without `can_fly` is an error. `e.flying` reads `false` there.
- **In water** every body swims along its look. A pitch up rises as fast as a jump in water does, a pitch down dives. At pitch 0 it swims and sinks as a mob does. Its speed in water is the game's swim speed, not `speed`. A flying body does not sink in water.
- `e.in_water` is `true` while it is in water: a crocodile can walk on land and swim when it is in.
- Clients see the pitch: a `looks = models.x` model tips with it (clients from 1.19.4); a vanilla look turns its head.

### a brain: on_think

AI is pack code. The engine gives the numbers and applies the answers. It
does not walk to a point or attack for you.

Use `on_think` for AI, not `on_steer`. The engine waits for `on_steer` two
milliseconds each tick, and a slow pack loses that decision. The engine never
waits for `on_think`, and it never loses its answer.

```lua
--!native
local zombie = game.entities.define {
    name = "walker", looks = "zombie", physics = "living", size = { 0.6, 1.95 },
    think_every = 0.25,                 -- seconds; each body thinks 4 times a second
    on_think = function(b)              -- one call for all the due bodies of this kind
        for i = 0, b.n - 1 do
            local o = i * 8             -- body i of a column is at byte i * 8
            local dx = buffer.readf64(b.player_x, o) - buffer.readf64(b.x, o)
            local dz = buffer.readf64(b.player_z, o) - buffer.readf64(b.z, o)
            buffer.writef64(b.yaw, o, math.deg(math.atan2(-dx, dz)))
            buffer.writef64(b.forward, o, if buffer.readf64(b.player, o) ~= 0 then 1 else 0)
        end
    end,
}
```

- `b.n` is the number of bodies in this call. Each other field of `b` is a
  `buffer` with one number (an f64, 8 bytes) for each body. Body `i` is at
  byte `i * 8`, for `i` from 0 to `b.n - 1`. A yes or no is 1 or 0. An id of
  nothing is 0.
- The engine sends the bodies after a tick. The answer goes on the bodies at
  the start of the next tick that has it: one tick later, or more for a slow
  pack. An answer is never dropped. A slow pack is never switched off.
- To change a value, write a new one. A value that you do not change stays
  as the body has it. A body keeps its intent until you change it.
- `think_every` is seconds, above 0 and at most 60. Without it, each body
  thinks each tick. The engine spreads the bodies of a kind over the ticks.
- An event makes a body think on the next tick, also when it is not due.
- `b` and its buffers are the same table and buffers in each call. Their
  numbers change. Keep your own memory in a table by `id`.
- `on_think` cannot wait: `task.wait` in it is an error.
- `on_think` is for `define`. `amend` refuses it. A kind without it costs
  nothing.
- `--!native` at the top of the file makes this loop fast where the server
  allows native code. The buffers are the form native code reads fastest.

| column | what it is |
|---|---|
| `id` | the entity id, as `e.id` and `world.entities()` give it |
| `x`, `y`, `z` | where its feet are |
| `health`, `age` | its health, and the ticks it has lived |
| `on_ground`, `in_water` | 1 or 0 |
| `hurt` | the damage it took since its last think; 0 for none |
| `hurt_by` | the id of the player whose hit it was; 0 for none |
| `landed` | 1: it came down on the ground after it was in the air |
| `blocked` | 1: it walked into a wall |
| `water` | 1: it went into water; -1: it came out; 0: neither |
| `touched` | the id of a player it began to touch; 0 for none |
| `player` | the id of the nearest player in survival or adventure; 0 for none |
| `player_x`, `player_y`, `player_z`, `player_dist` | where that player's feet are, and how far |
| `yaw`, `pitch` | where it looks. Write to turn it. |
| `forward`, `strafe` | its intent, -1 to 1. Write to walk. |
| `jumping`, `flying` | its intent, 1 or 0. `flying` is for a body with `can_fly`. |
| `vx`, `vy`, `vz` | its velocity. Write to push it by hand. |

- Each event is in one think only. The next think has it at 0 again.
- `citadel.budget().asks.kinds.think` counts the bodies: `asks` sent,
  `answered` applied, `late` applied more than one tick after they were
  sent. `missed` stays 0.
- Use `on_steer` only for an answer in the same tick, such as a vehicle that
  turns on a key. It can miss.
- Outside a hook, `e.forward`, `e.strafe`, `e.jumping` and `e.flying` on a
  world handle change the body at once.

#### a small steering library

The engine has no `move_to`. Copy this into your pack and change it as you
need. It turns smoothly, follows the points of `world.path`, jumps when a
wall blocks it, and aims a flier up or down.

```lua
--!native
-- steer.luau
local steer = {}

-- `from` turned toward `to` by at most `step` degrees.
function steer.turn(from: number, to: number, step: number): number
    local d = (to - from + 180) % 360 - 180
    return from + math.clamp(d, -step, step)
end

-- The yaw that looks from (x, z) to (tx, tz).
function steer.yaw(x: number, z: number, tx: number, tz: number): number
    return math.deg(math.atan2(-(tx - x), tz - z))
end

-- The pitch that flies up `dy` over `far` blocks: negative climbs.
function steer.pitch(dy: number, far: number): number
    return -math.deg(math.atan2(dy, far))
end

-- Body i of `b` walks the route { points = world.path(...), at = 1 }.
-- false when it is at the end.
function steer.follow(b, i: number, route, turn: number?): boolean
    local o = i * 8
    local x, y, z = buffer.readf64(b.x, o), buffer.readf64(b.y, o), buffer.readf64(b.z, o)
    local p = route.points[route.at]
    while p and (p.x - x) ^ 2 + (p.z - z) ^ 2 < 0.3 and math.abs(p.y - y) < 1 do
        route.at += 1
        p = route.points[route.at]
    end
    if not p then
        buffer.writef64(b.forward, o, 0)
        return false
    end
    local yaw = steer.turn(buffer.readf64(b.yaw, o), steer.yaw(x, z, p.x, p.z), turn or 45)
    buffer.writef64(b.yaw, o, yaw)
    buffer.writef64(b.forward, o, 1)
    local up = p.y > y + 0.5 or buffer.readf64(b.blocked, o) == 1
    buffer.writef64(b.jumping, o, if up then 1 else 0)
    return true
end

-- A flier of `b` aims at (tx, ty, tz): it flies there and looks up or down.
function steer.fly(b, i: number, tx: number, ty: number, tz: number)
    local o = i * 8
    local x, y, z = buffer.readf64(b.x, o), buffer.readf64(b.y, o), buffer.readf64(b.z, o)
    local far = math.sqrt((tx - x) ^ 2 + (tz - z) ^ 2)
    buffer.writef64(b.flying, o, 1)
    buffer.writef64(b.yaw, o, steer.turn(buffer.readf64(b.yaw, o), steer.yaw(x, z, tx, tz), 30))
    buffer.writef64(b.pitch, o, steer.pitch(ty - y, far))
    buffer.writef64(b.forward, o, if far > 1 then 1 else 0)
end

return steer
```

A chaser with it. It asks for a new path each second, or when it has none:

```lua
local steer = require("steer")
local routes = {}                       -- by body id
local chaser = game.entities.define {
    name = "chaser", looks = "zombie", physics = "living", size = { 0.6, 1.95 },
    think_every = 0.1,
    on_think = function(b)
        for i = 0, b.n - 1 do
            local o = i * 8
            local id = buffer.readf64(b.id, o)
            local r, age = routes[id], buffer.readf64(b.age, o)
            if buffer.readf64(b.player, o) == 0 then
                buffer.writef64(b.forward, o, 0)
            elseif not r or age > r.renew then
                local from = vec3(buffer.readf64(b.x, o), buffer.readf64(b.y, o), buffer.readf64(b.z, o))
                local to = vec3(buffer.readf64(b.player_x, o), buffer.readf64(b.player_y, o), buffer.readf64(b.player_z, o))
                routes[id] = { points = world.path(from, to, { size = { 0.6, 1.95 } }) or {}, at = 1, renew = age + 20 }
            end
            if routes[id] then steer.follow(b, i, routes[id]) end
        end
    end,
    on_remove = function(e) routes[e.id] = nil end,
}
```

### the handle

`world.spawn` returns a handle, `world.entities()` lists handles, and each
hook gets one:

```lua
it.id, it.name, it.alive, it.age
it.at                       -- vec3; writing it is a teleport
it.velocity                 -- vec3; writing it is steering by hand
it.on_ground, it.rotation, it.physics
it.health, it.max_health    -- health now; max_health is nil for an entity that is not alive (a mob or a living body)
it.origin                   -- the block it used to be, or nil
it.data                     -- your own record, saved with the chunk
it:push(vec3(0, 0.4, 0))    -- a shove, added to what it is already doing
it:settle()                 -- stop being an entity, be a block again where you stand
it:destroy()                -- gone on the next tick
it:nearby(8)                -- what else is within eight blocks, horizontally
it.forward, it.strafe, it.jumping   -- the intent fields: what it *wants* to do
it.flying                   -- intent: a can_fly body flies; see "flying and swimming"
it.in_water                 -- whether it is in water now
it.driver, it.riders, it.paint, it.scale, it:play(name, opts), it:stop(name)   -- a model entity's; see "vehicles"
```

`e.data` is a [data view](#data-views) for a **pack-defined entity**, including
one with `physics = "living"`. Nested writes persist through both callback and
world handles. It saves with the chunk only when the kind has `persist = "save"`.
Reading or assigning `.data` on a **built-in entity**, including an amended one,
raises an error: its engine-owned state is not a pack data record. Keep temporary
state for built-in entities in a pack table keyed by entity id; ids do not provide
a persistent identity across server restarts.

### selecting entities

`world.entities()` with no argument returns all entities. For a local query,
give a position and a radius. You can also filter by kind:

```lua
local cows = world.entities {
    near = vec3(8, 65, 8),
    radius = 16,
    kind = "cow",
}
for _, cow in cows do
    cow:push(vec3(0, 0.1, 0))
end

local allCows = world.entities { kind = "cow" }
```

- `near` and `radius` go together. They select a sphere, boundary included.
- Results are handles in ascending id order. Queued spawns are included; removed entities are not.
- `kind` is the handle's canonical name, with the pack namespace for a custom kind.
- Invalid options, a negative radius and non-finite numbers raise an error. An unknown kind returns an empty list.
- `entity:nearby(radius)` measures horizontal distance and excludes the entity itself.

`game.entities` gives a mob's native behaviour values:

```lua
local zombie = game.entities.zombie
print(zombie.behaviour)          -- "zombie"
print(zombie.profile.damage)     -- 5 in a0.1.0
print(game.entities.creeper.profile.ticks) -- 30 in a0.1.0
```

- Profiles are read-only. A write raises an error.
- A special behaviour without a shared profile returns `nil`.
- Profiles run no callbacks. To change gameplay, use `game.entities.amend(name, hooks)` and `game.entities.define(spec)`.

### what a missed deadline means here

Your hooks run outside the tick. Each tick, the engine sends your pack **one
batch** with all your due entities. It waits two milliseconds, then applies
the answers: `on_steer` before physics, `on_tick` after. The contract:

* **a hook reads the entity as it was at the start of that tick**; and
* **For custom kinds or `{ replace = true }`, a missed deadline keeps the last intent.** The entity keeps steering the
  same way. The miss is counted at
  `citadel.budget().asks.kinds["entity"].missed`.

| hook | a missed deadline means |
|---|---|
| `on_steer`, `on_tick` | Default amendments continue wrapped behavior. Custom kinds and explicit replacements keep their last intent; physics runs anyway. |
| `on_think` | nothing is missed: the engine does not wait. A slow answer lands on a later tick. See "a brain: on_think". |
| `on_damage` | **`"take"`**: the damage lands. A busy pack must not make its own entities invulnerable. |
| `on_spawn`, `on_load`, `on_remove` | the engine never waits on these. They are notifications, and their return value is not read. |

`on_remove` does **not** fire when your pack is removed.

A reload is not a missed deadline. If the new script no longer amends a kind,
the kind gets its wrapped behaviour back. Your own kinds, fuses included, keep
moving through a reload.

### two packs on one kind

Use `game.entities.amend(name, hooks, { priority = 10, replace = false })`.
Amendments run from lower to higher integer priority, regardless of pack name
or load order. Priority defaults to `0`. Two packs amending the same kind at
the same priority produce a load error naming both packs; choose distinct
priorities explicitly.

By default, wrapped behavior runs first, even if the hook omits `base` or
misses its deadline. Calling `base(e)` remains supported and never runs it
twice. Set `replace = true` explicitly to allow the hook to suppress the
wrapped steering/tick behavior; with this option, calling `base(e)` opts back
into it. The same options work with `game.entities.pig:amend(hooks, options)`.
Custom kinds made with `define` retain their existing `base` behavior.

## Items

An item is a name, or a table with its meta. Everything that takes an item
reads both.

```lua
"potion"                             -- just the item
{
    item = "potion",                 -- required in a table
    count = 2,                       -- 1 by default
    name = "Lime Laser",             -- text; never italic unless it says so
    lore = { "a laser follows you" },  -- lines under the name, grey unless they say; one text is one line
    color = colors.lime,             -- a potion's liquid
    dye = color(0.2, 0.5, 1),        -- leather armour's colour
    glint = true,                    -- the enchanted shine, with no enchantment
    canvas = c,                      -- a filled map of that canvas; then `item` may be left out
}
{ item = "player_head", skin = player.name }   -- a head with a face; see "head items"
```

With `canvas = c`, the item becomes `filled_map` unless you name another.

### head items

A `"player_head"` item shows a face when you give it a `skin`. It works
everywhere an item goes: a hotbar slot, a menu, a hand, a display, a chest.

```lua
player:hotbar{ [9] = { item = "player_head", skin = player.name, name = "Profile" } }
player:give{ item = "player_head", skin = "Notch" }
player:give{ item = "player_head", skin = { value = "ewogICJ0aW1l...", signature = "..." } }
```

- `skin` takes the same forms as a placed head (see "player heads"): a
  player's name, or `{ value = , signature = }`.
- The name of a player in the room uses the skin they joined with. This
  costs nothing.
- Any other name is looked up from Mojang once, in the background:
  - Clients from 1.20.5 look the name up themselves and show the face.
  - Older clients show a plain head the first time. Make the item again
    (for example, set the hotbar on the next join) and they show the face.
  - A name with no account shows a plain head and logs one line.
- The face stays with the item: in the player's file, in a chest, on the
  ground.
- `skin` on any other item is an error.
- Clients from 1.7 see the face. Bedrock clients see a plain head.

### items of your own

`id` makes an item the pack's own. The client draws the base item with its
`name` and `lore`. The server knows it by its `id` everywhere, across
restarts.

```lua
local COPPER = { item = "brick", id = "copper_ingot", name = "Copper Ingot" }
player:give(COPPER)                      -- count goes in the table: { ..., count = 4 }
player:held()                            -- { item = "brick", count = 1, id = "copper_ingot" }
player:count({ id = "copper_ingot" })    -- every copper ingot they carry
player:count("brick")                    -- plain bricks only, never a copper ingot
player:take({ id = "copper_ingot" }, 2)  -- up to 2 of them; answers how many it took
player:give{ item = "diamond_pickaxe", id = "drill", name = "Mining Drill", damage = 1200 }
```

The rules:

- Where a call *finds* an item (`take`, `count`, a recipe, a container):
  - A name matches the plain item only.
  - A table matches by the fields it names. `{ id = "x" }` is that pack
    item, whatever its base.
- A pack item stacks only with the same pack item. Only your own recipes
  (see "recipes") take it.
- `id` is a lower-case word, kept under your pack's name. Your ids read
  back bare, another pack's as `"pack:word"`. Either spelling works.
- `model` is the item definition that clients from 1.21.4 draw.
  `model = "copper_ingot"` is `assets/<pack>/items/copper_ingot.json`.
  `game.items.define` sets it. Set it by hand only for a file you shipped in
  `assets/`.
- `damage` is a tool's wear bar. `0` is new. Past its maximum, the tool
  breaks. Read it from `held()`; write it with `set_held`.
- The base item sets the look and what it does in a hand. A pack pickaxe
  mines. A pack block places that block, unless its `id` names a block of
  yours (see "Custom blocks").

### items with their own pictures

`game.items.define` returns an item table for anywhere an item goes:

```lua
local ingot = game.texture(16, 16)       -- a picture drawn in code, or a PNG file in the pack
ingot:rect(2, 6, 12, 5, "#d9822b")
ingot:rect(3, 6, 10, 1, "#f0a860")
local COPPER = game.items.define {
    name = "copper_ingot",                -- its id; the pack's namespace is added
    texture = ingot,                      -- or "textures/copper_ingot.png"
    label = "Copper Ingot",               -- its name; left out, "Copper Ingot" from the id anyway
    lore = { "Smelted from copper ore" },
}
player:give(COPPER)                       -- { ..., count = 4 } for more: COPPER is a plain table
player:take(COPPER, 2)                    -- an item table matches by its id
game.recipes.smelt{ input = ORE, result = COPPER }
```

- `looks` is the vanilla item underneath. Clients below 1.21.4 draw it. It
  sets what the item does in a hand.
  - Default: `paper` (stacks to 64, does nothing).
  - With `stack = 1`, the default is `carrot_on_a_stick`.
  - Name a pickaxe for a tool that mines, a sword for one that hits.
- `texture` is drawn flat in a hand and in the inventory. Vanilla items are
  16 by 16.
- Define items while the pack loads.

### drawing a texture

```lua
local t = game.texture(16, 16)            -- see-through until drawn on, 512 at most a side
local map = game.texture("textures/map.png")   -- a PNG file in the pack, 4096 at most a side
t:fill(color)                             -- every pixel
t:pixel(x, y, color)                      -- (0, 0) is the top left
t:rect(x, y, w, h, color)
t:frame(x, y, w, h, color)                -- a box's outline, one pixel wide
t:noise(x, y, w, h, { c1, c2, c3 }, seed) -- each pixel one of the colours: stone, bark, grain
t:sprite(x, y, { ".##.", "#..#" }, { ["#"] = colors.black }, 1)   -- pixel art, as on a screen
t:draw(other, x, y)                       -- another texture over this one; its see-through pixels skipped
t:copy()                                  -- a copy to draw on
```

A colour is any colour the API takes. `colors.transparent` is see-through.
Where a call takes a texture, a string names a PNG file in the pack.

### recipes

Add recipes at the top of `main.luau`, while the pack loads. A reload
replaces the pack's recipe list.

```lua
game.recipes.shaped{
    pattern = { "CCC", "CMC", "CCC" },    -- 1 to 3 rows of 1 to 3 letters; a space is an empty cell
    keys = { C = { id = "copper_cable" }, M = "iron_block" },
    result = macerator.item,              -- an item, with its count: { ..., count = 4 }
}
game.recipes.shapeless{ items = { "coal", "coal", { id = "iron_dust" } }, result = STEEL }
game.recipes.smelt{ input = { id = "copper_dust" }, result = COPPER }
```

- An ingredient is an item to match (see "items of your own"): a name, or
  `{ id = ... }`.
- A shaped recipe matches anywhere it fits in the grid, and mirrored.
- The 2x2 inventory grid takes recipes that fit in it. The crafting table
  takes all.
- Vanilla recipes are checked first. A pack adds recipes and never removes
  one.
- A furnace smelts a pack item only through a `smelt` recipe. No pack item
  burns as fuel.

```lua
player:give{ item = "potion", name = "Lime Laser", color = colors.lime, lore = { "30 seconds" } }
npc:hold{ item = "potion", color = colors.lime }
world.display{ kind = "item", item = { item = "potion", color = colors.lime }, at = vec3(0.5, 66, 2.5) }
```

The engine writes the meta in each client's format: NBT tags up to 1.20.4,
data components from 1.20.5. A field a version cannot show is left out. A
potion's colour needs 1.11. No other field has a version limit.

## Armour

What a player or an NPC wears.

```lua
player:wear{ head = "iron_helmet", chest = { item = "leather_chestplate", dye = colors.blue },
             legs = "chainmail_leggings", feet = "golden_boots" }
player:wear{ head = "carved_pumpkin" }   -- replaces all four: the three left out are bare
player:wear{}                            -- all off
npc:wear{ chest = "diamond_chestplate" } -- the same on an npc
```

`wear` fills the armour slots of a player or an npc. Each piece is an item (see "items"), so `dye` and `glint` work.

- The inventory, the body and the armour bar show the pieces. Armour does not reduce damage yet.
- Nearby clients draw the pieces from 1.8.
- Any item goes on the head. Other slots draw only armour made for them.
- On a pack server, only the pack takes armour off.
- On a survival server, these are the real armour slots. `wear` replaces their contents, and the player can take pieces off.

## Zones and raycasts

A zone tracks who is inside a box of blocks, once a tick. The other lookups
answer at once.

```lua
local goal = world.zone{ from = vec3(10, 64, 10), to = vec3(14, 66, 14),
    on_enter = function(player) message(player.name .. " scored", colors.lime) end,
    on_leave = function(player) end }
goal:contains(player)                -- boolean
goal:players()                       -- who is in it now
goal:destroy()

players.near(pos, 8)                 -- every player within eight blocks of a point
players.within(from, to)             -- every player inside a box of blocks, corners included

world.raycast(from, direction, 32)   -- the first block a ray meets within 32 blocks, or nil:
--   { block = vec3, face = "up" | "down" | "north" | "south" | "west" | "east" }
world.raycast(player.at + vec3(0, 1.62, 0), player:look())   -- what the player is looking at

world.sees(from, to)                 -- true when no block stops the line between the two points
world.raycasts(rays, out, n)         -- n lines at once, in buffers; see below
local block, sky, open = world.light_at(pos)   -- block light 0..15, sky light 0..15, open sky
world.path(from, to, { size = { 0.6, 1.95 } })  -- the points a body walks, a list of vec3, or nil
```

- `world.sees` and `world.raycasts` look as a mob looks: a block with a
  collision box stops the line, glass and leaves too. Water, lava, grass and
  flowers do not.
- `world.raycasts(rays, out, n)`: `rays` is a buffer with six f64 for each
  line: from x, y, z, then to x, y, z. `out` gets one f64 for each line: how
  far from `from` the first block is that stops it, or -1 when the line is
  clear. One call for all the bodies of an `on_think` is much cheaper than one
  call each.
- `world.light_at(pos)` gives three values: the block light, the sky light,
  and `true` when no block above stops the sky.
- `world.path(from, to, opts)` is the game's own search for a mob: four ways
  from each block, a step up of one block, a fall of at most `fall` blocks. It
  gives the middle of each block to walk on, from `from` to the block at `to`.
  The options: `size` (a number, or `{ width, height }`; 0.6 by 1.8),
  `swim = true` to go through water, `fall` (3), `range` (how far it may go
  from the goal; the distance plus 16), `budget` (the most blocks it looks at;
  2000). A search that stops early gives the part that came closest. `nil`
  when it found no step at all.
- A path costs the pack, not the tick. A short one costs some microseconds; a
  long one around a big wall costs more. Ask for a new one when the old one is
  old, not each think.

- `from` and `to` are block positions, in either order. Both corners are
  inside.
- A player is inside when their feet are.
- Disconnecting inside a zone runs `on_leave`.
- A zone ends with the script.

# Game logic

How a game runs: rooms, the rules a room simulates, events, and code split into modules.

## Rooms

A room is an isolated world with its own chunks and players. The globals `world`, `players`, `sound`, `fx`, `ui` and `commands` belong to
`rooms.main`. Every other room has them as fields.

```lua
local room = rooms.create{
    spawn_point = vec3(0.5, 65, 0.5),
    generate = function(chunk) chunk:fill(chunk.min, chunk.min + vec3(15, 0, 15), "stone") end,
}
player:move_to(room)          -- the client swaps worlds in place
room.ui.title{ title = "Welcome" }
room:message("A new round starts")   -- a chat line to everyone in this room
room.players.on_join(function(p) end)  -- fires after move_to as well
print(player.room == room)    -- rooms compare by identity; `player.room` is nil while moving
room:destroy()                -- when the last player left; players still in it keep the world
```

- The global `players.on_join` fires on connect, in the main room. A room's
  own fires on each move in. `players.on_leave` matches.

### Spawn points

`spawn_point` is the position where a player arrives. `spawn` is never a
position: it is the call `world.spawn` and the switch of an entity kind.

```lua
print(world.spawn_point)                  -- this room's point
world.spawn_point = vec3(8.5, 66, 8.5)    -- move it
room.spawn_point = vec3(0.5, 80, 0.5)     -- the same field of a different room

player.spawn_point = vec3(20.5, 65, -7.5) -- this player respawns here
print(player.spawn_point)                 -- vec3, or nil for the room's point
player.spawn_point = nil                  -- the room's point again
```

- `citadel.yml` has `spawn_point: [x, y, z]` for the main room.
  `rooms.create { spawn_point = vec3(..) }` sets it for a new room.
- A write to `world.spawn_point` or `room.spawn_point` changes where a player
  arrives: on a join, on a respawn, and on a move to the room. The clients in
  the room get the new compass target.
- The write is not stored. After a restart the room has the point of
  `citadel.yml` or of the stored world again.
- The write does not move the chunks that stay loaded, the spawn protection,
  or the area where no mob spawns by itself. Those stay at the first point.
- `player.spawn_point` is the player's own respawn point. A bed sets the same
  value where the game has beds. A point that a pack sets needs no bed. The
  engine keeps the block of the position: `vec3(20.2, 65, -7.9)` reads back as
  `vec3(20.5, 65, -7.5)`.
- `player.spawn_point = nil` also removes a point that a bed set.
- Manifest keys and `rooms.create` options are checked: an unknown key is
  an error naming the field and the accepted keys.

## Dimensions

A dimension is a world of the server's group, beside the main one: its own
chunks, its own type, its own folder. A Beta 1.6+ server in `mode: full` has
the Nether; a pack declares more in `citadel.yml`:

```yaml
dimensions:
  dungeon:                          # castle:dungeon, saved to world_dungeon
    type: { has_skylight: false, has_ceiling: true, weather: false }
    world: script                   # or void
```

```lua
local dungeon = world.dimension("dungeon")    -- that world's `world` table; "minecraft:the_nether" works too
dungeon.on_generate(function(chunk) chunk:fill(chunk.min, chunk.min + vec3(15, 0, 15), "bedrock") end)
routes.add{ from = "overworld", to = "dungeon", trigger = { block = "light_blue_carpet", ticks = 1 }, placement = { x = 0.5, y = 65, z = 0.5 } }
routes.add{ from = "dungeon", to = "overworld" }  -- no trigger: only player:travel takes it
player:travel("dungeon", vec3(0.5, 65, 0.5))      -- to a point, or without one to its spawn
```

- `type` fields, all optional and starting from the main world's:
  `has_skylight`, `has_ceiling`, `weather`, `ultrawarm`, `bed_works`,
  `respawn_anchor_works`, `coordinate_scale`, `fixed_time`, `effects`.
- A trigger block fires after `ticks` ticks standing in it (1 by default);
  after a trip the player steps out for half a second before it fires again.
- A player's inventory and health go with them; their file stays the main
  world's. Dying anywhere respawns them in the main world.

## Room rules

On a pack server, nothing hurts a player until the pack turns on a rule. The anticheat is the exception: it is on everywhere until a pack turns it off.
Rules are set one at a time, per room. A parkour, for example, turns on fall
damage only:

```lua
world.rules{ fall = true }                       -- landings past three blocks cost health
world.rules{ damage = true }                     -- the world hurts: void, fire, lava, drowning, suffocation, cactus
world.rules{ hunger = true }                     -- the food bar runs down and, when full, heals
world.rules{ anticheat = false }                 -- on by default: moves and hits are checked for cheats, see below
world.rules{ day_cycle = true }                  -- the sun moves: see "the time of day"
world.rules{ redstone = false }                  -- on by default: redstone signals move, see below
world.rules{ survival = true }                   -- the whole game: see below
world.rules()                                    -- { survival = false, fall = true, damage = false, hunger = false, anticheat = true, day_cycle = false, redstone = true }
room.world.rules{ fall = true, damage = true }   -- per room; a room made by rooms.create starts with only the anticheat and redstone on
```

A `mode: full` server has them all on. A pack can turn one off.

A rule is `true` or `false`. A rule that you leave out keeps its value, and
so does a rule you write as `nil`. Any other value is an error:
`world.rules{ fall = 0 }` and `world.rules{ fall = "off" }` stop the script.

`redstone` is on in every room until a pack turns it off. With it off, no
signal moves: a lever lights no wire, a piston stays in, a pack block's
`power` gives nothing and `block.powered` reads `false`. What was lit when
the rule changed stays as it is until something beside it changes.

`anticheat` checks what each Java player's client claims:

- A player who flies, runs too fast, sends moves faster than the game ticks, or walks through full blocks goes back to the last legal position.
- A claim to stand on nothing does not prevent fall damage.
- A hit on something the player does not look at, or faster than 20 per second, does not land.
- After enough failed checks in a short time, the engine removes the player. The message names the check.
- The flight check skips creative and spectator players, a player who may fly (`player.can_fly`), a rider and a dead player.
- `player:push` and a movement effect (`speed`, `jump_boost`, `levitation`, `slow_falling`, `dolphins_grace`) exempt the player while they last. `player:teleport` is always allowed.
- A pack that moves players in any other way turns `anticheat` off: `world.rules{ anticheat = false }`.

`survival` gives the room to the engine's survival, as on a `mode: full`
server:

- A broken block drops its normal drops.
- A block the world breaks by itself drops them too: a torch whose wall is
  gone, a leaf that decays, a block an explosion or a piston breaks, sand
  that cannot land.
- Placing uses up the stack.
- The inventory and a crafting table craft.
- A death drops the inventory, and the respawn button works.
- The engine saves the player's inventory.
- It also turns on `fall`, `damage`, `hunger`, `anticheat` and `day_cycle`.

Without `survival`, a dig reaches no block, and a block the world breaks by
itself leaves no item. `game.block(name).drops = true` switches one block of
the game back on (see "Blocks"). A pack block still leaves the drops its
definition lists; `drops = "table"` is the game's own drop and leaves
nothing. A survival pack puts `world.rules{ survival = true }` at the top,
and runs the same on either kind of server.

Anything that is not a rule is the pack's job: `player:damage` for a hit,
`player.health` to heal, `players.on_death` and `players.on_respawn` for what
happens next, and `hit.player` in `players.on_click` for one player hitting
another:

```lua
world.rules{ fall = true }
players.on_click(function(player, hit)
    if hit.button == "left" and hit.player then
        hit.player:damage(2)
        hit.player:push(player:look() * 0.5 + vec3(0, 0.3, 0))
    end
end)
```

## Game events

On a `mode: full` server, these events fire after the world changes. The
engine ignores return values, and a slow pack does not delay the tick. To
**veto** a break or a place, see [below](#saying-no).

```lua
world.on_block_break(function(player, pos, block) end) -> connection
world.on_block_place(function(player, pos, block) end) -> connection
--   block is the canonical name: what was there for a break, what was put
--   down for a place
world.on_entity_spawn(function(entity, name) end) -> connection   -- a mob appeared; entity is the handle
world.on_entity_death(function(id, name) end) -> connection    -- a mob died; it is gone, so id and name is all there is
players.on_pickup(function(player, item, count) end) -> connection
players.on_drop(function(player, item, count) end) -> connection
```

`player` is `nil` when:

- the world dropped the stack (a leaf decays, a mob dies, an explosion);
- the player has already left the room.

```lua
world.on_block_break(function(player, pos, block)
    if block == "diamond_ore" and player then
        message(player.name .. " struck diamond", colors.cyan)
    end
end)
```

`world.on_entity_spawn` fires for mob kinds only. `world.on_entity_death`
fires for mob kinds and for a pack's living body (`physics = "living"`). They
do not fire for an arrow, an item or another pack kind.

On a `mode: lite` server, `world.spawn` of a mob kind fires `world.on_entity_spawn`. A mob
that spawns by itself (its kind has `spawn = true`) fires it on every game
version that has natural spawning (a0.1.4 and later). A spider jockey fires
it two times: for the spider, then for its rider.

## Cancelling events

`players.on_break` and `players.on_place` run **before** the world changes. A
handler that returns `false` cancels the action. The player's client gets the
correct state.

```lua
players.on_break(function(player, pos, block) return false end) -> connection
players.on_place(function(player, pos, block) return false end) -> connection
--   player is the handle, pos is the block, block is its canonical name:
--   what is about to be broken, or what is about to be put down
players.on_damage(function(player, hit) return false end) -> connection
--   asked before damage lands on a player; false refuses all of it
--   hit.amount   the damage, in half hearts, before armour
--   hit.cause    "fall", "drown", "suffocate", "void", "lava", "fire", "cactus",
--                "starve", "attack", "shot", "blast" or "magic"
--   hit.by       the player who hit, or who shot the arrow; nil for anything else
--   hit.kind     the kind's name ("Skeleton") when a mob did it; else nil
```

```lua
-- No friendly fire, and nobody is hurt at the spawn.
players.on_damage(function(player, hit)
    if hit.by and hit.by.data.team == player.data.team then return false end
    if player.at:distance(SPAWN) < 8 then return false end
end)
```

- A refused arrow bounces off, as off a creative player.
- A pack's own `player:damage` is not asked about, in this pack or another.
- An entity of a pack's own has the same question as a hook: `on_damage`
  in `game.entities.define`, which answers `"take"` or `"ignore"`.

```lua
-- A spawn area nobody digs in.
players.on_break(function(player, pos, block)
    if math.abs(pos.x) < 16 and math.abs(pos.z) < 16 then
        player:message("not here", colors.red)
        return false
    end
end)
```

- Only `false` is a veto.
- A handler that returns **nothing** allows the action.
- A handler that *errors* is not a veto. It counts as a missed deadline.

Also:

* **The observe-only events come after.** A vetoed break never reaches
  `world.on_block_break` or `world.on_block_place`.
* **Across packs, any `false` wins.** One `false` cancels the action.
* **These handlers can delay the tick.** The engine waits **two milliseconds**
  for your pack, then stops waiting. `task.wait` and anything that blocks are
  errors here.

### what a missed deadline means

Each hook the engine waits on states what a missed deadline does:

| hook | a missed deadline means | why |
|---|---|---|
| `players.on_break` | **the break is denied** | Protection fails closed on timeout, error, overflow, or a disabled handler. |
| `players.on_place` | **the place is denied** | The same protection guarantee applies. |
| `players.on_damage` | **the damage is denied** | The same protection guarantee applies. |

The rule: **fail open only where the default is safe**. A pack block's own
`on_break` (it comes with pack blocks) fails *closed* to the drops its
definition declares.

The engine counts misses at `citadel.budget().asks.kinds["break"].missed`.
After enough misses, it stops asking your pack for that kind and logs this
once. See "Limits and reload".

## Modules and tasks

Split a pack into modules, and run work later or at the same time.

```lua
local venue = require("venue")      -- loads <pack>/venue.luau once; its return value is the module
local elapsed = task.wait(seconds) -- seconds actually waited, not pack uptime; seconds defaults to 0
local co = task.spawn(fn, ...)      -- starts now; returns a thread
local co = task.delay(seconds, fn, ...) -- starts after the delay; returns a thread
local co = task.defer(fn, ...)      -- starts after this callback yields or returns; returns a thread
task.cancel(co)                     -- closes the thread and cancels its pending wakeup
```

`spawn`, `delay` and `defer` accept either a function or a suspended coroutine,
forward all arguments (including nils), and return that coroutine. `spawn`
runs immediately until the task yields or returns. `task.cancel` also works
after the task has called `task.wait`; canceling a running thread is an error.
Canceling a task stops its script, but cannot undo I/O already submitted.

`wait` and `delay` use elapsed real time in both full and lite mode. Unlike
Roblox's heartbeat-based scheduling, they resume once the requested time has
passed and the script scheduler can run them, without rounding to Minecraft's
50 ms ticks. Zero or negative seconds yield until the next scheduler turn.
Use `time.on_tick` for work tied to world ticks. The actual wait may be longer
under load. Durations must be finite and within the supported clock
range; invalid values raise catchable errors. `time.every` remains a repeating
timer returning a connection, and can cancel itself inside its callback.

**Initialization exception:** tasks spawned, deferred or delayed while
`main.luau` loads start only after initialization commits. This preserves the
pack's atomic startup. The top level may `task.wait`, but cannot wait for one
of those child tasks to finish before startup.

Ordinary event callbacks and `main.luau` may call `task.wait`. Synchronous ask
handlers and a module's top level may not. `require` resolves from the pack
root, caches by canonical file path, rejects cycles, and rejects symlinks that
lead outside the pack. A module returning nil is cached as true.

# Data

What survives a restart, what the whole experience shares, and the limits a pack runs in.

## Storage

`storage` keeps small per-pack values across restarts and reloads: numbers,
strings, booleans and plain tables of those. It saves to
`<pack>/data/storage.json` shortly after each change. Saves atomically replace
the file after syncing a temporary file, and preserve the previous valid value
in `storage.json.bak`. A corrupt or unreadable store prevents the pack from
loading and names the affected path; it is never silently replaced with an
empty store. If recovery is needed, stop the pack, keep the damaged file for
inspection, and restore the backup to `storage.json`.

`storage.status()` returns `{ pending: boolean, error: string? }`. A write
failure remains visible and is retried. `storage.flush()` yields until the
current values are saved, or raises the write error. Call it from a callback
or `task.spawn`, after initialization. `storage.set` changes memory immediately;
unflushed changes can still be lost if the process crashes.

```lua
local best = storage.get("best." .. player.name) or 0
if score > best then storage.set("best." .. player.name, score) end
storage.set("best." .. player.name, nil) -- forgets it
storage.keys("best.")                    -- every key with that prefix, sorted; storage.keys() is all of them
```

Strings and record keys in JSON-backed storage must be valid UTF-8; invalid
bytes raise an error instead of being replaced. Use `stores.open():blob_put` for
binary data. The UTF-8 rule also applies to persistent entity and block data
and other JSON-backed APIs.

A value it cannot hold is an error that names it, never a changed copy:

```lua
local t = { 1, 2 }; t.total = 3
storage.set("score", t)
-- error names score and total: mixed lists and records have no JSON shape.

storage.set("tick", function() end)
-- error: storage cannot save tick: a function is not a JSON value...
```

- Records use string keys; lists must be contiguous from index 1. A table cannot mix the two.
- Numbers must be finite, and cyclic tables raise an error before changing stored data.
- Persistent data views are accepted directly; reads return detached plain tables.
- Only `nil` deletes. `{}` saves and reads back as an empty table.

## Shared stores

`stores` keeps facts and player-owned binary blobs outside disposable instance worlds.

On Minefort, a development workload and all instances of its experience share one store. A pack cannot choose another store. When `CITADEL_STORE` names a socket, that socket must work or the call fails.

**Without a socket, data lives in files that survive a restart.** Every local run works this way.

- Facts are in `data/store/00000000-0000-0000-0000-000000000000.json`.
- A blob is a file under `data/store/blobs/<player-uuid>/00000000-0000-0000-0000-000000000001/`.
- Writes are atomic. A killed server keeps the previous value.
- `store_dir` in `citadel.yml` moves that directory. Two servers on one laptop need two directories.
- The first call logs which store opened, and where.

```luau
local scores = stores.open()
players.on_join(function(player)
    local visits = scores:increment("visits", 1)
    player:message("Visit number " .. tostring(visits))
end)
```

Every call yields while the I/O runs. Other callbacks continue.

- Call from scripts, callbacks or tasks. Do not call from synchronous ask handlers or at module initialization.
- A pack can have up to 32 pending requests.
- The `storage` API stays a local per-pack JSON file, even in a published world.

The calls:

- `stores.open()` returns the experience's store. Passing an id is an error.
- `handle:get(key)` returns `(value, version)`. Version zero means absent.
- `handle:set(key, value, if_version, lease?)` returns the new version.
- `handle:delete(key, if_version, lease?)` removes a value.
- `handle:increment(key, by)` atomically increments a number, starting at zero.
- `handle:list(prefix?, cursor?, limit?)` returns `(keys, next_cursor)`.
- `handle:blob_get(player_uuid, key)` returns `(binary_string_or_nil, version)`.
- `handle:blob_put(player_uuid, key, bytes, if_version, lease?)` returns the new version.
- `handle:blob_delete(player_uuid, key, if_version, lease?)` deletes a blob.
- `stores.blob_list(player_uuid)` returns entries across all blob stores in this scope.
- `stores.lease(key, holder, ttl_ms)` returns a fencing token.
- `stores.renew(key, token)` and `stores.release(key, token)` maintain a lease.

Facts and blobs have separate keys: a fact `"world"` and a blob `"world"` are different values.

Limits:

- Keys: at most 256 bytes. Facts: at most 1 MiB. Blobs: at most 32 MiB.
- Hosted storage per experience: 512 MiB, and 1 MiB more for every Java player who has ever joined it. There is no limit on how many values. Each player may have at most 1,000 blobs.
- 100,000 issued lease tokens. Leases last up to one hour.
- Hosted blobs are not in world archive backups.

`pcall` preserves the value passed to `error`, including tables, numbers and
booleans. Native binding errors remain readable strings. Store errors reach
`pcall` as a table:

- A version conflict is `{err="conflict", version=current_version}`.
- A stale fencing token is `{err="held", by=current_holder}`.

## Shop

`shop` sells this experience's products for Gems. The owner creates products on minefort.com, each with a key such as `vip`. The pack draws its own shop and asks Minefort to offer a product.

**The player says yes or no in Minefort's own dialog, not in the pack.** The pack learns only whether a purchase was paid. It never sees the player's Gems, the price or a reason.

```luau
players.on_join(function(player)
    if shop.owns(player, "vip") then
        player:message("Welcome back, VIP")
    else
        shop.prompt(player, "vip") -- Minefort shows its dialog
    end
end)

shop.on_paid(function(purchase)
    -- Hand the item over here. Returning without an error marks it delivered.
    for _, player in players.list() do
        if player.uuid == purchase.player then player:message("Thanks for buying VIP") end
    end
end)

shop.on_declined(function(purchase)
    -- The player said no, or did not answer. Close the pack's own shop screen.
end)
```

- `shop.prompt(player, product)` returns a request id, or nil when Minefort did not offer it. A player or a uuid string.
- `shop.owns(player, product)` returns whether the player owns a pass.
- `shop.on_paid(fn)` calls `fn({request, player, product})` for each undelivered paid purchase. It runs on the server the player is on: an experience has many servers, and each one hands over only to its own players. A purchase for a player who is not online waits until they join one. At least one active paid handler must complete successfully, and all active paid handlers must succeed, before the purchase is acknowledged. With no paid handler, or if one raises an error, it stays pending. An `on_declined` listener alone never acknowledges a paid purchase. Delivery can repeat after a failure or restart; use `purchase.request` as a durable idempotency key when granting a reward.
- `shop.on_declined(fn)` calls `fn({request, player, product})` when the player said no or did not answer.
- A product key is 1 to 32 characters of `a-z`, `0-9`, `_` and `-`. Another key is an error.

Calls yield, like `stores`. Only experiences in the Minefort Creator Rewards Program have the shop. Elsewhere, and in local runs, `prompt` returns nil and `owns` returns false.

After an error, read again. After an I/O timeout, a write may have committed. Retry only versioned writes, never an increment. A world release rollback does not rewind shared facts or blobs.

## Network

`network` is for an experience made of more than one server. Such an experience is a **network**. Each server in it is a **member**. One member is the **default**: players land on it. Every other member runs only when a pack asks for an **instance** of it.

An instance has a **label**. One member can run in several ways, such as `2v2` and `4v4`. The label says which. Minefort stores the label and filters on it, and does nothing else with it.

**Any server of the network can call `network`.** The pack names a member and a label. Minefort decides the network, the instance's id and where the instance runs.

```luau
-- The default member: a place where players pick how to play.
-- This author calls an instance of "bedwars-arena" an arena.
local waiting = {} -- instance id -> the players who go there when it is online

commands.add("join <label:word>", function(player, args)
    local arena, why = network.find{
        label = args.label,   -- "2v2"
        party = player,       -- room for the player's whole party
        start = { member = "bedwars-arena", slots = 8, data = { map = "castle" } },
    }
    if not arena then return "No arena now: " .. tostring(why) end
    if arena.state == "online" then
        player:connect(arena.id)
    else
        -- It is still starting. Keep the player here until it is online.
        waiting[arena.id] = waiting[arena.id] or {}
        table.insert(waiting[arena.id], player)
    end
end)

network.on_instance_change(function(instance)
    if instance.state ~= "online" then return end
    for _, player in waiting[instance.id] or {} do player:connect(instance.id) end
    waiting[instance.id] = nil
end)

network.on_instance_stop(function(id) waiting[id] = nil end)
```

```luau
-- The member "bedwars-arena": it says how much room it has.
local me = network.info()                 -- `me.id` is nil on a server that is not an instance
local map = me and me.data and me.data.map or "castle"

players.on_join(function()
    if me and me.id then network.status{ open = math.max(0, me.slots - #players.list()), status = "waiting" } end
end)
-- When the round starts: network.status{ open = 0, status = "playing" }
-- When the round ends, each player goes back to the default member:
--   player:connect(me.network)     -- the name of the network
```

The calls:

- `network.start{ member, label, slots, data? }` starts an instance of `member`. It returns `{id, state}` at once, with `state = "starting"`: the instance comes online later. `slots` is the number of players the instance takes. `data` is the pack's own value for the instance, read there with `network.info()`.
- `network.find{ label, players?, party?, start? }` returns `{id, state}` for the instance to send `players` players to, or nil when no instance has room.
  - It picks an `online` instance with that label and that much `open`, the fullest first.
  - The room is held for 10 seconds, so two calls do not both get the last place.
  - `players` is 1 unless you set it.
  - `party` is a player, or their uuid. When they lead a `/party`, Minefort holds room for every member. Connect the leader, and the party follows them there. A player who leads no party needs room for one.
  - With `start = { member, slots, data? }`, Minefort starts an instance when none has room, and holds the room on it. The `state` is then `"starting"`.
  - Use `find` with `start`, not `find` and then `start`. The default runs on many servers, and each would start its own instance.
- `network.stop(id)` stops an instance of this network. It returns `true` when Minefort accepted it.
- `network.info()` returns `{network}` on every server of a network. `network` is the name of the network.
  - On an instance it returns `{network, id, member, label, slots, data}`.
  - `id` is nil on a server that is not an instance.
- `network.status{ open, status?, meta? }` says where this instance is. It returns nothing and does not yield.
  - `open` is the number of players the instance takes now. `0` closes it to `find`.
  - `status` is the pack's own word, such as `"waiting"` or `"playing"`.
  - `meta` is the pack's own value. Other servers of the network read it.
  - Minefort takes one status a second. The first call goes at once. Of the calls in the second after it, only the last goes.
- `network.on_instance_start(fn)` calls `fn(instance)` when an instance is first seen: started, or running when this server began to listen. It returns a connection.
- `network.on_instance_change(fn)` calls `fn(instance)` when an instance's `state`, `open`, `status` or `meta` changes. It returns a connection.
- `network.on_instance_stop(fn)` calls `fn(id)` when an instance is gone. It returns a connection.
- `network.online(label?)` returns how many play on this network: on the platform's hub, everyone on Minefort; on any other network, its members and their instances. With `label`, only the players in that mode's games, every region's. An answer is kept for 5 seconds, so a scoreboard can ask on every redraw. It returns nil and why when Minefort did not answer.
- `network.instances(label?)` returns everything this network runs, as this experience sees it: first its own servers that run all the time, online and taking players, as `{id, name, state, players, region}` (on the platform's hub, the hubs), then the network's games started on demand, each the instance table below. With `label`, only that mode's games: `network.instances('4v4v4v4')`. `id` is what `player:connect` takes. Never another network's. It returns nil and why when Minefort did not answer.
- `network.browse(view, options?)` finds other networks, and only the platform's hub may ask:
  - `view` is `"search"` (what matches `query`: names as they are typed, and domains), `"for-you"` (more of what `player` plays, busiest first, none of their recent ones), `"recent"` (where `player` played last, newest first) or `"featured"` (the busiest). Each row is a network: `{id, name, category, motd, icon, players, maxPlayers, state}`, and `id` is what `player:connect` takes. A network is one row, however many servers it has. It returns one page of 6 rows and how many there are in all: `local rows, total = network.browse('featured', { page = 2 })`.
  - `options` is `{ player?, query?, page?, category?, online?, ids?, sort?, also? }`. `player` is a player or a uuid, and only `"for-you"` and `"recent"` need it. `page` is from 1, and 1 when left out.
  - Minefort narrows and orders before it pages, so a page and the total always agree: `category` (`"pvp"`, `"survival"`…), `online = true` for what is up now, `ids` (at most 64 row ids, such as a player's favorites) and `sort` (`"players"` or `"name"`; the view's own order when left out). `"recent"` takes none of these.
  - `also = { recent = true, favorites = ids }` brings a board's sidebar in the same round trip, as a third value: `local rows, total, side = network.browse('for-you', { player = p, also = { recent = true, favorites = saved } })`. `side.recent` and `side.favorites` are each `{ rows, total }`; `side.recent` is `false` for a player who is not on this hub.
  - On a refusal it returns nil and why: `"unsupported"` anywhere but the platform's hub, `"not-here"` for a player who is not on this hub, `"unavailable"` when Minefort's search is down, or `"timeout"`. It is a round trip to Minefort, so call it from a script or callback.

An instance table:

| Field | Set by | Meaning |
|---|---|---|
| `id` | Minefort | The instance's name. `player:connect` takes it. |
| `member`, `label` | the pack that started it | Which member, and which label. |
| `state` | Minefort | `"starting"`, then `"online"`, then `"stopping"`. |
| `open` | the instance | The number of players it takes now. |
| `status` | the instance | Its own word, or nil. |
| `players` | Minefort | The number of players on it. |
| `meta` | the instance | Its own value, or nil. |

**`network` does not move players. `player:connect(id)` does.** The instance's `id` is the server name it takes. The name of the network, `network.info().network`, sends a player back to the default member. Do not send a player to an instance that is `"starting"`: keep the player until the instance is `"online"`.

**Events come to the default member's servers only.** Call `network.instances()` once at the start, then keep the list from `on_instance_start`, `on_instance_change` and `on_instance_stop`. An event can be lost. Call `network.instances()` again, once a minute at most, to repair the list.

**A failed call returns nil and a reason.** `start`, `find` and `info` return `nil, reason`. `list` returns `{}, reason`. `stop` returns `false, reason`. The reason is Minefort's word, or one of these:

- `"unavailable"`: there is no network here. Every local run answers this.
- `"io"`: the request was not sent.
- `"timeout"`: no answer came in 35 seconds. A `start` may have happened.

`find` returns `nil` with no reason when no instance has room.

Limits. A value out of these is an error, and nothing is sent:

- `label`: 1 to 32 characters of `a-z`, `0-9` and `-`.
- `member`: 1 to 40 characters of `a-z`, `0-9` and `-`.
- `slots`: 1 to 200. `players`: 1 to 64. `open`: 0 to 200.
- `data`: at most 4096 bytes as JSON. `meta`: at most 512 bytes as JSON.
- `status`: at most 32 characters.
- An unknown field in a table is an error.
- A network has at most 20 instances in a region, and one `start` a second.
- Minefort removes an instance with no players for 60 seconds after its first player, or for 5 minutes without one.

Calls yield, like `stores`, but for `status` and the three events. Call from scripts, callbacks or tasks.

## Hub

`hub` is what Minefort tells its own hub: the portals of the experience
grounds and the staff. Never the servers or the hubs: the hub browses them
with `network.browse`, and its hubs with `network.instances`, and asks the
count with `network.online`. On a server that is not a hub, every
list is empty.

```lua
task.spawn(function()
    for _, s in network.browse('featured') or {} do print(s.name, s.players) end
    for _, e in hub.experiences() do print(e.slot, e.experience) end
    for _, h in network.instances() or {} do print(h.name, h.players) end
    print(network.online())
end)
```

- `hub.role(player)` returns the player's rank on Minefort: `"owner"`, `"admin"`, `"moderator"` or `"builder"`, and nil for everyone else. It also takes a uuid, with or without dashes.
- Minefort sends the ranks every minute. Anywhere but a hub, they are nil.
- `hub.role(player)` returns the player's rank on Minefort: `"owner"`, `"admin"`, `"moderator"` or `"builder"`, and nil for everyone else. It also takes a uuid, with or without dashes. Minefort sends the list every minute, so a new rank reaches the hub within one. Anywhere but a hub, it is nil.
- `hub.experiences()` returns a list of `{slot, experience, title, pitch, icon, banner, players}`. `experience` is the name `/play` takes. A slot that is not in the list has no experience.
- A `banner` is a 1024×512 PNG its creator uploaded and Minefort checked: 8 by 4 maps. Read it with `http.get(banner, { cache = 86400 }):image()`; a new banner has a new URL, so the cache never shows an old one.
- `hub.rent(player, slot, product, experience)` offers a portal of the grounds for Gems, like `shop.prompt`: `product` is one of the hub's rentals, such as `portal_24h`, and `experience` the name `/play` takes of any published experience, which the portal then leads to. It returns a request id, or nil; `shop.on_paid` hands the purchase over. Renting your own portal again adds time, and may leave `experience` out to keep what it shows.
- `hub.point(player, slot, experience)` turns the player's own live portal to another published experience, as often as they like. It returns whether it did.
- Minefort decides who may rent or point what: a stand someone else holds, or a name that is no published experience, is a no. Anywhere but its hub, every answer is no.
- Minefort keeps the lists up to date. The first call of `experiences` waits at most two seconds for them, so call it from a task.

## HTTP

`http.get` fetches a URL: map tiles, a leaderboard, any public API.

```lua
local res = http.get("https://tile.example.org/15/9649/12315.png", {
    query = { key = "abc" },             -- added to the URL, encoded
    headers = { accept = "image/png" },
    timeout = 15,                        -- seconds, 1 .. 60; 15 is the default
    cache = 86400,                       -- seconds a 200 answer is kept on disk; left out, nothing is kept
})
res.ok        -- true for a 2xx status
res.status    -- 200; 0 when no answer came
res.error     -- why no answer came, or nil
res.body      -- the answer, a string
res.headers   -- { ["content-type"] = "image/png", ... }, names in lower case
res:json()    -- the body as a table; an error when it is not JSON
res:image()   -- a PNG body as { width, height, pixels }; pixels is a buffer, 4 bytes (RGBA) a pixel, row by row
```

- The call waits, like `task.wait`. Events, other callbacks and other chunks
  run during the wait. Call it from a script or a callback, not from the top
  level of a module.
- Transport failures return `res.ok = false`. Invalid arguments or exhausted
  request slots raise errors. `timeout` and `cache` must be finite; `timeout`
  is clamped to 1–60 seconds, and negative `cache` means zero.
- Only `http` and `https`, and only GET. An answer is at most 16 MiB.
- A pack can have 64 requests without an answer. Eight are on the wire at
  the same time.
- A server's packs send 600 requests in a minute at most, all packs
  together. Over that, a request waits for room, and fails when its
  `timeout` ends first. An answer from the cache does not count.
- A host can turn off private and loopback addresses (see below). Such an
  address is then an error in `res.error`, also after a redirect.
- `cache` keeps the body in `<pack>/data/http/`. A cached answer has status
  200 and no headers. Use it for data that does not change, such as tiles.
- A `range` header gets a part of a file (`headers = { range = "bytes=0-126" }`).
  The status is then 206, and the cache keeps each range by itself.
- A gzip body arrives undone, with the server's `content-encoding: gzip` or
  without it. A tile cut out of an archive is gzip without the header.
- `res:image()` reads PNG with 8 bits a channel, not interlaced.

The host decides whether packs get this, with the environment the server
starts in. A pack cannot change it, and the server's `citadel.yml` cannot:

```sh
CITADEL_DISABLE_HTTP=true         # http.get is off for every pack; res.error then says so
CITADEL_DISABLE_HTTP_LOCAL=true   # no private or loopback address: a pack cannot reach the host's own network
```

### a socket

`http.socket` opens a WebSocket and keeps it open. Use it for what a server
says the moment it happens, such as a chat line or a score, where `http.get`
would ask again and again.

```lua
local socket = http.socket("wss://live.example.org/room/7", {
    headers = { authorization = "Bearer abc" },   -- sent with the handshake
    on_message = function(message)
        local event = message:json()               -- or message.text, the message as it came
        if event.kind == "chat" then message(event.author .. ": " .. event.body) end
    end,
})
socket.open          -- true while the connection is up
socket:send("hello") -- queues text; true if queued, false if closed or full
socket.error         -- terminal queue overflow, or nil
socket:cancel()      -- closes it for good
```

- When the connection ends or cannot be made, the engine dials again every 3
  seconds. The log says so once. The pack gets no event for it: read
  `socket.open`. Receive-queue overflow is terminal and does not reconnect.
- A socket gives no message twice and none from before it opened. For what
  was said before, ask with `http.get` first.
- `on_message` runs on a tick, with the tick budget of any callback. At most
  32 messages of a socket go to the pack in a tick; the rest wait.
- Each direction queues at most 256 messages or 4 MiB per socket. If the
  incoming queue fills, the socket closes permanently and `socket.error`
  explains why. Cancel its handle, then create a new socket after handling
  the gap. The outgoing queue returns false when full. A true send result means queued, not delivered.
- Only `ws` and `wss`. A message is at most 1 MiB; a larger send is an error.
  A binary message arrives as text with invalid UTF-8 replaced.
- A pack can have 8 sockets. A socket ends with the script.
- The host's two switches for `http.get` hold for sockets too.

### a world from fetched data

`world.on_generate` can wait, so a chunk can come from data that is fetched
when the chunk loads:

```lua
local tiles = {}
local function tile(tx, tz)                        -- one fetch for each 256 by 256 blocks
    local key = tx .. "," .. tz
    local t = tiles[key]
    if not t then
        t = { loading = true }
        tiles[key] = t                              -- before the wait, so the next chunk does not fetch it again
        local res = http.get(`https://tile.example.org/heights/{tx}/{tz}.png`, { cache = 86400 })
        if res.ok then t.image = res:image() end
        t.loading = false
    end
    while t.loading do task.wait(0.05) end          -- another chunk started the fetch
    return t.image
end

world.on_generate(function(chunk)
    local image = tile(chunk.min.x // 256, chunk.min.z // 256)
    for x = chunk.min.x, chunk.max.x do
        for z = chunk.min.z, chunk.max.z do
            local h = if image then buffer.readu8(image.pixels, ((z % 256) * 256 + x % 256) * 4) else 64
            chunk:fill(vec3(x, 0, z), vec3(x, h, z), "stone")
        end
    end
end)
```

- The engine waits 60 s for a chunk. A chunk that is not ready then is air.
- Make the chunk without the data when the fetch fails.

## Limits and reload

**The runaway stop.** A callback that runs longer than 100 ms is stopped.
The log names its file and line. Chunk callbacks get 2 s, and 2 s again
after each wait.

**The tick budget.** A pack's tick and event callbacks share part of each
tick. Set it with `budget_ms` in the pack's `citadel.yml`. The default is
**2 ms**.

- It covers `time.on_tick`, `time.every` and the survival events
  (`world.on_block_break` and the rest).
- It does not cover `players.on_join`, input events (`on_click`, `on_chat`,
  commands), or task threads. Those keep the 100 ms runaway limit. Chunk
  callbacks keep their separate 2 s limit.
- It counts work, not time spent waiting.

```yaml
# citadel.yml
budget_ms: 2           # this pack's share of a 50 ms tick; 2 is the default
```

When the budget runs out mid-batch:

- Ordinary events retain their original arguments and remaining listeners
  until the next budget window. Canceling a subscription also removes its
  pending delivery. The bounded event queue still applies.
- `time.on_tick` coalesces missed ticks: remaining listeners resume with the
  latest tick number. It does not replay every elapsed tick.
- Socket messages stay queued until their callback can run.
- A `time.every` timer that does not fit retains its place among due timers.
- Nothing is killed. A started callback always finishes.

Read the numbers with `citadel.budget()`:

```lua
local b = citadel.budget()
print(b.of)        -- 2, the ms this pack gets per tick
print(b.used)      -- what the last tick spent
print(b.peak)      -- the most any tick has spent
print(b.skipped)   -- callbacks not run for want of budget, since the script started
print(b.dropped)   -- events this pack never saw; see below
print(b.slowest)   -- { hook = "on_tick", ms = 4.1 }, or nil
print(b.asks)      -- what the engine's questions cost this pack; see below

citadel.on_slow(function(slow)
    print(slow.hook, slow.used, slow.of, slow.skipped)   -- "on_tick" 2.4 2 3
end)
```

Hook names are short: `"on_tick"`, `"every"`, or the event's name
(`"block_break"`, `"pickup"`). `on_slow` runs at most once a second. The
server log shows the pack, hook and time, at most once every five seconds.

Going over is not an error. Do less per tick, or raise `budget_ms`.

**`b.dropped` counts lost ordinary events.** Each pack retains at most 4096
ordinary events; overflow drops the oldest ordinary event and logs the pack.
Joins, leaves, deaths and respawns are retained in order and never evicted by
ordinary traffic or skipped because the tick budget was spent. They carry the
original player session, so a delayed leave still has its `player.data` after
a reconnect. This is in-process delivery, not a durable journal across a
server crash. Keep lifecycle callbacks short so their retained backlog drains.

**`b.asks` counts the engine's questions.** An **ask** is a
cancellable event, such as "may this player break this block". The engine
waits a few milliseconds for the answer. Three exist: `players.on_break`
(kind `"break"`), `players.on_place` (kind `"place"`) and
`players.on_damage` (kind `"damage"`). With no answer in time, the engine
denies the protected action. With no protection listener registered, the
action follows the normal game rules. A listener that completes and returns
nil still allows the action; an error or missing answer does not.

```lua
local a = citadel.budget().asks
print(a.asks)       -- questions you were asked
print(a.answered)   -- answers that arrived in time
print(a.missed)     -- deadlines that passed with no answer from you
print(a.late)       -- answers that arrived after the engine had acted; dropped
print(a.skipped)    -- questions you were not asked, because a kind of yours is switched off
print(a.disabled)   -- true once any kind of yours has been switched off
print(a.kinds)      -- the same six per kind: a.kinds["break"].missed
```

Counters are totals; watch them per kind:

```lua
time.every(60, function()
    for kind, count in citadel.budget().asks.kinds do
        if count.missed > count.answered then
            citadel.log(`slow at {kind}: {count.missed} of {count.asks} missed`)
        end
    end
end)
```

The log names a kind you keep missing. Miss it too often and the engine
**stops asking you** that kind. It then takes the default, logs this once,
and sets `disabled`.

Ask handler rules:

- Answer at once. Never call `task.wait` in one.
- Answering costs tick budget, under the hook name `"ask"`.
- A spent budget does not stop an ask from being answered.

Saving any `.luau` file in the pack, at any depth, restarts the pack's
script. The server keeps running.

- Players stay connected.
- Initialization stages recipes, assets, layouts, block/entity registrations,
  commands, model registrations, asks, spawn settings and queued world actions.
  A failed entry script discards these drafts and resumes the old script.
- The entry must finish within 30 seconds, including any `task.wait` or read
  requests. `task.spawn` work starts after successful initialization.
- Local storage is flushed before loading the replacement, and the old VM
  finishes cleanup before the replacement starts callbacks.
- Writes to shared stores, purchase prompts/acks and `storage.flush` belong
  in `task.spawn` or callbacks, because external writes cannot be rolled back.
  Existing-world/player side effects should also be performed in callbacks.
- On success, the old script's timers and connections end.
- `players.on_join` runs again for every online player. Make it safe to run
  twice.

**A reload keeps the world.** Every existing chunk stays, in script and
terrain worlds.

A changed `world.on_generate`, `seed` or `terrain` applies only to chunks
generated **from here on**. To regenerate the whole map, stop the server,
delete the world folder, and start it again. The log names that folder the first
time a script world reloads.
