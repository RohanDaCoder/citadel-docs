     3→===== DOC: 3d-models | 3D models =====
     4→
     5→```luau
     6→local car = models.new("car", function(m)
     7→    local paint = m:material("paint", colors.red, { grain = 0.1 })   -- a colour a display may repaint
     8→    local glass = m:material("glass", "dark_aqua", { alpha = 0.45 }) -- what is behind shows through
     9→    local door = m:texture(30, 16, { tint = paint })                 -- drawn in greys, coloured by paint
    10→    local grille = m:texture(8, 4)                  -- pixel art for one face, drawn as it is
    11→    grille:fill(colors.black)
    12→    grille:rect(1, 1, 6, 2, colors.gray)            -- x, y, w, h, colour
    13→    grille:pixel(0, 0, colors.transparent)          -- a see-through pixel
    14→
    15→    local body = m:part("body", { pivot = vec3(0, 6, 0) })
    16→    body:box(vec3(0, 4, -20), vec3(8, 12, 20), paint, {
    17→        faces = { north = grille },                 -- one side wears something else
    18→    })
    19→    local screen = body:part("windscreen")
    20→    screen:box(vec3(0, 12, -6), vec3(8, 18, 2), glass, { rotation = vec3(22.5, 0, 0) })
    21→    local wheel = body:part("wheel_front", { pivot = vec3(8, 4, -12) })
    22→    wheel:box(vec3(6, 0, -16), vec3(10, 8, -8), paint)
    23→    wheel:box(vec3(6, 0, -16), vec3(10, 8, -8), paint, { rotation = vec3(45, 0, 0) })
    24→    body:mirror("x")                                -- the left half, from the right one
    25→
    26→    m:animation("drive", {
    27→        length = 1, loop = true,
    28→        wheel_front = { rotation = { [0] = vec3(0, 0, 0), [0.25] = vec3(-90, 0, 0), [0.5] = vec3(-180, 0, 0),
    29→            [0.75] = vec3(-270, 0, 0), [1] = vec3(-360, 0, 0) } },   -- quarter turns: see the rules
    30→        wheel_front_mirrored = { rotation = { [0] = vec3(0, 0, 0), [0.25] = vec3(-90, 0, 0), [0.5] = vec3(-180, 0, 0),
    31→            [0.75] = vec3(-270, 0, 0), [1] = vec3(-360, 0, 0) } },
    32→    })
    33→end)
    34→
    35→local d = world.display{
    36→    kind = "model", model = car,
    37→    at = vec3(10.5, 65, 4.5), rotation = { yaw = 90 },      -- degrees, as every entity turns: 0 faces south, 90 west
    38→    scale = 3.5,                             -- 1 draws it at 16 units to the block
    39→    paint = { paint = colors.blue },         -- keys are material names
    40→    fallback = "minecart",                   -- what a client that cannot show it sees; nil shows nothing
    41→    seats = { vec3(0, 7, 2) },               -- optional: where riders sit, in model units; see "vehicles"
    42→}
    43→d:move(vec3(12.5, 65, 4.5), { yaw = 180 })   -- place and turn it in one step, every part together
    44→d:move(at, { forward = forward, up = up })                      -- pointed: nose along forward, roof toward up (a car on a wall)
    45→d.at, d.rotation                             -- live too; each write is a move of its own
    46→d.scale = 2                                  -- live
    47→d.paint = { paint = colors.red }             -- live
    48→d:play("drive")                              -- from the beginning; an unknown name is an error
    49→d:play("drive", { speed = 2 })               -- twice as fast; on the one already playing, the new speed at once
    50→d:stop("drive")                              -- the parts stay where they are
    51→d:destroy()
    52→```
    53→The rules:
    54→- Make models while the pack loads. `models.new` in a callback is an error.
    55→- `rotation.pitch` and `rotation.roll` tip the whole model about its
    56→origin, with parts, animations and seats.
    57→- A rider stays upright. For a car on a wall, hide the driver
    58→(`invisibility`) and use `camera.fixed`.
    59→- **16 units are one block.** The origin is the model’s bottom centre, `+y`
    60→is up, and the front is `-z`.
    61→- A box reaches `-24 .. 24` on every axis: three blocks. For a bigger thing,
    62→set the display’s `scale`.
    63→- `m:texture(w, h, { scroll = "up", speed = 2 })` is a texture that moves
    64→when a block is drawn from the model. See “blocks drawn from a model”.
    65→- A box turns on **one** axis only, in steps of 22.5 degrees, up to 45
    66→either way. Anything else is an error. An octagonal wheel is two boxes,
    67→one turned 45.
    68→- Box corners go in any order and can be fractional. A box’s `pivot`
    69→defaults to its centre.
    70→- Every box is in a part; there is no `m:box`. A part turns around its
    71→`pivot` (default: the model’s origin). `m:part` makes a child of the root,
    72→`part:part` a child of that part.
    73→- `part:mirror("x")` mirrors what the part has so far, pivots, turns and
    74→hitboxes too. A child’s twin is `<name>_mirrored`. Only `"x"` works in this version.
    75→- `part:hitbox(from, to)` is a box a player can hit on a living body that
    76→wears the model. See “a living body”.
    77→- Between two keys, a part turns **the short way round**. Keep each step
    78→under 180 degrees. A wheel is `[0] = 0, [0.1] = -90, [0.2] = -180, ...`:
    79→one key from 0 to 360 does not turn. A `tween` of `rotation` is not like
    80→this: it turns as written, so there `roll = 360` is a full turn.
    81→- `speed` is 0.01 to 100; a value outside is taken as the nearest end. A
    82→speed of 0 does not pause: use `stop`. A new speed applies at once.
    83→- An animation is keys per part: `{ [seconds] = vec3 }` for `rotation`
    84→(degrees about the pivot) and `position` (an offset in model units).
    85→  - Keys can be in any order.
    86→  - An unknown part name is an error that lists the model’s parts.
    87→  - Parts cannot share a track. Write a loop.
    88→- A material is flat unless it has a `grain` (`0..1`: how much darker its
    89→darkest pixel is). `0.1` is a painted panel, `0.4` a tyre. A grained face
    90→has four tones, one pixel per unit. `alpha` below 1 is glass.
    91→- A texture stretches over its face. For fine detail, draw two pixels per
    92→unit.
    93→- With `tint = material`, draw in greys. White is the material’s colour;
    94→darker is a seam or a shadow.
    95→- A mirrored box shows a side texture from the other end. Draw an
    96→asymmetric texture once per side, after the `mirror`.
    97→- `paint` repaints materials by name, and every texture they tint. An
    98→unknown material name is an error that lists the model’s materials.
    99→- Only Java clients from 1.21.4 see a model. Older clients and Bedrock see
   100→`fallback`. A client that loads the resource pack after it joined gets
   101→its models again when the pack is in; the pack does nothing for this.
   102→- A client that turns the resource pack down, or cannot load it, sees
   103→`fallback` from then on, also for the models it already sees.
   104→- `citadel model render <pack dir> <name> --out car.png` draws a model.
   105→Add `--animation drive --at 0.25` for mid-move. No name lists the models.

   108→===== DOC: a-world-per-player | A world per player =====
   109→
   110→```luau
   111→-- main.luau
   112→local COURSE = { vec3(0, 65, 4), vec3(4, 66, 8), vec3(-3, 68, 12) }
   113→
   114→world.on_generate(function(chunk)
   115→    chunk:fill(vec3(chunk.min.x, 64, chunk.min.z), vec3(chunk.max.x, 64, chunk.max.z), "stone")
   116→end)
   117→
   118→players.on_join(function(player)
   119→    player.ui.title{ title = "Lobby", subtitle = "type /play", color = colors.cyan }
   120→end)
   121→
   122→commands.add("play", function(player)
   123→    local mine = rooms.create{
   124→        spawn_point = vec3(0.5, 65, 0.5),
   125→        generate = function(chunk)
   126→            chunk:fill(vec3(chunk.min.x, 64, chunk.min.z), vec3(chunk.max.x, 64, chunk.max.z), "stone")
   127→            for _, at in COURSE do
   128→                chunk:set(at, "gold_block")
   129→            end
   130→        end,
   131→    }
   132→    mine.players.on_join(function(p)
   133→        p:message("Reach every gold block.", colors.yellow)
   134→        mine.ui.title{ title = "Go", color = colors.lime }
   135→    end)
   136→    mine.players.on_leave(function()
   137→        if mine.players.count() == 0 then mine:destroy() end   -- the last one out closes it
   138→    end)
   139→    player:move_to(mine)
   140→end)
   141→```

   144→===== DOC: api-basics | API basics =====
   145→
   146→- Namespaces: `world`, `players`, `sound`, `fx`, `ui`, `commands`, `time`,
   147→`rooms`, `storage`, `http`. Plus `task` for waiting and `require` for splitting a
   148→pack into files.
   149→- A pack is its files. `loadstring` is not there, so a pack cannot run text
   150→as code, and `require` reads only files inside the pack. `getfenv` and
   151→`setfenv` are not there.
   152→- The first six belong to the main room. `rooms.create{}` gives another room
   153→the same six tables.
   154→- Event subscriptions are `on_*` and return a connection;
   155→`connection:cancel()` stops the subscription. `world.on_generate` and
   156→`world.on_populate` are single-handler setters: a later call replaces the
   157→previous handler, and they return nothing.
   158→- Positions are `vec3(x, y, z)` with fields `x y z`. Block positions are
   159→floored.
   160→- Colours are `color(r, g, b)` in `0..1`, `colors.red`, …, or
   161→`color.hsv(h, s, v)`, everywhere, text included.
   162→  - A name string also works: Minecraft’s
   163→sixteen (`"red"`, `"dark_aqua"`, `"light_purple"`, …), six more
   164→(`"orange"`, `"lime"`, `"cyan"`, `"purple"`, `"magenta"`, `"pink"`),
   165→`"transparent"`, or hex (`"#ff8800"`).
   166→  - `colors` holds the same names. `colors.grey` is an error that lists
   167→them.
   168→- Text is a string or a table of coloured runs. See “Text formatting”.
   169→- Calls with more than three inputs take an options table. Every field has
   170→a default.
   171→  - **An unknown field is an error** that names the nearest valid one:
   172→`world.display{ kind = "text", colour = "red" }` stops the script with
   173→*no option “colour”; did you mean “color”?*
   174→  - A field of the wrong type is also an error.
   175→- For optional settings that accept both, `nil` removes an override and
   176→`false` switches it off. Each field documents whether it accepts `nil`.
   177→Numeric settings such as `player.speed`, `player.scale` and `player.reach`
   178→require a number; `nil` does not reset them.
   179→  - `player.visible = nil` shows the player again, because a player is
   180→visible by default.
   181→  - Where off is the default, the two do the same: `display.glow = false`
   182→and `display.glow = nil` both remove the glow.
   183→  - A flag is `true`, `false` or `nil`. A number or a string is an error:
   184→`world.rules{ fall = 0 }` does not turn the rule off.
   185→- One spelling per idea: a position is `at`, removing a thing is
   186→`:destroy()`, stopping a timer or an event is `:cancel()`, and a box’s
   187→corners are `from` and `to`.
   188→- Block names are Minecraft’s, without `minecraft:`.
   189→  - Every block of every version is real here and stored exactly. An older
   190→client sees the nearest block its version has.
   191→  - A name even the newest version lacks becomes the nearest block. Write
   192→`"future_block|obsidian"` to pick the substitute yourself.
   193→  - Properties go in brackets, in any order and any subset:
   194→`"oak_trapdoor[facing=east]"`, `"stone_button[facing=west, face=wall]"`.
   195→Missing properties come from the default state. The nearest state wins.
   196→  - A name that is no block of any version (`"grassblock"`,
   197→`"stone_brick"`) is an error that lists the nearest real names.
   198→  - Queries (`game.block(name)`, the block an entity stands on) return `nil` for
   199→a name the game lacks.
   200→- Sound names are `"<pack>.<file>"` for your assets, or vanilla names like
   201→`"block.note_block.hat"`.
   202→- Time is in seconds. Only the day is in ticks (24000 to a day).
   203→- Nothing is global state except the callbacks you register.

   206→===== DOC: armour | Armour =====
   207→
   208→```luau
   209→player:wear{ head = "iron_helmet", chest = { item = "leather_chestplate", dye = colors.blue },
   210→             legs = "chainmail_leggings", feet = "golden_boots" }
   211→player:wear{ head = "carved_pumpkin" }   -- replaces all four: the three left out are bare
   212→player:wear{}                            -- all off
   213→npc:wear{ chest = "diamond_chestplate" } -- the same on an npc
   214→```
   215→`wear` fills the armour slots of a player or an npc. Each piece is an item (see “items”), so `dye` and `glint` work.
   216→- The inventory, the body and the armour bar show the pieces. Armour does not reduce damage yet.
   217→- Nearby clients draw the pieces from 1.8.
   218→- Any item goes on the head. Other slots draw only armour made for them.
   219→- On a pack server, only the pack takes armour off.
   220→- On a survival server, these are the real armour slots. `wear` replaces their contents, and the player can take pieces off.

   223→===== DOC: blocks-and-terrain | Blocks and terrain =====
   224→
   225→A build that a script writes is a schematic with no file:
   226→```luau
   227→local road = world.build(function(b)
   228→    b:box(vec3(-4, 0, -48), vec3(4, 0, 48), "gray_concrete")
   229→    b:line(vec3(0, 0, -48), vec3(0, 0, 48), "white_concrete")
   230→    b:block(vec3(0, 1, 0), "sea_lantern")     -- later writes win
   231→end)
   232→road.size, road.min          -- vec3(9, 2, 97) and vec3(-4, 0, -48)
   233→world.paste(road, vec3(0, 64, 0))             -- road.min lands here
   234→```
   235→The rules:
   236→- Coordinates are whole blocks in the build’s own space, and may be
   237→negative. A build written around `vec3(0, 0, 0)` lands with its middle
   238→`-build.min` from `origin`.
   239→- A block name this game version lacks becomes the nearest block it has.
   240→- `chunk:paste` and `world.paste` take a build like any schematic. Make it
   241→at the top of the script, not inside `on_generate`.
   242→- A build costs only what it writes. One build may write 4 096 16-block
   243→cubes (32 MB, sixteen million solid blocks), in a box of up to 256 million
   244→blocks. For more, use several builds or a `.schem`.
   245→- Fences, walls, glass panes and iron bars join their neighbours, and stairs
   246→take their corners. Write `"oak_fence"`, not its `north=true` states.
   247→## Player heads
   248→A `"player_head"` or `"player_wall_head"` shows a face when you give it a
   249→`skin`:
   250→```luau
   251→world.set_block(vec3(0, 65, 0), "player_head[rotation=8]", { skin = "Notch" })
   252→world.set_block(vec3(1, 65, 0), "player_wall_head[facing=south]", { skin = player.name })
   253→world.set_block(vec3(2, 65, 0), "player_head", { skin = { value = "ewogICJ0aW1l...", signature = "..." } })
   254→world.set_blocks({ { at = vec3(3, 65, 0), block = "player_head", skin = "jeb_" } })
   255→```
   256→- A name is looked up from a player in this room, else from Mojang. The
   257→head appears at once and gets its face later. A name with no account
   258→leaves a plain head and logs a line.
   259→- `{ value = , signature = }` is the account’s `textures` property, as for
   260→`world.npc{ skin = }`. The signature is optional.
   261→- The face is saved with the chunk. Replacing, breaking or turning the head
   262→forgets it: write the new state with its `skin` again.
   263→- A head in a `.schem` (Sponge or MCEdit) or an imported world keeps its
   264→face through pastes, turns and `citadel import`. A head saved with only a
   265→name is looked up when its chunk loads.
   266→- `skin` on any other block is an error.
   267→- Clients from 1.7 see the face. Bedrock clients see no face.
   268→- For a head as an item, see “head items”.
   269→## Half blocks: `detail = 2`
   270→At `detail = 2`, every coordinate is a half block. The engine turns each
   271→block’s eight cells into the block, a slab or a stair of the material, with
   272→the correct `facing`, `half` and `shape`:
   273→```luau
   274→local roof = world.build(function(b)
   275→    for k = 0, 9 do                          -- a 45-degree roof, half a block a step
   276→        b:box(vec3(k, k, 0), vec3(19 - k, k, 15), "deepslate_tiles")
   277→    end
   278→end, { detail = 2 })                         -- 10 blocks wide: coordinates 0..19
   279→```
   280→| cells of a block | what is placed |
   281→| --- | --- |
   282→| all eight | the block |
   283→| the bottom four, or the top four | a bottom or top slab |
   284→| a half and one quarter above it (or below) | an outer-corner stair |
   285→| a half and two quarters on one side | a straight stair, climbing that side |
   286→| a half and three quarters | an inner-corner stair |
   287→| anything else | the block when four or more cells hold it, else nothing |
   288→- The slab and the stair are the material’s own: `stone_bricks` makes
   289→`stone_brick_slab` and `stone_brick_stairs`, `oak_planks` makes
   290→`oak_slab`, `quartz_block` makes `quartz_stairs`.
   291→- A material with no slab or stairs, or whose slab or stairs came in a
   292→later release (concrete’s), is the whole block or nothing.
   293→- Only full blocks are fitted. A lantern, flower, fence or stair named
   294→directly is placed as named in a block with no full-block cells. So a
   295→detail is one `b:block`, not eight.
   296→- A block that holds two materials takes the one most of its cells hold.
   297→- `detail` is `1` (the default) or `2`. `build.size` and `build.min` are in
   298→blocks. The cube limit counts cells, so detail 2 holds an eighth as many
   299→blocks.
   300→## Turning a build
   301→A build turns and flips as a value; the original does not change:
   302→- A build turns about `vec3(0, 0, 0)`, so a part drawn around its middle
   303→turns in place. `min` reads back the new start.
   304→- Block states turn with it: facings, log axes, fence and pane sides, stair
   305→corners, door hinges, rail curves, sign and banner rotation.
   306→- `rotate` takes 90, 180 or 270. Any other value is an error.
   307→## Cutting a build, and changing its blocks
   308→A build somebody made by hand is a kit of pieces. `crop` takes one piece out
   309→of it, and `replace` makes it of other blocks. Both give a new build; the
   310→original does not change.
   311→- The corners are in the build’s own blocks, in either order. A file’s
   312→lowest corner is `vec3(0, 0, 0)`.
   313→- A box that reaches outside the build is cut to it. A box with none of the
   314→build in it is an error that says where the build runs.
   315→- A cropped piece has no named parts. `replace` keeps them.
   316→- `replace` takes block names with no state. A block keeps its state where
   317→the new block has one like it: stairs stay stairs that face the same way.
   318→Where it has none, the block is the plain block. `"air"` takes a block
   319→away.
   320→- A name that is not a block is an error that names it.
   321→- To save memory, crop the pieces while the pack loads and keep only them:
   322→a file nobody holds is let go.
   323→## Naming the parts
   324→A build names its pieces as it writes them, and the names stay after the
   325→paste. `citadel render` frames a part by name. `citadel check` says which
   326→part an edit touched.
   327→```luau
   328→local house = world.build(function(b)
   329→    b:part("walls", function()
   330→        b:box(vec3(-5, 0, -4), vec3(5, 4, 4), "stone_bricks")
   331→        b:part("door", function() ... end)      -- "walls/door"
   332→    end)
   333→    b:part("roof", function() ... end)
   334→end, { detail = 2 })
   335→world.paste(house, vec3(0, 64, 0), { part = "house" })   -- "house", "house/walls", "house/roof"
   336→chunk:paste(house, vec3(0, 64, 0), { part = "house" })   -- the same from on_generate
   337→```
   338→- A part is the box its writes reached, in whole blocks at either detail.
   339→It turns and flips with the build.
   340→- A name is 1 to 64 characters without a `/`. A part inside another part is
   341→named by its path, `"walls/door"`.
   342→- A name may repeat. Selecting it takes every part with that name.
   343→- Name the parts you will talk about: the body, each tower or wing, the
   344→roof, the entrance. Then “make the tower taller” stays an edit to the
   345→tower.
   346→## Seeing what you built
   347→`citadel render <pack dir> --out view.png` runs the pack with nobody joining
   348→and draws its world.
   349→- Each block has its real shape, in the average colour of its textures.
   350→- With named parts, four cameras frame them from the sides (`view-1.png`
   351→looks north). Otherwise they circle the spawn.
   352→Ask for the view that answers your question:
   353→```sh
   354→citadel render ./castle --out v.png --view approach,entrance     # does the way in read?
   355→citadel render ./castle --out v.png --view roof --part castle/keep
   356→citadel render ./castle --out v.png --view plan,cutaway          # the enclosed spaces, storey by storey
   357→citadel render ./castle --out gate.png --at 0,66,30 --look 0,70,-10   # one camera, placed
   358→```
   359→| view | camera | the question it answers |
   360→| --- | --- | --- |
   361→| `sides` | four, round the build, a little above it | silhouette and proportion from every side |
   362→| `approach` | a player’s eye height, out from the main door | what a player sees walking up to it |
   363→| `entrance` | close on the main door, eye height | does the way in read as the way in |
   364→| `roof` | high up, at an angle | the roof line, and where the parts meet |
   365→| `plan` | straight down, to scale, one per storey | the enclosed spaces, walls and doors of each floor |
   366→| `cutaway` | at an angle, one per storey | the enclosed spaces as a player stands in them |
   367→| `eye` | in each named part, where a player stands, at eye height | the part as one who walks in sees it: a hall from inside, a square from its edge |
   368→| `night` | as `sides`, at night | the light: only blocks that give light (lanterns, lamps, glowstone, froglights) light the build |
   369→- `--part name` frames that part and the parts inside it.
   370→`--from x,y,z --to x,y,z` frames a box. Without either, `--view` frames
   371→every named part.
   372→- The main door is the lowest door that opens outdoors. A build with no
   373→`*_door` block has no `approach` or `entrance` view.
   374→- `plan` and `cutaway` remove everything above each storey. `--cut y`
   375→removes everything above `y` for any view. `--night` draws any view at
   376→night, the placed cameras of `--at` too.
   377→- Under a roof, a face is lit by the sky light that comes in through the
   378→openings and by the light blocks near it, as in the game: a room with
   379→windows is light, one without is dark.
   380→- `--around x,y,z`, `--distance d`, `--height h` and `--views n` circle a
   381→point instead. `--size 1280x720`, `--fov 60` and `--radius r` (how far
   382→around the target the world is read) change the rest.
   383→- Each file prints one JSON line on stdout: `{"file":..., "view":..., "eye":[x,y,z], "look":[x,y,z]}`, with `"cut"` when something was removed.
   384→**What a picture proves.** Shape, depth, proportion and silhouette, not
   385→textures: every block is one flat colour. Say so when you report on how a
   386→build looks. At night a block is lit by the light blocks within 15 blocks of
   387→it, as in the game; a lamp outside the views’ box lights nothing.
   388→## Checking what you built
   389→`citadel check <pack dir>` measures the named build and reports what is
   390→wrong with it:
   391→```sh
   392→citadel check ./castle                          # every named part
   393→citadel check ./castle --part castle/keep --storeys 3 --enclosed
   394→citadel check ./castle --save before.snap       # write the blocks down ...
   395→citadel check ./castle --since before.snap      # ... and say what changed, part by part
   396→```
   397→It lists:
   398→- the enclosed spaces (the air closed in with doors and windows shut)
   399→- how many blocks the build holds
   400→- the storeys
   401→- for each innermost part: its places to stand and the detail near them
   402→(blocks within reach that are not a full cube and not glass)
   403→- the doors, and where each opens
   404→- each face: how much is one plane, its windows and how many are framed,
   405→its materials
   406→- the roof: how much is one height, how much is stairs and slabs
   407→- the setting: how much of the ground around it has something placed.
   408→Then it lists the findings:
   409→| finding | kind | what it means |
   410→| --- | --- | --- |
   411→| `FLOATING` | fix | blocks that touch nothing standing |
   412→| `DOOR_BLOCKED` | fix | a block in a door’s way at foot or head height, named |
   413→| `DOOR_DROP` | fix | a door that opens onto nothing to stand on |
   414→| `DOOR_UNREACHED` | fix | a door nobody can walk to from outside |
   415→| `UNREACHED` | fix | floor inside walls and under a roof that nobody can walk to from outside |
   416→| `STOREYS` | fix | `--storeys n` asked for, and not what enclosed spaces stand on |
   417→| `NOT_CLOSED_IN` | fix with `--enclosed` | outside air reaches the inside with doors and windows shut, and where it comes in |
   418→| `FLAT_FACE` | advice | a face nearly all in one plane |
   419→| `FLUSH_WINDOWS` | advice | windows with nothing in front of them: no sill, lintel or post that stands out |
   420→| `ONE_MATERIAL` | advice | a face nearly all one block |
   421→| `FLAT_ROOF` | advice | the top one flat height, not stepped |
   422→| `BLOCKY_ROOF` | advice | a sloping roof of whole blocks where stairs could be |
   423→| `LOW_CEILING` | advice | a room two blocks high |
   424→| `NO_SETTING` | advice | bare ground all round |
   425→| `BARE_FACE` | advice | a face with few shape blocks (stairs, slabs, walls, trapdoors, lanterns): masses without detail |
   426→| `DARK_AT_NIGHT` | advice | over half of the places a player walks to is dark at night |
   427→| `SPARSE` | advice | a part where players walk with little detail near them: an empty hall, square or deck |
   428→| `PART_OVERLAP` | advice | two parts (`parts.define`) overlap without one inside the other: regenerating either rewrites the other |
   429→- A fix is wrong for any build. Weigh advice against the build’s purpose:
   430→a market stall is open, and a tower’s roof may be flat.
   431→- A player walks on two clear cells over something solid, steps onto stairs
   432→and slabs, jumps one block, drops three, and climbs ladders and vines.
   433→Blocks are sorted by their names.
   434→- `--json` prints one JSON object. The command exits 1 when there is
   435→something to fix.
   436→- `--since` counts changed blocks by the innermost part that holds them,
   437→and counts the rest as `(in no part)`.
   438→Ship a build too big for `chunk:set` lines as a `.schem` in the pack folder,
   439→and paste it:
   440→```luau
   441→local lobby = world.schematic("builds/lobby.schem")   -- at the top, not per chunk
   442→world.on_generate(function(chunk)
   443→    chunk:paste(lobby, vec3(0, 64, 0))         -- origin is the build's lowest corner
   444→end)
   445→world.paste(lobby, vec3(100, 64, 0))           -- the same build, live
   446→chunk:paste(lobby, vec3(0, 64, 0), { air = true })   -- both take this third argument
   447→```
   448→The rules:
   449→- `file` is a path inside the pack folder, written with `/`. These are
   450→errors that name the file: a path from the root, a path that leaves the
   451→pack with `..`, a missing file, and a file that is not a schematic.
   452→- Call `world.schematic` while the pack loads and keep the value. Inside
   453→`on_generate`, it reads the file again for every chunk.
   454→- `origin` is where the build’s **lowest** corner goes. The build fills
   455→`origin` to `origin + schem.size - vec3(1, 1, 1)`.
   456→- Air in the build is skipped, so a paste sits on the terrain. Pass
   457→`{ air = true }` to place the air too.
   458→- `chunk:paste` writes only the part inside its chunk, so the call in
   459→`on_generate` builds the whole thing. `world.paste` writes all of it at
   460→once, like `world.set_blocks`.
   461→- Sponge v2, Sponge v3 and the old MCEdit `.schematic` all load. Block
   462→entities (chest contents, signs) and entities do not: a chest pastes
   463→empty.
   464→- A paste does not turn. Turn the value first with `:rotate` or `:mirror`
   465→(see “turning a build”). A file’s schematic has them too.
   466→- A paste keeps the exact blocks of any release Citadel knows. A newer
   467→name becomes the nearest block. What nothing covers becomes air, and the
   468→log names and counts it once per file.
   469→## The time of day
   470→The time is in ticks, 0 at dawn and 24000 to a day. Each room has its own
   471→time, and late joiners get the same sky.
   472→```luau
   473→world.time("night")          -- sets the hour: sunrise 23000, day 1000, noon 6000, sunset 12000, night 13000, midnight 18000
   474→world.time(18000)            -- sets the hour, in ticks
   475→world.time(function(s)       -- a cycle: asked each tick, s seconds after this call
   476→    return 1000 + s * 40     -- a day of ten minutes, from morning
   477→end)
   478→world.time(function(s)       -- anything the pack likes: a day that stops at dusk
   479→    return math.min(1000 + s * 20, 12000)
   480→end)
   481→local now = world.time()     -- 0 .. 23999
   482→```
   483→- A call replaces the previous one, a function too.
   484→- The function returns ticks or a name. If it errors, the sky stays where
   485→it was.
   486→- Whether the sun moves is a rule: `world.rules{ day_cycle = true }` runs
   487→the version’s own day (20 minutes), and nothing else of survival.
   488→- On a `mode: lite` world and in a room made by `rooms.create`, the rule is
   489→off and the sun stays straight overhead (noon).
   490→- On a `mode: full` world, and after `world.rules{ survival = true }`, the
   491→rule is on.
   492→- A number or a name sets the hour. With `day_cycle` on, the day runs on
   493→from there, as `/time set` does. With it off, the sky stays there.
   494→- A function drives the sky itself. The engine’s day stands aside until the
   495→next `world.time` call.
   496→- A stopped sky, the normal day or an `s * 20` day costs one packet a second. A faster or
   497→slower day costs one packet every tick it moves.
   498→Reading blocks:
   499→**A read never generates.** A position in an unloaded chunk reads as `nil`
   500→(not loaded), not `"air"`. Inside `on_generate`, `chunk:get` always works.
   501→A block change is stored, so late joiners see it. A block name may list `|`
   502→alternatives (`"deepslate|stone"`): the first one the game version knows
   503→wins. Without `|`, an unknown name becomes the nearest block, never air.
   504→## Containers
   505→A chest’s stacks, for a pipe, a quarry or a sorting machine to take from
   506→and put into:
   507→- A chest a player has open belongs to that player until they close it.
   508→Until then, `take` and `put` do nothing.
   509→- Each half of a double chest is its own 27 slots.
   510→- A kept handle never goes stale. `items()` on a chest that is gone returns
   511→an empty list.
   512→## Populating the overworld
   513→`on_populate` works on the engine’s overworld (`world: overworld`, or
   514→`mode: full` with no `world` key). It gets each new chunk with terrain,
   515→caves and ores in place, with the same `chunk:get`, `chunk:set` and
   516→`chunk:fill` as `on_generate`. Use it for your own ores and trees. A changed
   517→hook reaches new land only.
   518→## Biomes
   519→A biome is what the client colours a column by: the grass, the leaves, the
   520→water, the sky and the fog. It is also the weather there. Each block column
   521→has one biome.
   522→- A column that nothing sets is `"plains"`.
   523→- The engine’s overworld sets the biomes of its own chunks. `on_populate`
   524→can read them and change them.
   525→- A name is a vanilla biome name of any release: `"windswept_hills"` and
   526→`"mountains"` are the same hill. A wrong name is an error.
   527→- A client that lacks a biome shows the nearest one it has. A 1.8 client
   528→shows `"cherry_grove"` as plains.
   529→A pack makes biomes of its own. A new biome is a copy of a vanilla biome
   530→with other colours and weather:
   531→```luau
   532→local crystal = game.biomes.define {
   533→    name = "crystal",        -- becomes "mypack:crystal", which define returns
   534→    like = "forest",         -- the vanilla biome to copy; "plains" when left out
   535→    grass = "#7fd8c8",       -- each colour is a colour name or a color value
   536→    leaves = "#58b7a6",
   537→    water = "#3fd0ff",
   538→    water_fog = "#0a4060",   -- the view under water
   539→    sky = "#b0e8ff",
   540→    fog = "#e0f6ff",         -- the far distance
   541→    weather = "snow",        -- "rain" or "snow"; "none" or false for no weather
   542→}
   543→
   544→world.on_generate(function(chunk)
   545→    chunk:fill_biome(chunk.min, chunk.max, crystal)
   546→end)
   547→```
   548→- Define biomes at the top of the script. A client learns the biomes when
   549→it joins.
   550→- Clients from 1.16.2 show a new biome. An older client and a Bedrock
   551→client show the `like` biome.
   552→- A changed colour reaches a player on the next join. A biome that is
   553→new after the first player joined shows as its `like` until the server
   554→restarts. The console says so.
   555→- A colour that is left out stays as `like` has it. `weather = "snow"`
   556→also makes the grass and leaves colder in colour, unless you set them.
   557→- A biome does not make trees or blocks. The generator puts them there.
   558→## Noise
   559→`noise` gives smooth random numbers for hills, caves and biome borders. The
   560→engine calculates them, so a generator stays inside its 100 ms.
   561→| Option | Default | Meaning |
   562→| --- | --- | --- |
   563→| `seed` | 0 | the same seed gives the same numbers each time |
   564→| `scale` | 64 | the size of one hill, in blocks |
   565→| `octaves` | 1 | layers of detail, 1 to 16 |
   566→| `lacunarity` | 2 | how many times finer each next layer is |
   567→| `gain` | 0.5 | how many times as strong each next layer is |
   568→A world with hills and two biomes:
   569→```luau
   570→local hills = noise.new { seed = 7, scale = 96, octaves = 4 }
   571→local climate = noise.new { seed = 8, scale = 300 }
   572→
   573→world.on_generate(function(chunk)
   574→    local h = hills:grid(chunk.min.x, chunk.min.z, 16, 16)
   575→    local c = climate:grid(chunk.min.x, chunk.min.z, 16, 16)
   576→    for z = 0, 15 do
   577→        for x = 0, 15 do
   578→            local i = z * 16 + x + 1
   579→            local at = chunk.min + vec3(x, 0, z)
   580→            local top = 64 + math.floor(h[i] * 24)
   581→            local dry = c[i] > 0
   582→            chunk:fill(at, at + vec3(0, top - 1, 0), "stone")
   583→            chunk:set(at + vec3(0, top, 0), dry and "sand" or "grass_block")
   584→            chunk:set_biome(at, dry and "desert" or "forest")
   585→        end
   586→    end
   587→end)
   588→```
   589→- Make each noise at the top of the script, not inside `on_generate`.
   590→- Ask for a chunk with one `grid` call. 256 `get` calls are slower.
   591→- `grid` gives up to 65 536 numbers (256 x 256).
   592→## A declared world
   593→`world.generate` declares a world as rules. The engine makes each chunk from
   594→them, on all cores, and no script runs for a chunk. Use it for a large world.
   595→`world.on_generate` stays for what the rules cannot say.
   596→```luau
   597→local hills = fields.noise { seed = 7, scale = 96, octaves = 4 }
   598→local dry = fields.noise { seed = 8, scale = 300 }:gt(0)
   599→
   600→local made = world.generate {
   601→    height = 64 + hills * 24,                -- the y of the surface
   602→    sea = 62,                                -- water fills the open air up to here
   603→    biomes = { { "desert", when = dry }, { "forest" } },   -- the first that holds
   604→    surface = {                              -- the first rule that holds, for each block
   605→        { block = "stone", when = fields.slope:gt(2), depth = 4 },
   606→        { block = "sand", biome = "desert", depth = 4 },
   607→        { block = "grass_block" },           -- depth 1: the top block
   608→        { block = "dirt", depth = 4 },       -- the 3 blocks below it
   609→    },
   610→    rock = { { block = "stone" } },          -- the body of the land
   611→    plants = { { block = "short_grass", chance = 0.3, biome = "forest" } },
   612→    things = { { cell = 8, { shapes = { oak }, chance = 0.4, biome = "forest" } } },
   613→}
   614→made:sample(hills, pos)     -- a field's value there, as the engine calculates it
   615→made:biome_at(pos)          -- "forest"
   616→```
   617→**A field** is a number at each block, written as a recipe. `fields.noise`
   618→gives one, and maths on fields gives more: `+ - * / ^`, a minus sign, and
   619→the methods. A number is a field too.
   620→```luau
   621→-- 1 on a column with water beside it: sugar cane beside water.
   622→local w = fields.water
   623→local beside_water = w:at(1, 0, 0):max(w:at(-1, 0, 0)):max(w:at(0, 0, 1)):max(w:at(0, 0, -1)):gt(0.5)
   624→plants = { { block = "sugar_cane", height = 2, chance = 0.5, when = beside_water * w:lt(0.5) } }
   625→```
   626→- A rule asks a question with `when`: it holds where the field is above
   627→0.5. `a * b` is “and”, `a:max(b)` is “or”, `1 - a` is “not”.
   628→- `height` cannot use `fields.height`, `slope`, `water` or `shore`: they
   629→are read from it.
   630→- `biome` in a rule is a biome name. It is the same as a `when`, and faster.
   631→**The rules:**
   632→| Key | A rule | Meaning |
   633→| --- | --- | --- |
   634→| `biomes` | `{ "desert", when = f }` | the first that holds names the biome of the column |
   635→| `surface` | `{ block, biome, when, depth }` | `block` for the top `depth` blocks (1) of each surface |
   636→| `rock` | the same | the body of the land under the surface rules |
   637→| `plants` | `{ block, chance, biome, when, ... }` | at most one plant on a column |
   638→| `things` | `{ cell, seed, { shapes, chance, biome, when, afloat, place, y }, ... }` | at most one thing in a grid cell |
   639→| `fluids` | `{ block, below, biome, when }` | the carved air under `below` becomes `block`; the first that holds |
   640→- A **block** is a name, or a list with a field that chooses:
   641→`{ "stone", "andesite", by = fields.hash(3) * 2 }`. `floor(by)` counts
   642→through the list.
   643→- A **plant** is `block`, or `blocks = { lower, upper }` for a plant of two
   644→blocks. With `height = f` it grows: `block` repeats, and `tip` is the top
   645→block. `afloat = true` puts it on the water, and `sink = 1` puts it one
   646→block lower (ice in the top of the sea). `clear = n` keeps `n` blocks of
   647→water free over a plant that grows in water.
   648→- A column tries the plant rules in order. Each rule that holds takes its
   649→`chance` of the column’s roll, so two rules of 0.3 and 0.2 give a plant
   650→on half of the columns.
   651→- A plant stays only where the game version’s own rule lets it stay, for
   652→example cane needs water beside the block under it, at the same level.
   653→Where the rule fails, the column has no plant. Light is not known yet,
   654→so a rule about light is not checked.
   655→- A **thing** is one of `shapes`: builds from `world.build` or
   656→`world.schematic`. Its `(0, 0, 0)` goes on the block above the ground. A
   657→thing that crosses a chunk border is complete. Nothing stands on ground
   658→that is under water, but `afloat = true` puts the thing on the water.
   659→- `density = f` makes a block solid where `f` is above 0. Use it with a
   660→`solid` noise for caves, overhangs and land in the air. With `height`
   661→too, a block must pass both.
   662→- Without `height` and `density`, the rules add to the land that the
   663→engine’s own terrain made (`world: overworld`): surface rules do not
   664→run, plants grow on each column, and a thing must stand inside one chunk.
   665→- Make the shapes and the fields at the top of the script, within the load
   666→limits (see “loading”).
   667→**Caves.** `density` carves air under the top surface. A plant or a thing
   668→goes into that air with `place`, and `fluids` fill it:
   669→```luau
   670→local caves = fields.noise { seed = 3, scale = 24, octaves = 2, solid = true }
   671→world.generate {
   672→    height = 72 + hills * 20,
   673→    density = 1 - caves:abs():lt(0.12) * fields.y:gt(5),   -- caves under y 5 and up
   674→    rock = { { block = "stone" } },
   675→    plants = {
   676→        { block = "moss_carpet", place = "floor", chance = 0.6 },          -- moss on cave floors
   677→        { block = "cave_vines_plant", tip = "cave_vines", height = fields.room / 3,
   678→          place = "ceiling", chance = 0.3 },                               -- glow berries from the ceilings
   679→        { block = "glow_lichen[{wall}=true]", place = "wall", chance = 0.1, y = { 0, 50 } },
   680→    },
   681→    fluids = { { block = "water", below = 30 }, { block = "lava", below = 10 } },  -- a lake, and lava under it
   682→    things = { { cell = 6, { shapes = { stalagmite }, place = "floor", when = fields.room:gt(5) } } },
   683→}
   684→```
   685→| `place` | Where | At most |
   686→| --- | --- | --- |
   687→| `"top"` (the default) | on the top surface, as before | one plant on a column |
   688→| `"floor"` | the air block over each floor of a cave | one plant on each floor |
   689→| `"ceiling"` | the air block under each ceiling, hanging down | one plant under each ceiling |
   690→| `"wall"` | each air block of a cave with rock on a side (plants only) | one plant in each block |
   691→- A column can cross many caves. Each floor and each ceiling of each cave
   692→is its own place, with its own roll.
   693→- `y = { low, high }` keeps a rule to the blocks it starts at from `low` to
   694→`high`. `when`, `chance` and `y` are read at the air block the plant
   695→starts in, not at the rock under it.
   696→- A plant that grows (`height`) under a ceiling hangs down: `block` is at
   697→the ceiling and `tip` is the lowest block. With `blocks`, the first is at
   698→the ceiling. A plant never grows into rock, a fluid or another plant.
   699→- A wall plant is one block. In its name, `{wall}` is the side the rock is
   700→on and `{facing}` is the side away from it: `"vine[{wall}=true]"`,
